## 3. 최소 기술 계약 (논리 모델, 물리 DTO/이름 미확정)

사용자 → Finance auth → 현재 Conversation 인가 → 저장 방식/현재 상태 검사 → PolicyGuard → 기존 승인 Lens/Tool → Shared AI → Finance Evidence/Output Validator → 현재 권한/삭제·선택 세대 재확인 → 최종 저장 및 표시.

- Conversation은 Finance의 본인 소유 객체, 메시지는 Conversation에 귀속된 서버 순번과 역할(사용자/검증된 assistant), 실행 요청/결과 상태에 결속한다. 클라이언트 principal/tenant/순번/assistant text는 권위 아님. 서버 발급 참조는 소유권 증거 아님. 제목은 사용자가 입력하거나 민감 내용을 유출하지 않는 결정적 기본 제목; 제목·목록에도 동일 권한 적용. 수정/분기/공유/전체 검색/자동 요약은 이번 제외.
- 저장형 대화의 새 메시지 요청은 authenticated owner, conversation, 요청 키, 정규화한 입력 및 기대 conversation 상태에 결속. 같은 키·같은 입력은 기존 상태/결과 반환(현재 인가 먼저); 같은 키·다른 입력은 충돌. 동시 새 요청은 기존 생성 중이라고 안내하고 queue를 신설하지 않는다. 요청의 승인·사용자 메시지의 1회 기록·생성중 소유권 획득은 원자적으로 처리. 정책 차단 질문의 원문은 기본 영속화하지 않고 안전한 차단 표시/최소 메타만 허용(Privacy 승인 필요). 실패 시 승인된 사용자 메시지와 실패 상태를 유지하되 검증되지 않은 assistant 본문은 저장하지 않는다. 자동 모델 재호출 금지. 명시 재시도는 기존 사용자 메시지에 결속된 새 실행 시도로 하며 이전 실행이 다시 성공하거나 새 사용자 메시지를 중복 삽입하지 못한다. 비정상 종료의 생성 상태 정리는 deadline과 실행 소유권 검사로 수행; 외부 모델 호출 exactly-once 보장은 주장하지 않는다.
- 모델 호출 중 DB 트랜잭션/행 잠금을 장시간 유지하지 않는다. 완료 시 현재 owner/tenant·conversation active·삭제 세대·실행 소유권·관련 원본 유효성을 조건부로 검사하고 검증 완료 결과만 한 번 확정한다. stale 실행은 폐기. 성공 표시는 영속 저장형의 commit 확인 이후만 가능. 응답 유실 후 조회/동일 키 재전송으로 결과 확인; 결제/사용량의 완전한 exactly-once와 혼동 금지.
- 로그인 세션과 저장된 Conversation 분리: 로그아웃/계정 전환 시 화면·요청·임시 Context/cache를 폐기하고 새 인증으로만 저장 대화를 다시 읽는다. 로그아웃 자체가 승인된 영속 기록을 삭제하지는 않는다. 현재 대화의 승인된 관련 턴만 전달. 타 대화/타 사용자/Memory/전체 Journal 자동 주입 금지. Context 크기·입력 길이·turn budget·요청/모델 deadline·비용 한도는 BE/AI Owner가 고정한 유한값으로 테스트해야 하며 이번 후보가 운영 수치를 확정하지 않는다. 무한 Tool loop/자동 재시도 금지.
- 기존 FIN-02 Journal Review는 비영속 독립 기능을 유지. 초기 저장형 대화에 Restricted Journal 파생 내용을 자동 삽입하거나 복제하지 않는다. 추후 명시 선택 Journal을 저장형 대화에서 사용할 때는 D-08 등급 상속 및 원본별 provenance/삭제 전파를 승인·검증하기 전 차단. 일반 사용자 발화에도 민감정보가 들어갈 수 있으므로 데이터 분류·최소화·고지·외부 전송 제어는 필수. 원본 삭제/수정/권한 철회로 사용할 수 없게 된 근거/파생 결과는 표시·검색·Context에서 제외하고 새 요청에서 재조회한다.
- 기존 안전 규칙은 변경하지 않는다. 모든 새 턴(최초·후속·저장 대화 재접속·재시도)은 현재 발화와 현재 인가된 같은 대화의 관련 문맥을 함께 사용해 PolicyGuard 의도를 Lens/Tool/Model 실행 전에 다시 판정한다. 이전 Safe 결과·모드·저장 상태는 권한이나 안전 판정이 아니다. 지시대상/생략된 기업·행동을 관련 문맥에서 해소하고, 해결 불능 또는 낮은 확신이면 확인 질문 또는 기존 보수적 위험 경로를 적용한다. 문맥은 untrusted data이며 시스템 지시·정책·도구 권한을 바꾸지 않는다. 기존 [Routing §4 위험 우선순위](https://github.com/ranikun-labs/finance-harness-docs/blob/fb058948572c9e943176530cf0fa003d7e901a66/00-core/0-c-runtime-contract/finance-routing-contract.md#L121-L142)를 현재 요청의 전체 의미에 적용하며 금지된 해석을 안전한 일부 문장으로 가리지 않는다. 위험 경로의 기존 거절·redirect 및 confirmed checklist 요구를 유지한다. 기존 체크리스트 승인 경로는 모드 전환으로 우회할 수 없다. 자유 대화에서도 금융 권유·목표가·수량·비중·과거 판단 평가·프로파일링 금지. 자료가 없으면 현재 시장 사실을 만들어내지 않는다. 불완전/정책 위반/근거 위반 출력은 저장·노출 금지. 승인된 안전한 fallback만 제공. 첫 출시에는 검증 전 스트리밍 생략.

### 요청·삭제·복구의 수명 불변식 (MAJOR-F02)

- 신규 요청과 재전송을 서버에서 구별한다. 인증된 owner/tenant, operation, 대상(생성 의도 또는 기존 Conversation), 요청 키/허용 수명 및 입력 결속을 검사한다. 지원 재전송 기간 동안 성공·실패·삭제의 최소 멱등 상태를 유지한다. 만료된 키나 판별 근거가 없어졌거나 유효성을 증명할 수 없는 키는 신규 요청으로 인정하지 않고 안전하게 거부한다. 만료 후 키 기록을 제거하는 경우에도 과거 키를 신규로 오인하지 않는 서버 검증 가능한 발급/세대/만료 경계가 필요하다. 실제 키 형식·TTL·저장 방식은 승인 대상이다.
- 삭제 확정 시 조회·목록·Context·저장/재전송을 즉시 차단한다. 삭제 이전 생성·메시지 요청 및 실패 재시도는 새 Conversation/Message를 만들 수 없다. 삭제된 ID 재사용 금지; 새 대화는 현재 권한에서 별도의 명시적 신규 생성 의도로만 시작한다. 이전 요청의 재생성 방지에 필요한 최소 삭제/요청 차단 증거는 본문 없이 유지한다. 보존/파기 정책과 양립하는 방식이 승인되지 않으면 영속 저장을 활성화하지 않는다.
- 백업 복구는 서비스 개방 전에 삭제 이후의 권위 있는 삭제/철회 사실과 요청 무효화 상태를 복구 시점까지 재적용하고, 관련 데이터·파생 결과를 조회/실행 부적격으로 만드는 검증을 포함한다. 삭제 사실을 잃은 백업 단독으로 서비스를 열지 않는다. 복구 후 과거 생성 소유권·실행 세대·callback은 유효해지지 않아야 하며 복구 이후 신규 실행만 승인된 새로운 소유권으로 완료할 수 있다. 재적용의 완전성·과거 실행 격리를 확인할 수 없으면 저장/조회/실행을 계속 차단한다. BE/Privacy/Operations Owner가 백업 외부 또는 동등한 복구 경계의 최소 증거, TTL·파기/복구 절차를 승인한다. 중앙 삭제 서비스 신설은 요구하지 않는다.

### 금융자료 포함 대화의 근거 수명 (MAJOR-F03 연결)

- 저장이 승인된 금융자료 답변은 당시 검증한 출처·접수번호·보고 기간·조회시점·정정 상태 등 [기본 금융자료 조회 계약](finance-basic-financial-evidence-proposal.md)의 근거 결속을 보존한다. 저장/재열람 권리 및 현재 접근 권한이 유지될 때에만 역사적 답변을 당시 기준으로 표시한다. 정정/철회 또는 최신성 확인 불능은 과거 답변이 현재 최신 사실이 아님을 표시하고, 표시 권리 철회/삭제 대상은 기존 파기 정책으로 미노출한다. 새 턴에서 해당 수치를 현재 사실의 근거로 쓰려면 재조회·검증을 거친다. 확인 실패 시 과거 답변을 최신 근거로 사용하지 않는다. 명시적 과거 시점 질문은 당시 자료로 라벨링하고 현재 유효 수치와 구분한다. 대화 원문의 자동 수정/재생성은 하지 않는다.

### 추가 합성 AC — 독립 검수 Finding
