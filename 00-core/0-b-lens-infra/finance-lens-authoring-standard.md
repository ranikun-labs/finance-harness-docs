# finance-lens-authoring-standard.md

> **상태**: 초안 v0.1
> **상위 문서**: `finance-analysis-lens-pack-overview.md` §7~§10, §12 (본 문서는 그 작성 기준을 실무 표준으로 분리한 것)
> **Safety Core 참조**: `00-service-policy.md`, `finance-policyguard-rules.md`, `finance-output-validator.md`, `finance-market-data-grounding.md`, `finance-routing-fixtures.md`
> **범위**: per-lens 문서의 **작성 표준**(구조, 문체, 금지/허용 표현, 셀프 체크)만 정의한다. 개별 렌즈 본문, 렌즈 목록, guard/validator 규칙 자체는 정의하지 않는다.
> **불변 원칙**: **렌즈는 "무엇을 보는가"만 정의한다. "그래서 무엇을 해야 하는가"는 정의하지 않는다.**

## 1. 문서 목적

**본 문서는 앞으로 작성되는 모든 per-lens 문서가 따라야 하는 단일 작성 표준이다.**

- 목적은 두 가지다.

```text
1. 일관성 — 모든 Lens 문서는 Metadata Standard
   (finance-knowledge-artifact-metadata-standard.md)의 공통 envelope와
   본 문서의 Lens extension(§3) 및 본문 구조·문체 규칙을
   일관되게 사용한다.
2. 안전성 — 렌즈 문서가 투자 조언(매수/매도 판단, 목표가/손절가,
   수량/비중, 종목/업종 추천, 확정 예측)으로 새는 것을
   작성 단계에서 차단한다.
```

- 본 표준을 위반한 렌즈 문서는 리뷰에서 반려되며, 배포 대상이 될 수 없다.
- 본 표준과 상위 문서가 충돌하면 상위 문서가 이긴다: `00-service-policy.md` > policyguard > overview > **본 표준** > 개별 렌즈 문서.

## 3. Lens Metadata Extension

**공통 envelope의 상속.** 모든 Knowledge Artifact 공통 metadata envelope(document_id, artifact_type, version, lifecycle_status, implementation_status, exposure_class, distribution_boundary, runtime_loadable, routable, 공통 dependency/provenance 필드와 형식·validation contract)는 `finance-knowledge-artifact-metadata-standard.md`가 소유한다. 본 문서는 그 envelope를 **상속하며 재정의하지 않는다.** 렌즈 문서의 공통 envelope 필드 작성은 해당 표준(§13.1, §14)을 따른다.

본 절이 소유하는 것은 **Lens 전용 metadata extension**의 의미와 작성 규칙뿐이다 (metadata-standard §13.2가 canonical owner로 본 문서를 참조한다).

모든 렌즈 문서는 서두에 아래 Lens 전용 metadata 블록을 **이 순서대로** 포함한다.

```text
lens_key          : {kebab-case 영문. catalog 등록 key와 문자 단위로 동일}
category          : {공통 시장 / 주식 / 환율·금리·매크로 / 자산군 확장 / 투자 일지·행동 분석}
lens_tier         : {existing-mvp / existing-extension / new}
trigger           : {이 렌즈가 선택되는 질문 신호. 예시 질문 1~3개 포함}
forbidden_intents : {이 렌즈로 자주 유입되는 RISK_* intent 목록}
redirect_to       : {이 렌즈가 redirect 대상이 되는 RISK_* intent 목록}
related_lenses    : {함께 참조되거나 병행 적용되는 lens key 목록 (없으면 빈 목록)}
fixture_refs      : {이 렌즈를 참조하는 fixture id 목록}
output_style      : 공통 5단 구조 내 사용 (templates §3)
activation_gate   : {active 전환에 요구되는 검증 게이트 — 기본: §13 등록 체크리스트
                     + fixture regression 전체 통과}
```

위 10개가 Lens extension의 canonical 필드명이다 (`redirect`와 `redirect_to`를 혼용하지 않는다 — canonical은 `redirect_to`). 필드의 **형식·필수 여부**는 metadata-standard §13.2가, **의미와 작성 규칙**은 본 문서가 소유한다.

- `lens_tier`는 구 `status` 필드의 개명이다. canonical 값은 lowercase kebab-case로 `existing-mvp / existing-extension / new`이며(metadata-standard §14.2 표기 규칙), **의미는 변경하지 않는다.** legacy 값 대응: `기존-MVP → existing-mvp`, `기존-확장 → existing-extension`, `신규 → new`. 기존 Lens 10종의 실제 값은 이번 개정에서 수정하지 않으며 migration 시 위 대응으로 변환한다. 개명 이유: 공통 envelope의 `lifecycle_status`(metadata-standard §8)와의 축 혼동 방지. `category`는 Lens 전용 필드이며 기존 의미를 유지한다.
- 기존 Lens 10종의 실제 metadata migration은 본 개정에서 수행하지 않는다 (별도 작업).

작성 규칙:

- **lens_key**: `finance-lens-catalog.md`에 없는 key를 새로 만들 수 없다. 신규 key는 §13 등록 절차를 먼저 완료한다.
- **trigger의 예시 질문**: 안전 질문만 쓴다. 위험 질문("지금 사도 돼?")을 trigger 예시로 쓰면 렌즈가 위험 intent를 직접 처리하는 것처럼 읽히므로, 위험 질문은 반드시 `forbidden_intents` 항목에 배치한다.
- **forbidden_intents**: "이 렌즈가 처리한다"는 뜻이 아니라 "**Input Guard가 렌즈보다 먼저 잡아야 한다**"는 선언이다. 이 구분을 문서 안에서 흐리지 않는다.
- **fixture_refs**: 존재하지 않는 fixture id를 적지 않는다. 신규 fixture가 필요하면 "fixture 추가 필요(§13)"로 표기한다.

## 4. 렌즈 문서 공통 본문 구조

본문은 아래 4블록을 **이 순서대로, 하나도 생략 없이** 포함한다. 블록 추가는 가능하나(예: 개념 배경), 4블록의 대체·병합은 불가하다.

### 4.1 판단 전 체크리스트

- 형식: **질문형 목록**. 3~7개 권장.
- 각 항목은 사용자가 스스로 답하는 질문이어야 하며, 답을 내포한 유도 질문은 금지한다.
  - 유도 질문 예(금지): "수급이 좋을 때 진입하는 것이 유리하지 않은가?" — 질문 형식이지만 방향을 내포.
- 조건-행동 매핑 금지: "~이면 ~하라"는 물론, "~인지 확인하고, 그렇다면 진입을 고려" 같은 **반쪽 공식**도 금지.
- 체크리스트는 **질문이지 규칙이 아니다**. 항목을 모두 통과하면 무언가 해도 된다는 함의를 만들지 않는다 ("이 체크리스트를 통과하면" 류 문장 금지).

### 4.2 확인할 데이터

- 형식: **데이터 항목 + 확인 방법**의 목록. "어떤 데이터를, 어디서(출처 유형), 어떤 기준으로(하루 vs 누적, 기준시각)" 볼지만 쓴다.
- 데이터의 **현재 값·방향·평가를 쓰지 않는다**. Phase 1에는 데이터가 없다는 전제를 유지한다.
- 출처는 "거래소 공시, 공식 고시" 같은 **출처 유형**으로 쓰고, 특정 상용 서비스명 나열은 피한다(약관/재제공 검토 전).
- 상세 규칙은 §9.

### 4.3 오해하기 쉬운 패턴

- 형식: 패턴별 4부 구조(§8.1). 2~5개 권장.
- 이 블록은 사고당 위험이 가장 큰 블록이다. **§8의 별도 작성 규칙을 반드시 따른다.**

### 4.4 투자 일지 질문

- 형식: 기록으로 남길 **질문형 목록**. 2~5개 권장.
- 감정 태그와 판단 근거를 **분리해서** 기록하게 유도한다.
- 상세 규칙은 §10.

## 5. 작성 문체 규칙

| # | 규칙 | 설명 |
|---|---|---|
| 1 | **단정 어미 금지** | 시장/데이터에 대해 "~입니다 / ~하고 있다 / ~일 것이다"로 끝내지 않는다. "~인지 확인하는 것이 좋습니다 / ~인지 점검할 수 있습니다"로 전환한다 |
| 2 | **행동 명령형 금지** | "사라/팔라/줄여라/늘려라/기다려라/서둘러라" 등 매매·포지션 관련 명령형·권유형을 쓰지 않는다. 허용되는 명령형은 "확인해보세요 / 기록해보세요" 등 **확인·기록 행동**뿐이다 |
| 3 | **질문형 우선** | 체크리스트·일지 블록은 질문형으로 끝낸다. 평서문이 필요하면 "확인 방법 안내" 문형만 사용한다 |
| 4 | **주어를 사용자에게** | "나는 무엇에 반응하고 있는가?"처럼 사용자의 자기 점검 주어를 쓴다. "AI가 보기에 / 일반적으로는 ~가 맞다" 같은 화자 판단 주어를 피한다 |
| 5 | **확률·전망 언어 금지** | "가능성이 높다/낮다, 유력하다, 예상된다, 전망이다"를 시장 방향에 대해 쓰지 않는다. 확률 표현으로 위장한 예측도 예측이다 |
| 6 | **성과 언어 금지** | "수익에 도움이 된다, 손실을 줄여준다, 승률" 등 성과 프레이밍을 쓰지 않는다. 렌즈의 효용은 "판단 근거를 더 명확히 **기록**할 수 있다"까지로 서술한다 |
| 7 | **가치 평가 형용사 주의** | 시장/종목/가격에 "좋다/나쁘다/싸다/비싸다/매력적이다"를 쓰지 않는다. "저평가/고평가"도 결론이므로 금지 |
| 8 | **긴박감 조성 금지** | "지금 아니면, 놓치기 전에, 서두르지 않으면" 류 시점 압박 표현 금지 |
| 9 | **중립 어휘** | 렌즈 key는 영문 kebab-case, 본문은 한국어. 마케팅 톤·이모지·과장 수식어 없이 정책 문서 톤을 유지한다 |
| 10 | **거절 문맥의 지칭은 허용** | "목표가는 제공하지 않습니다"처럼 금지 항목을 **지칭·설명**하는 문장은 허용된다(validator §6). 단 "제공하지 않지만 굳이 말하면 ~" 류 조건부 제공은 어떤 문맥에서도 금지 |

## 6. 금지 표현

아래 표현이 **제공/지시/추천/예측 맥락**으로 렌즈 문서에 나타나면 즉시 반려한다. (거절·정책 설명 맥락의 지칭은 §5-10 예외.)

| 군 | 금지 표현 예 | 이유 |
|---|---|---|
| 매매 지시 | 사세요 / 파세요 / 매수하세요 / 매도하세요 / 보유하세요 / 정리하세요 / 들고 가세요 | 직접 투자 행동 지시 |
| 가격·시점 | 목표가 / 손절가 / 익절 / 진입 타이밍 / 매수 기회 / 매도 타이밍 / 저점 / 고점 (시점 판단 맥락) | 가격·시점 제시는 매매 판단으로 기능 |
| 수량·비중 | 몇 주 / N% 비중 / 비중 확대·축소 / 분할 매수·매도 지시 | 포지션 조정 지시 |
| 추천 | 추천합니다 / 이 종목·업종·지역이 좋다 / 급등주 / 유망주 | 종목·업종 추천 (업종 우회 포함) |
| 예측·성과 | 오를 것 / 빠질 것 / 급등 가능 / 수익 가능 / 손실 방지 / 확실합니다 / 유력합니다 | 확정 예측, 이익 보장·손실 보전 오인 |
| 데이터 단정 | 외국인이 사고 있다 / 수급이 좋다 / 컨센서스가 좋다 / PER이 낮다 / 환율 때문이다 | 출처·기준시각 없는 사실·인과 단정 |
| 감정 판단 | FOMO이니 사지 마세요 / 불안해할 필요 없습니다 (행동 연결 맥락) | 감정 평가 + 행동 지시 |
| 과거 평가 | 그때 산 건 잘못 / 팔았어야 했다 / 다음부터 사지 마라 | 기록 기반 행동 결론 |
| 판단 공식 | A이면 매수 / B이면 매도 / 이 조건이면 진입 고려 | 조건→행동 규칙 생성 |
| 통과 함의 | 이 체크리스트를 통과하면 / 항목이 모두 충족되면 | 체크리스트의 매매 승인 장치화 |
| 우회 서술 | 참고로만 말하면 / 일반적으로는 ~가 정답 / 교과서적으로는 사야 | 면책을 가장한 판단 제공 |
| Advisory 예고 | 향후 조언 기능으로 확장 / 프리미엄에서는 판단 제공 | Advisory Mode 암시 금지 (overview §12) |

## 7. 허용 표현

작성자는 아래 문형 안에서만 서술한다. 새 문형이 필요하면 본 표준 개정으로 추가한다.

| 문형 | 예 |
|---|---|
| 확인 질문형 | "수급이 하루짜리인지 누적 흐름인지 확인했는가?" |
| 확인 방법 안내형 | "외국인 수급은 일별 데이터와 누적 데이터를 함께 보는 것이 좋습니다." |
| 관점 분해형 | "이 질문은 실적·수급·이벤트·감정 요인으로 나눠 볼 수 있습니다." |
| 개념 일반론형 | "리밸런싱은 ~하는 절차를 말합니다." (종목·시점과 연결하지 않는 정의까지만) |
| 기록 유도형 | "지금의 판단 근거를 한 문장으로 기록해보세요." |
| 감정 분리형 | "지금의 감정을 한 단어로 기록한다면? (예: FOMO, 불안, 확신)" |
| 중립 비교형 | "입력가 대비 단순 차이 +N%" (사용자 입력값 라벨링 필수, 행동 프레이밍 금지) |
| 한계 고지형 | "현재 데이터가 연결되어 있지 않아 단정할 수 없습니다." |
| 거절 지칭형 | "목표가는 제공하지 않습니다." |
| 고지형 | "이 내용은 투자 권유가 아니라 체크리스트입니다." |

- 판별 기준: 문장을 읽은 사용자가 **"무엇을 해야 하는지"를 얻으면 위반, "무엇을 확인·기록할지"를 얻으면 허용**이다.

## 8. 오해하기 쉬운 패턴 작성 규칙

이 블록은 렌즈 문서에서 가장 새기 쉬운 부분이다. "흔한 해석 오류"를 알려주는 서술이 뒤집히는 순간 매매 신호 사전이 되기 때문이다. 아래 규칙을 예외 없이 적용한다.

### 8.1 패턴별 4부 구조 (고정)

```text
[패턴]        흔히 하는 해석을 중립 서술로 기술
[놓치는 것]    그 해석이 흔히 확인하지 않는 항목
[확인 질문]    놓친 항목을 스스로 점검하는 질문
[기록 질문]    이 패턴에 해당했는지 일지에 남길 질문
```

- 4부 어디에도 "올바른 해석은 ~다"라는 **정답 제시를 두지 않는다.** 렌즈는 오류를 교정하지 않고, 확인하지 않은 것을 확인하게 한다.

### 8.2 역신호화 금지 (핵심 규칙)

- **패턴의 부정이 행동이 되게 쓰지 않는다.** "하루 순매수를 추세로 오해하기 쉽다"까지는 관찰이지만, "누적 순매수라면 추세로 볼 수 있다"를 덧붙이는 순간 조건-행동 공식이 된다. 뒷문장을 쓰지 않는다.
- **"이 패턴이 아니면 안전하다/기회다"라는 대칭 함의를 만들지 않는다.** 패턴 서술 뒤에는 반드시 확인 질문·기록 질문만 온다.
- "이 패턴이 보이면 매수/매도 기회" 형식은 어떤 완곡 표현("고려해볼 수 있다", "관심을 가질 만하다")으로도 금지다.

### 8.3 사례 서술 제한

- 특정 종목·특정 날짜의 사건을 "이런 일이 있었다"로 단정 인용하지 않는다. 사례가 필요하면 종목·시점을 지우고 "예를 들어 ~한 상황을 가정하면"의 **명시적 가상 사례**로 쓴다.
- 가상 사례에도 가격 수치·수익률 수치를 넣지 않는다. 수치가 들어간 사례는 목표가·성과 예시처럼 재인용될 수 있다.
- 패턴의 발생 빈도·적중률을 수치화하지 않는다 ("십중팔구", "대부분 틀린다" 포함). 빈도 단정은 확률 예측의 다른 형태다.

### 8.4 감정 관련 패턴

- 감정이 개입된 패턴(추격, 공포 매도 등)은 **행동의 서술**로만 쓰고, 감정 상태의 평가("비합리적이다")나 교정 지시("참아라")를 붙이지 않는다. 확인·기록 질문으로만 연결한다.

## 9. 데이터/시세/시장 사실 작성 규칙

`finance-market-data-grounding.md`를 렌즈 작성 관점으로 요약 적용한다. 충돌 시 grounding 문서가 이긴다.

| # | 규칙 |
|---|---|
| 1 | **Phase 1 전제 고정**: 렌즈 문서는 실시간 시세/수급/컨센서스 데이터가 **없다**는 전제로 작성한다. "데이터가 연결되면 ~를 판단해준다"는 예고도 쓰지 않는다 (수치 표시 ≠ 판단 허용 — validator §10) |
| 2 | **현재형 단정 금지**: 시장에 대한 "지금 ~하고 있다" 문장은 출처+기준시각이 있어도 렌즈 **문서**에는 쓰지 않는다. 문서는 시점 무관하게 읽히기 때문이다 |
| 3 | **전환 공식 적용**: "~입니다" → "~인지 확인하는 것이 좋습니다" |
| 4 | **출처·기준시각을 확인 항목으로**: "데이터의 출처와 기준시각을 확인했는가?"를 확인할 데이터 블록의 상수 항목으로 포함한다 |
| 5 | **달력 사실의 한계**: 월말/분기말 여부, 공표된 일정 등 달력상 확정 사실은 언급 가능하나, 그로부터의 시장 영향 단정("그래서 매도가 나온다")은 금지 |
| 6 | **사용자 입력값 라벨링**: 사용자 입력 가격/수량을 다루는 서술은 항상 "입력값/기록 기준"으로 라벨링하고, 중립 수치 비교(단순 차이)까지만 허용. 익절/손절/물타기 프레이밍 금지 |
| 7 | **수치 사용 최소화**: 렌즈 문서 본문에 가격·지표·수익률 수치를 쓰지 않는다. 개념 설명에 수치가 불가피하면 가상의 값임을 명시하고 실제 종목·현재 시점과 연결하지 않는다 |
| 8 | **인과 단정 금지**: "환율 때문에", "금리 때문에" 등 단일 원인 단정을 쓰지 않는다. "~와의 관계를 확인할 수 있다"로 전환한다 |

## 10. Journal/Review 질문 작성 규칙

| # | 규칙 |
|---|---|
| 1 | **질문으로만 끝난다**: 일지/복기 블록의 모든 항목은 질문형이다. 행동 결론("그러니 다음엔 ~해라")으로 끝나면 validator §12 실패 유형(unsafe journal review conclusion)이다 |
| 2 | **감정과 근거의 분리**: 감정 태그 기록 질문과 판단 근거 기록 질문을 별도 항목으로 둔다. 두 개를 한 문장에 섞어 감정을 근거의 평가어로 쓰지 않는다 |
| 3 | **과거 평가 금지**: "당시 판단이 옳았는가/틀렸는가"를 묻지 않는다. "당시 무엇을 확인했고 무엇이 비어 있었는가"를 묻는다 |
| 4 | **미래 행동 지시 금지**: "다음에는 ~하기로 하자" 형식 금지. "다음 기록에는 ~를 함께 남겨보면 어떤가?"처럼 **기록 행동**까지만 유도한다 |
| 5 | **반증 질문 허용**: "이 판단이 틀렸다고 볼 신호를 미리 정할 수 있는가?"는 허용된다. 단 그 신호에 구체 가격("~원 이탈")을 예시로 붙이면 손절가 제시로 기능하므로 금지 |
| 6 | **CTA 연결**: 블록 마지막은 기록/복기 CTA 문형("공부 노트로 저장", "다음 일지에 남겨보세요")으로 닫는다. 매매 행동 CTA는 서비스 정책 §11에 따라 금지 |

## 11. PolicyGuard 연결 규칙

| # | 규칙 |
|---|---|
| 1 | **렌즈는 guard 뒤에서만 동작한다**: 렌즈 문서에 "이 렌즈가 위험 질문을 판별/처리한다"는 서술을 두지 않는다. 위험 intent 탐지는 Input Guard, 거절 선언은 guard/템플릿 책임이다 |
| 2 | **forbidden intent는 경고 표지다**: metadata의 forbidden intent는 "이 렌즈로 자주 유입되는 위험 질문 유형"의 목록이며, 렌즈가 그 질문에 답하는 근거가 아니다 |
| 3 | **redirect 대상으로서의 서술**: 렌즈가 RISK_* redirect 대상인 경우, 렌즈 콘텐츠는 "거절 선언 **이후에** 제공되는 체크리스트"로 소비된다는 점을 metadata에 명시한다. 렌즈 본문에 거절 선언 문구를 중복 작성하지 않는다 (거절 문구는 templates 책임) |
| 4 | **신규 위험 패턴의 귀속**: 렌즈 작성 중 새 위험 표현(자산군 특유의 판단 요청 등)을 발견하면 렌즈 문서에 규칙을 만들지 말고 `finance-policyguard-rules.md` §7.1 패턴 보강으로 제안한다. guard 규칙의 source of truth는 policyguard 문서 하나다 |
| 5 | **우회 서술 금지**: "guard가 없다면 이렇게 답할 수 있다" 류의 가정 서술을 렌즈 문서에 두지 않는다. 그 자체가 우회 프롬프트의 재료가 된다 |

## 12. Output Validator 체크포인트

렌즈 문서의 각 블록이 validator의 어떤 검사에 걸리는지 작성자가 미리 확인한다. **렌즈 문서의 문장이 그대로 LLM 응답에 인용될 수 있다**는 전제로 쓴다.

| 렌즈 문서 요소 | validator 검사 (finance-output-validator.md) | 작성자 확인 사항 |
|---|---|---|
| 체크리스트 항목 | forbidden trading action / 판단 공식 여부 | 조건-행동 문장, 통과 함의 문장 없음 |
| 확인할 데이터 | unsupported market data claim (§10) | 현재형 단정·수치·인과 단정 없음, 출처/기준시각 항목 포함 |
| 오해 패턴 | forbidden trading action / performance guarantee | 역신호화(§8.2)·빈도 수치화 없음 |
| 일지 질문 | unsafe journal review conclusion (§12) | 행동 결론·과거 평가 없음, 질문으로 종료 |
| 감정 관련 서술 | unsafe emotional judgment | 감정 평가·감정 기반 행동 지시 없음 |
| 금지 항목 지칭 | 오탐 예외 (§6) | 지칭은 거절/설명 맥락에만 존재, 조건부 제공 없음 |
| 렌즈별 금지 표현 목록 | 검사 카테고리 확장 후보 | validator 반영 필요 여부를 문서 말미에 표기 |
| 예시 응답(포함 시) | output shape (§9) | 5단 구조 + 투자 권유 아님 고지 포함 |

- 렌즈별 금지 표현(§7.3 블록, overview §7.3)에 새 표현을 추가하면, validator 문서 개정 필요 여부를 리뷰에서 판정한다. 렌즈 문서 단독으로는 검사 규칙이 생기지 않는다.

## 14. 작성 완료 전 셀프 체크리스트

렌즈 문서를 제출하기 전, 작성자가 문서 전체를 놓고 점검한다. 리뷰어도 동일 목록을 사용한다.

**구조**

- [ ] 공통 metadata envelope가 Metadata Standard(finance-knowledge-artifact-metadata-standard.md §13.1)를 준수한다
- [ ] Lens extension 10개 필드(§3)가 전부 존재한다
- [ ] lens_key가 catalog와 문자 단위로 일치한다
- [ ] 각 Lens 전용 필드가 본 문서 §3의 의미 규칙을 준수한다
- [ ] 본문 4블록(체크리스트/확인할 데이터/오해 패턴/일지 질문)이 순서대로 모두 존재한다
- [ ] 오해 패턴이 모두 4부 구조(§8.1)를 따른다
- [ ] 예시 응답을 넣었다면 5단 구조와 고지를 포함한다

**문체·표현**

- [ ] 시장/데이터에 대한 "~입니다/~하고 있다/~일 것이다" 단정 문장이 없다
- [ ] §6 금지 표현이 제공/지시/추천/예측 맥락으로 등장하지 않는다 (지칭은 거절/설명 맥락뿐이다)
- [ ] "A이면 B하라" 및 반쪽 공식("그렇다면 고려")이 없다
- [ ] "체크리스트 통과 = 행동 가능" 함의가 없다
- [ ] 좋다/나쁘다/싸다/비싸다/저평가/고평가 등 가치 결론이 없다
- [ ] 확률·전망·성과·긴박감 표현이 없다

**데이터**

- [ ] 가격/지표/수익률 수치가 없다 (가상 사례 예외 요건 §8.3, §9-7 충족 시만)
- [ ] 출처/기준시각 확인 항목이 확인할 데이터 블록에 있다
- [ ] 달력 사실 언급이 시장 영향 단정으로 이어지지 않는다
- [ ] 사용자 입력값 서술에 라벨링과 중립 비교 한계가 지켜졌다

**일지/감정**

- [ ] 일지/복기 항목이 전부 질문형이고 행동 결론이 없다
- [ ] 감정 평가·감정 기반 행동 지시가 없다
- [ ] 반증 질문에 구체 가격 예시가 붙지 않았다

**연결**

- [ ] forbidden intent가 "guard 선행" 의미로 서술되어 있다
- [ ] 거절 선언 문구를 렌즈 본문에 중복 작성하지 않았다
- [ ] 신규 위험 패턴 발견 시 policyguard 보강 제안으로 분리했다
- [ ] Advisory Mode 관련 서술·암시가 없다

**최종 판별 질문**

- [ ] 이 문서의 어떤 문장도, 단독으로 인용됐을 때 "무엇을 하라"로 읽히지 않는가?

## 15. 나쁜 예시와 안전한 수정 예시

아래 왼쪽 열은 **금지 예시의 인용**이며, 어떤 렌즈 문서에도 그대로 쓸 수 없다.

| 위반 유형 | 나쁜 예시 (금지) | 안전한 수정 |
|---|---|---|
| 매매 판단 | "수급이 누적 순매수라면 매수를 고려할 수 있습니다." | "수급이 하루짜리인지 누적 흐름인지 확인했는가?" |
| 판단 공식 | "실적 발표 전 기대가 과열이면 비중을 줄이는 것이 정석입니다." | "실적 기대가 이미 가격에 반영됐다고 볼 근거가 있는가?" |
| 통과 함의 | "아래 항목을 모두 확인했다면 진입해도 늦지 않습니다." | "아래 항목 중 아직 확인하지 않은 것은 무엇인가?" |
| 가격 제시 | "리스크 기준은 보통 매수가의 -7% 선에서 잡습니다." | "나의 리스크 허용 기준을 어떤 근거로 정할 것인지 기록해보세요." |
| 추천(업종 우회) | "종목은 고를 수 없지만 반도체 업황은 긍정적입니다." | "이 종목의 이슈가 업황 요인인지 개별 요인인지 확인했는가?" |
| 확정 예측 | "월말 리밸런싱 매도가 나올 가능성이 높습니다." | "월말/분기말 리밸런싱 구간에 해당하는지 확인했는가?" |
| 데이터 단정 | "외국인이 순매수 중이므로 수급은 우호적입니다." | "외국인 순매수가 하루짜리인지 누적 흐름인지, 출처와 기준시각과 함께 확인하는 것이 좋습니다." |
