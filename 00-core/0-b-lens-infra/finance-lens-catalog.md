# finance-lens-catalog.md

> **상태**: 초안 v0.1
> **상위 문서**: `finance-harness-reuse-map.md` (패턴 매핑), `00-service-policy.md` (금지 정책)
> **범위**: 금융 하네스에서 사용할 finance lens 목록과 각 렌즈의 책임 정의
> **불변 원칙**: **판단하지 않고, 기록하게 한다.** 매수/매도/목표가/손절가/수량/비중/종목추천은 어떤 렌즈에서도 출력하지 않는다.

---

## 1. finance lens의 정의

**finance lens는 막연한 투자 질문을 특정 확인 관점의 체크리스트로 구조화하는 단위다.**

- 렌즈는 **답을 주지 않는다.** 확인할 항목을 준다.
- 렌즈는 **사실을 단정하지 않는다.** Phase 1에는 실시간 데이터가 없으므로 "확인하는 방법"만 안내한다.
- 렌즈의 출력은 항상 **기록/복기 CTA**로 끝난다 (질문 → 체크리스트 → 기록 → 복기 루프).
- 하나의 질문에 **복수 렌즈가 적용**될 수 있다 (routing은 `00-core/0-c-runtime-contract/finance-routing-contract-v1.md` 책임).

렌즈 공통 출력 구조:

```text
1. 질문 재해석
2. 적용된 렌즈(관점)
3. 확인할 체크리스트
4. 기록/복기 질문
5. 투자 권유 아님 고지
```

## 2. 개발 하네스 skill과 finance lens의 관계

| 항목 | 개발 하네스 skill | finance lens |
|---|---|---|
| 입력 | 작업 TASK | 투자 질문 |
| 역할 | TASK 유형별 처리 관점 | 질문 유형별 확인 관점 |
| metadata | key, trigger, output | key, trigger, **forbidden intent**, output style |
| 출력 | docs/code/decision/risk 후보 | 체크리스트 + 기록/복기 질문 |
| 종료 | handoff | journal/review CTA |

- 구조적으로 동일한 routing 패턴을 공유하며, 렌즈는 **forbidden intent 필드가 추가**된 skill이다.
- forbidden intent가 감지되면 렌즈 출력 대신 **거절 → 체크리스트 redirect** 표준 응답으로 전환된다 (`finance-policyguard-rules.md` 책임).

## 3. MVP 핵심 렌즈 (5개)

### 3.1 `market-context`

| 항목 | 내용 |
|---|---|
| 목적 | "요즘 어때?"류 막연한 질문을 시장 국면 확인 관점으로 구조화 |
| 사용 조건 | 종목/시장에 대한 포괄적 질문, 다른 렌즈 선택이 애매한 기본 진입점 |

체크리스트 예시:

```text
- 이 질문은 단기/중기/장기 중 어느 관점인가?
- 지금 시장이 상승/하락/횡보 중 어느 국면이라고 보는가? 그 근거는?
- 종목 이슈인가, 시장 전체 이슈인가?
- 최근 흐름 중 가격 외에 확인한 정보가 있는가?
```

금지 표현:

```text
지금 시장은 좋습니다 / 나쁩니다 (단정)
지금이 저점/고점입니다
비중을 늘리기/줄이기 좋은 구간입니다
```

---

### 3.2 `supply-demand`

| 항목 | 내용 |
|---|---|
| 목적 | 수급(외국인/기관/개인) 관련 질문을 누적 흐름 확인 관점으로 구조화 |
| 사용 조건 | 수급, 매수세, 외국인/기관, 리밸런싱 등 언급 시 |

체크리스트 예시:

```text
- 외국인/기관 수급이 하루짜리인지 누적 흐름인지 확인했는가?
- 월말/분기말 리밸런싱 구간인지 확인했는가?
- 수급과 가격이 같은 방향인가, 엇갈리는가?
- 수급 데이터를 어디서 확인할 것인가?
```

금지 표현:

```text
외국인이 순매수 중이므로 긍정적입니다 (사실 단정)
수급이 좋으니 사도 됩니다
기관이 팔고 있으니 파세요
```

---

### 3.3 `earnings`

| 항목 | 내용 |
|---|---|
| 목적 | 실적/펀더멘탈 질문을 기대 반영 여부 확인 관점으로 구조화 |
| 사용 조건 | 실적, 어닝, 컨센서스, 펀더멘탈 언급 시 |

체크리스트 예시:

```text
- 다음 실적 발표 일정은 언제인가?
- 시장 기대(컨센서스)가 이미 가격에 반영됐다고 볼 근거가 있는가?
- 실적 기대의 근거가 산업 업황인가, 회사 개별 요인인가?
- 실적이 기대에 못 미치면 나는 어떻게 할 계획인가? (기록용)
```

금지 표현:

```text
실적이 좋을 것이므로 매수 적기입니다
컨센서스 상회가 확실합니다 (단정)
목표가는 O원입니다
```

---

### 3.4 `event-calendar`

| 항목 | 내용 |
|---|---|
| 목적 | 시점성 이벤트(리밸런싱, FOMC, 옵션만기, 실적시즌)를 확인 관점으로 구조화 |
| 사용 조건 | 월말/분기말, 특정 일정, "이번 주에 뭐 있어?"류 질문 시 |

체크리스트 예시:

```text
- 이번 주/이번 달에 예정된 시장 이벤트는 무엇인가?
- 월말/분기말 리밸런싱 구간에 해당하는가?
- 이벤트가 이 종목/시장에 영향을 주는 경로는 무엇이라 생각하는가?
- 이벤트 전후로 내가 확인할 데이터는 무엇인가?
```

금지 표현:

```text
이벤트 전에 사두세요 / 팔아두세요
이벤트 후 급등/급락이 예상됩니다 (단정)
이벤트 매매 전략을 추천합니다
```

---

### 3.5 `emotion-check`

| 항목 | 내용 |
|---|---|
| 목적 | FOMO/불안/조급함 등 감정이 섞인 질문에서 감정과 판단 근거를 분리 |
| 사용 조건 | "너무 오르는데", "따라가도 돼?", "무서운데", "물렸는데" 등 감정 신호 감지 시 |

체크리스트 예시:

```text
- 지금 반응하는 것은 정보인가, 가격 움직임인가?
- 이 종목을 원래 관찰하고 있었는가, 오르는 것을 보고 알게 됐는가?
- 지금의 감정을 한 단어로 기록한다면? (예: FOMO, 불안, 확신)
- 이 판단이 틀렸다고 볼 신호를 미리 정할 수 있는가?
```

금지 표현:

```text
따라가도 됩니다 / 늦었습니다
FOMO이니 사지 마세요 (행동 지시)
지금 들어가면 물립니다
```

> ⚠️ `emotion-check`는 감정을 **평가하지 않는다.** 감정 태그를 기록하게 하고 판단 근거와 분리하는 것까지가 책임이다.

## 4. MVP 이후 확장 렌즈

| 렌즈 | 목적 | 확장 시점 판단 기준 |
|---|---|---|
| `valuation` | 밸류에이션 확인 관점 (PER/PBR 등 지표를 "어디서 어떻게 볼지") | 목표가 요청 거절 후 redirect 대상으로 수요 확인 시 |
| `macro-rate-fx` | 금리/환율 환경 확인 관점 | 매크로 질문 빈도 확인 시 |
| `sector-cycle` | 업황/섹터 사이클 확인 관점 | 종목 질문이 산업 질문으로 확장되는 패턴 확인 시 |
| `journal-review` | 과거 기록 기반 복기 질문 생성 | Journal 데이터 누적 후 (Review 정책 §8 준수) |
| `risk-checklist` | 판단 전 리스크 기준 기록 유도 | 손절가 요청 거절 후 redirect 대상으로 수요 확인 시 |

- 확장 렌즈도 §1의 공통 출력 구조와 금지 원칙을 동일하게 따른다.
- `journal-review`는 **과거 행동 평가 금지** ("그때 산 것은 잘못입니다" 불가), 누락 체크리스트와 회고 질문 생성만 허용.

## 5. 예시 질문별 적용 렌즈

| 사용자 질문 | 적용 렌즈 | 라우팅 근거 |
|---|---|---|
| "하이닉스 요즘 어때?" | `market-context` + `supply-demand` + `earnings` | 막연한 종목 질문 → 기본 3관점 분해 |
| "월말 리밸런싱이 뭐야?" | `event-calendar` (+ Learn 개념 설명) | 개념 질문 + 시점성 이벤트 |
| "실적 발표 전에 뭘 봐야 해?" | `earnings` + `event-calendar` | 실적 관점 + 일정 확인 |
| "지금 너무 오르는 것 같은데 따라가도 돼?" | `emotion-check` + `market-context` | **forbidden intent 주의** — "따라가도 돼?"는 매수 판단 요청이므로 직접 판단 거절 후 감정 분리 체크리스트로 redirect |

> 마지막 예시처럼 **판단 요청이 섞인 질문**은 렌즈 적용 전에 Input Guard가 먼저 발동한다. 거절 표준 응답 → 렌즈 체크리스트 redirect 순서는 `finance-policyguard-rules.md`가 정의한다.
