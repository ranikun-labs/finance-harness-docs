## 1. 렌즈 목적

**AI 인프라 관련 질문을 "수요 원천 → 워크로드 → 컴퓨트 실리콘 → 메모리 의존 → 네트워킹 → 시스템 통합 → 전력·냉각 → 데이터센터 → 클라우드·플랫폼 → 소프트웨어·서비스"의 구조 지도와, 노드별·의존별 확인 항목으로 구조화한다.**

이 렌즈는 03-domain-deep-dive의 **공간 축(밸류체인 구조)** 렌즈다. 계층 경계를 먼저 고정한다:

```text
- semiconductor-cycle   은 시간 축 — 제품 가격, 재고, capacity, 가동률,
                        수율, 리드타임, 공급 조정, 사이클 시차 구조와
                        그 확인 방법론을 소유한다. 사이클 위치의 현재·
                        과거 검증 방법론도 그 렌즈의 책임이다.
                        본 렌즈는 이 변수들의 수준·추이·메커니즘을
                        다루지 않는다.
- ai-compute-value-chain(본 렌즈)은 공간 축 — 노드의 역할, 노드 간
                        구조적 의존, 수요가 어디서 발생해 어떤 경로로
                        전달되는가, 제약이 어느 경로로 파급될 수 있는가,
                        대체 경로의 존재, 그리고 각 노드·의존에서
                        확인할 질문만 소유한다.
- sector-cycle          은 산업 불문의 범용 사이클 분해 축과 층위 구분을
                        소유한다. 본 렌즈는 사이클 렌즈가 아니다.
- earnings              는 실적 일정·기대·요인의 해석 프레임을 소유한다.
                        본 렌즈는 노드별 "확인 가능한 공시 항목의 유형"
                        안내까지만 담당하고, 실적 해석·전망은 하지 않는다.
- supply-demand         는 투자자 수급(자금 흐름) 분석을 소유한다.
                        본 렌즈의 "수요/공급"은 컴퓨트 자원과 인프라의
                        물리적 수요·공급 구조이며, 투자자 자금 흐름이
                        아니다.
- market-context        는 기간 좌표화와 국면 가정의 기록 프레임을
                        소유한다. "AI 시대" 류 국면 서사는 본 렌즈의
                        소재가 아니다 — 수요 "구조"의 설명과 수요의
                        "현재 강도" 단정은 다르며, 후자는
                        RISK_DATA_GROUNDING 경로다.
- macro-rate-fx         는 환율·금리 변수의 해석을 소유한다. 본 렌즈는
                        환율이 체인 원가 구조에 개입하는 "경로의 확인
                        항목"까지만 언급한다.
- 02 Asset-Class 계층   은 ETF·지수 상품의 vehicle 구조를 배타 소유한다.
                        상품(vehicle) 구조의 확인 관점은 02 계층 유지,
                        본 렌즈는 산업 체인 구조만 담당한다.
```

분석 모델 (체인의 노드 구분 — 확인 항목의 주소 체계):

```text
노드 1. 수요 원천        — AI 서비스·기업 수요가 인프라 투자로 전환되는
                          출발점. CAPEX는 여기서 "구조적 흐름의 경로"
                          로만 다룬다 (수준·추이 확인은 semiconductor-
                          cycle, 방향 단정은 어느 렌즈도 하지 않는다)
노드 2. 컴퓨트 워크로드   — 학습과 추론 등 워크로드 성격의 구분과,
                          워크로드 구분이 하위 노드 요구를 다르게
                          만드는 구조
노드 3. 가속기·컴퓨트 실리콘 — 범용 가속기와 전용 칩(설계 주체·수요처
                          구분), 설계–위탁생산–패키징의 분업 구조
노드 4. 메모리 의존       — 가속기와 고대역폭 메모리의 결합이 만드는
                          구조적 의존 관계. **아키텍처상 의존 구조까지만**
                          — 메모리의 가격·재고·capacity·가동률·공급
                          사이클은 semiconductor-cycle 소유
노드 5. 네트워킹·인터커넥트 — 컴퓨트 노드 간 연결이 시스템 성능의
                          구성 요소가 되는 구조
노드 6. 서버·시스템 통합   — 부품이 시스템으로 조립·통합되는 단계의
                          역할 구조
노드 7. 전력·냉각         — 컴퓨트 밀도가 전력·냉각 요구로 전환되는
                          구조와, 인프라 제약이 발생할 수 있는 위치
노드 8. 데이터센터 인프라  — 부지·건설·설비가 컴퓨트 배치의 물리적
                          전제가 되는 구조
노드 9. 클라우드·플랫폼    — 인프라가 서비스로 제공되는 계층과
                          수요–공급의 중개 구조
노드 10. 소프트웨어·서비스 — 최종 수요가 발생·확인되는 계층 (본 렌즈는
                          이 계층의 존재와 접점 확인까지만 — 애플리케이션
                          체인 자체는 본 렌즈 범위 밖)
```

노드 위에 겹치는 세 가지 경로 개념:

```text
의존 경로   — 한 노드의 산출이 다른 노드의 전제가 되는 구조적 연결.
             "무엇이 없으면 무엇이 진행되지 않는가"의 확인 주소.
병목 경로   — 의존 경로 중 공급 제약이 파급될 수 있는 위치.
             본 렌즈는 "제약이 발생할 수 있는 구조적 위치"와
             "제약의 존재를 확인할 항목"까지만 다룬다.
             현재 어느 노드가 병목인지의 단정, 병목의 심화·해소
             전망은 다루지 않는다.
대체 경로   — 동일 기능을 다른 구성으로 달성할 수 있는 구조적 분기
             (예: 범용 가속기 ↔ 전용 칩, 복수 공급 경로).
             대체 가능성의 "존재 확인"까지 — 대체의 우열·전환
             전망은 다루지 않는다.
```

- 이 렌즈는 체인의 어떤 노드에 대해서도 **현재 상태를 판정하지 않는다.** 수요 강도, 공급 부족, 병목 위치, CAPEX 추이, 가동 상황은 전부 시점 민감 데이터이며, 그에 대한 질문은 확인 항목으로 전환된다. 이 렌즈의 책임은 "AI 인프라"라는 뭉뚱그려진 인상을 **노드·의존·경로 단위의 확인 가능한 질문 목록**으로 분해하게 하는 것까지다.
- **노드는 확인 항목의 주소이지 투자 대상 목록이 아니다.** 어떤 노드도 "유리한 위치"로 서술되지 않으며, 노드 서술은 기업명 열거를 최소화하고 역할·계층 중심으로 한다.
- 고대역폭 메모리(HBM)는 본 렌즈에서 **가속기–메모리 결합이 만드는 아키텍처상 의존 구조의 확인**까지만 다룬다. 그 메모리의 가격 구조·재고·capacity·가동률·공급 사이클 메커니즘은 semiconductor-cycle의 책임이며 본 렌즈는 중복 서술하지 않는다.
- 국가·지역별 체인 역할(설계/제조/패키징/장비/소재의 지역 분담 구조와 정책 변수)은 본 렌즈의 노드 서술에 포함되는 확인 항목이다. 공시·공개 자료로 확인 가능한 범위까지만 다루며, **지정학 전망은 어떤 형태로도 다루지 않는다.**

## 3. 이 렌즈가 다루지 않는 질문

**"AI"라는 소재가 intent 분류를 완화하지 않는다** (semiconductor-cycle §3, macro-rate-fx §3의 자산군 불변 원칙과 동일). 아래 질문은 Input Guard가 먼저 분류하고, 거절/안내 선언 이후에만 이 렌즈의 확인 항목이 redirect로 제공될 수 있다.

| 질문 | intent | 처리 |
|---|---|---|
| "AI 밸류체인 최대 수혜주 뭐야?" | RISK_RECOMMENDATION | REFUSE_AND_REDIRECT — 종목 제시 불가. **체인 구조 설명이 수혜주 지목으로 우회되지 않는다.** redirect 응답은 노드별 확인 기준까지만 제공한다 |
| "장비·소재 쪽에서 제일 좋은 노드가 어디야?" | RISK_RECOMMENDATION | REFUSE_AND_REDIRECT — 노드·계층의 우열 서열도 추천의 우회 형태다 |
| "HBM 지금 부족하지?" | RISK_DATA_GROUNDING | 공급 상태의 현재형 단정 유도 — 단정 불가 안내 선행. 공급 변수의 확인 방법론은 semiconductor-cycle redirect의 소재다 |
| "AI 수요 아직 강하지? 꺾인 거 아니지?" | RISK_DATA_GROUNDING | 수요 강도의 현재형 단정·동의 유도 — 단정 불가 안내 + 확인 항목 전환 |

```text
  발표로 확인된 사실과 전망·해설을 구분해 적었는가?
- 체인 구조에 대한 나의 가정은 무엇이고, 그 가정이 틀렸다고
  볼 확인 항목을 미리 정했는가?
```

## 5. 확인할 데이터

Phase 1에는 데이터가 연결되어 있지 않으므로, 아래는 **사용자가 직접 확인할 항목과 출처 유형**이다. 이 렌즈는 어떤 노드의 현재 수요·공급·가동·병목 상태도 제시하지 않으며, 특정 상용 서비스명을 나열하지 않는다 (standard §4.2).

| 확인 항목 | 확인 방법 (출처 유형) | 유의 |
|---|---|---|
| 수요 원천 노드의 투자 공시 | 해당 기업의 공시·공식 발표 자료 | 가이던스(계획)와 집행(실적)의 구분, 회계 기간 확인. **수준·추이의 확인 방법론은 semiconductor-cycle §5와 병행** |
| 노드별 사업 구성 | 각 노드 기업의 공시 내 사업 부문 서술 | 부문 구분 기준이 회사마다 다름 — 같은 이름의 부문이 같은 범위가 아님을 확인 |
| 고객·매출 구성의 공개 범위 | 공시 내 주요 고객·지역 구성 서술의 유무 | **고객·비중은 비공개 관행이 일반적이다** — 공시에 존재하는 범위까지만 확인 가능하며, 비공개 관계를 확인된 것처럼 취급하지 않는다 |
| 가속기–메모리 결합 구조 | 제품 공개 자료·기술 문서의 구성 서술 | 아키텍처상 의존의 확인까지 — 해당 메모리의 가격·재고·공급 상황은 semiconductor-cycle의 확인 항목 |
| 네트워킹·시스템 구성 | 제품·시스템 공개 자료 | 구성 요소의 역할 확인까지 — 특정 구성의 우열 평가 없음 |
| 전력·냉각·데이터센터 제약 | 인프라 관련 공시·공개 계획 자료, 공공 인허가·전력 관련 공표 자료 | **제약의 존재 확인까지** — 제약의 심화/해소 전망은 별개의 미확인 주장 |
| 지역별 역할 분담 | 각 사 공시의 생산·시설 지역 서술, 공식 정책 발표 원문 | 공시·공식 발표로 확인되는 범위까지 — 정책의 시장 영향 단정과 지정학 전망은 하지 않는다 |
| 정책·규제 변수의 존재 | 규제·정책 기관의 공식 발표 원문 | 발표의 존재와 적용 범위 확인까지. **제도는 개정될 수 있으므로 공식 출처에서 현행 여부를 확인** |
| 대체 경로의 존재 | 공시·제품 공개 자료에서 대체 구성의 언급 유무 | 존재 확인까지 — 대체의 우열·전환 시점 전망 없음 |
| 데이터의 출처와 기준시각 | 어느 출처의, 언제 기준 자료인지 항상 함께 확인 | 상수 항목 |

### 5.1 근거의 성격 구분 (구조 지식 vs 시점 데이터)

이 렌즈의 내용은 두 성격의 지식을 다루며, 응답에서 이 둘을 섞지 않는다 (semiconductor-cycle §5.1과 동일 구분의 공간 축 적용):

```text
안정적 구조 지식 (렌즈가 설명할 수 있는 것):
  - 노드의 구분과 역할 (계층 구조, 분업 구조)
  - 의존 경로의 존재 (가속기–메모리 결합, 컴퓨트–전력 요구의 연결)
  - 대체 경로의 존재 (범용/전용의 분기, 복수 공급 경로라는 구조 유형)
  - 공개/비공개의 경계 (고객 구성·공급 관계의 공시 제한)

시점 데이터 (렌즈가 말할 수 없는 것 — grounding §2):
  - 현재 수요 강도, 현재 공급 상황, 현재 병목 위치,
    현재 CAPEX 추이, 현재 가동·배치 상황
  - 위 변수들의 방향과 그로부터의 노드별 유불리
```

- "이 노드는 대체가 어려우니 협상력이 유지된다" 같은 문장은 구조 지식처럼 보이지만 **현재 상태 단정과 방향 평가의 결합**이므로 금지다. 구조 지식의 서술은 "의존·대체 경로가 존재한다"까지이며, 그 경로로부터의 유불리·지속성 단정은 어떤 형태로도 하지 않는다.
- 체인 구도는 시간이 지나며 바뀔 수 있는 지식이다. 본 문서의 노드 구분 자체도 "작성 시점의 확인 프레임"이며, 특정 기업·구도가 고정되어 있다는 전제를 만들지 않는다.

## 6. 오해하기 쉬운 패턴

### 패턴 1. 구조 지도의 수혜 지도화

```text
[패턴]      체인의 노드·의존 지도를 "어느 노드가 돈을 버는 지도",
            즉 수혜주 목록의 대체물로 읽는 해석.
[놓치는 것]  노드는 확인 항목의 주소라는 점. 같은 노드 안에서도
            역할·매출 구성·경쟁 구조가 다르고, 그 확인은 노드
            지목이 아니라 개별 공시 확인의 문제라는 점.
[확인 질문]  나는 노드에서 "확인할 항목"을 얻었는가, "살 목록"을
            얻었다고 느끼는가? 후자라면 어떤 확인을 건너뛰었는가?
[기록 질문]  이 노드에서 내가 실제로 확인한 공시 항목과, 노드
            이름만으로 건너뛴 가정을 나눠 기록한다면?
```

### 패턴 2. 수요 서사의 사실화

```text
[패턴]      "AI 수요는 계속 커진다"는 서사를 출처·기준시각이 있는
            확인된 사실처럼 전제하고 하류 노드를 읽는 해석.
[놓치는 것]  수요 구조의 존재(수요 원천 노드가 있다)와 수요의 현재
            강도(지금 얼마나 강한가)는 다른 지식이라는 점. 후자는
            시점 데이터이며, 수요 원천 노드의 공시에서 확인할
            항목이 따로 있다는 점.
[확인 질문]  내가 전제한 수요는 어느 노드의, 언제 기준의, 어떤
            공시에서 확인된 것인가? 서사와 공시를 구분했는가?
[기록 질문]  "수요"를 근거로 적을 때, 그 옆에 출처와 기준시각을
            붙인다면 무엇을 적을 수 있고 무엇을 적을 수 없는가?
```

### 패턴 3. 병목의 고정화

```text
[패턴]      특정 노드를 "병목"으로 지목한 시점의 정보를 구조적
            상수처럼 취급하고, 이후에도 그 노드가 계속 제약이라고
            전제하는 해석.
[놓치는 것]  병목은 구조적 "위치"가 아니라 시점 민감한 "상태"라는
            점. 그리고 제약에 대응하는 공급 조정의 확인은
            semiconductor-cycle의 변수(capacity·리드타임 등)로
            따로 확인해야 한다는 점. 대체 경로의 존재 여부도
            확인 항목에서 빠져 있다는 점.
[확인 질문]  내가 아는 병목 정보의 기준시각은 언제인가? 그 이후의
            공급 대응·대체 경로를 확인할 항목을 정했는가?
[기록 질문]  병목 가정을 기록할 때 "가정한 날짜"와 "재확인할
            항목"을 함께 남긴다면 무엇인가?
```

### 패턴 4. 단일 경로 가정

```text
[패턴]      수요가 체인의 한 경로(예: 하나의 가속기 유형, 하나의
            공급 경로)로만 흐른다고 전제하고, 그 경로 위의 노드를
            필연적 통과 지점으로 읽는 해석.
[놓치는 것]  대체 경로의 존재 — 전용 칩과 범용 가속기의 분기,
            복수 공급 경로, 시스템 구성의 차이. 그리고 대체
            경로의 존재 여부 자체가 공시·공개 자료로 확인할
            항목이라는 점.
[확인 질문]  이 노드를 거치지 않는 구성이 존재하는지 확인했는가?
            "대체 불가"는 확인된 사실인가, 서사인가?
[기록 질문]  내 가정에서 "반드시 거친다"고 전제한 노드와, 그
            전제의 확인 근거를 나란히 기록한다면?
```

### 패턴 5. CAPEX 공시와 체인 전체의 등치

```text
[패턴]      수요 원천 노드의 투자 발표 하나를 체인 전 노드의 수요
            확정으로 읽는 해석.
[놓치는 것]  가이던스와 집행의 구분, 투자가 노드별로 배분되는
            구조(모든 노드에 같은 비율로 흐르지 않는다), 발표와
            하류 노드 반영 사이의 단계. 배분·시차의 확인 방법론은
            semiconductor-cycle(투자 사이클 구분)의 소재라는 점.
[확인 질문]  이 발표는 계획인가 집행인가? 내가 보는 노드에 이
            투자가 도달하는 경로에서 확인 가능한 항목은 무엇인가?
[기록 질문]  발표 시점의 기록과, 이후 각 노드에서 실제 확인한
            것을 나란히 남긴다면? (semiconductor-cycle 패턴 3의
            전/후 기록과 동일 방식)
```

## 7. 투자 일지 질문

```text
- 오늘 나의 체인 가정은 무엇이었고, 그 가정은 어느 노드와 어느
  경로(의존/병목/대체)에 대한 것인가?
- 근거로 삼은 것 중 "구조 지식"(노드·의존·대체 경로의 존재)과
  "시점 데이터"(현재 수요·공급·병목 상태)를 나눠 기록한다면 각각
  무엇인가? 시점 데이터에는 출처와 기준시각을 붙였는가?
- 내가 확인하지 않고 전제한 경로는 무엇인가? (수요가 이 노드를
  반드시 거친다 / 이 의존은 대체가 없다 / 이 제약은 계속된다
  중에서)
- 확인할 수 없었거나 불확실한 채로 남긴 것은 무엇인가?
  (고객 구성, 공급 관계 등 비공개 항목 포함)
- 나는 체인 구조의 확인을 어느 지점에서 특정 노드·기업의 유불리
  결론으로 바꿨는가, 아니면 구조 가정과 확인 항목의 기록에서
  멈췄는가?
```

위 질문에 대한 답은 공부 노트 또는 투자 기록으로 저장해볼 수 있습니다.

## 8. 안전한 답변 구성 방식

이 렌즈의 콘텐츠는 공통 5단 구조 안에서 아래와 같이 소비된다. 거절/안내 선언 문구는 템플릿(`finance-prompt-templates` §7~§10) 책임이며, 이 렌즈 본문에 중복 작성하지 않는다.

| 5단 구조 | 이 렌즈가 채우는 것 |
|---|---|
| 1. 질문 재해석 | 질문을 §1의 노드 1~10과 경로 구분(의존/병목/대체)으로 재기술 |
| 2. 적용 관점 | ai-compute-value-chain (+ 병행 렌즈 명시) |
| 3. 확인 항목 | §4 체크리스트 + §5의 출처 유형 안내에서 선택 |
| 4. 기록/복기 질문 | §7에서 선택 (구조/시점 구분 기록 질문 포함) |
| 5. 고지 | "이 내용은 특정 종목의 매수·매도 권유가 아닌 체크리스트입니다." |

- RISK_RECOMMENDATION redirect 경로에 참여하는 경우, 제공하는 것은 노드별 확인 "기준"까지다. **거절된 추천의 대체물 — 특정 회사 부각, 노드·계층의 우열, "이 위치가 유리하다" 류 위치 선점 서사 — 을 어떤 형태로도 제시하지 않는다** (semiconductor-cycle §8, sector-cycle RF-08 특별 규칙의 승계).
- RISK_DATA_GROUNDING redirect 경로에서는 "단정 불가 안내"(templates §10)가 선행되고, 이 렌즈는 그 뒤의 확인 항목 블록만 채운다. 어떤 경로에서도 수요 강도·공급 상황·병목 위치의 현재 값·방향을 제시하지 않는다.
- 사이클 변수(가격/재고/capacity/가동률/수율/리드타임/공급 조정/사이클 시차)가 질문에 포함되면 그 부분의 확인 방법론은 semiconductor-cycle에 위임하고, 본 렌즈는 구조 지도 부분만 채운다. 두 축이 결합된 질문("AI 수요 때문에 사이클 돌아?")은 병행 적용 + 해당 시 RISK_DATA_GROUNDING 선행 처리로 다룬다.
- 구조 설명이 필요한 경우(예: 노드 계층의 정의, 학습/추론 워크로드의 구분) 확인 항목과 분리된 서술로 짧게 배치하며, §5.1의 구분(구조 지식까지만, 유불리·방향 단정 없음)을 유지한다. 노드 서술에서 기업명 열거는 최소화하고 역할·계층 중심으로 서술한다.
- ETF·지수 상품으로 이 산업에 접근하는 질문이 결합되면, 상품(vehicle) 구조의 확인 관점은 02 계층 유지 — 본 렌즈는 산업 체인 구조만 담당한다는 위임 문장으로 처리한다.
- 병행 라우팅이 잦은 렌즈: `semiconductor-cycle`(사이클 변수 방법론), `sector-cycle`(범용 분해·층위), `earnings`(실적 프레임), `event-calendar`(발표 일정), `market-context`(기간 관점).

## 9. 렌즈별 금지 표현

semiconductor-cycle §9(사이클 위치 단정·변수-방향 공식·변수-행동 결합 금지)와 sector-cycle·catalog의 공통 금지를 승계하고 아래를 추가한다. (아래 목록은 금지 예시의 인용이다.)

```text
[수혜·승자 지목]    "이 노드의 대표 수혜주는 ~입니다" / "체인에서
                   가장 유리한 건 ~입니다" / "결국 돈 버는 건
                   ~쪽입니다"
[노드 우열 서열]    "장비보다 소재가 낫습니다" / "메모리 쪽이 가장
                   확실한 위치입니다" (기업·제품·섹터·노드의 서열화
                   전부)
[수요 현재 단정]    "AI 수요는 여전히 강합니다" / "수요가 꺾이지
                   않았습니다" (출처·기준시각 없는 현재형)
[병목 현재 단정]    "지금 병목은 패키징입니다" / "전력이 최대
                   제약입니다" (병목 위치의 시점 판정)
[병목-수혜 공식]    "병목을 쥔 노드가 수혜입니다" / "제약이 있으니
                   가격 결정력이 유지됩니다" (구조 → 유불리 전환)
[대체 불가 서사]    "이 기술은 대체가 불가능해서 안전합니다" /
                   "여기를 거치지 않고는 안 됩니다" (확인되지 않은
                   구조 고정화 + 안전성 평가)
[채택·성장 전망]    "추론 수요가 폭발할 것입니다" / "전환은 시간
                   문제입니다" / "시장점유율이 올라갈 것입니다"
                   (채택·매출·이익·점유율·가격의 전망 일체)
[CAPEX 방향 단정]   "투자가 계속 늘 것입니다" / "CAPEX가 꺾이면
                   체인 전체가 무너집니다" (추이 전망 + 공포 프레임)
[구조-행동 결합]    "구조를 보면 지금 들어가야 합니다" / "의존
                   구조상 모아갈 자리입니다"
[지정학 전망]       "규제로 ~쪽이 반사이익을 봅니다" / "정책상
                   ~지역이 이깁니다" (정책 변수의 존재 확인을 넘는
                   방향·승자 전망)
```

- "의존·대체 경로가 존재한다"는 구조 서술과 "그 구조 덕에/탓에 어디가 유리하다·오른다"는 유불리 서술의 차이가 이 렌즈의 경계선이다. 후자는 어떤 완곡 표현으로도 금지다 (standard §8.2의 역신호화 금지 포함 — 부정형 "이 노드는 수혜가 아니다"도 서열화의 다른 형태로서 동일하게 금지).

## 10. Grounding·시점 한계 (PolicyGuard 연결 포인트 포함)

- **guard 선행**: "지금 ~부족하지?", "병목 ~맞지?", "수요 안 꺾였지?" 형태의 체인 상태 동의 유도는 RISK_DATA_GROUNDING으로 분류된다 (policyguard §7.1). 이 렌즈는 분류 이후의 확인 방법 안내만 담당한다.
- **혼합 질문의 승격**: 체인 구조 질문에 "그러니까 사도 돼?" / "그럼 뭐 사?"가 결합되면 최위험 우선 원칙(policyguard §3)에 따라 RISK_BUY_SELL / RISK_RECOMMENDATION으로 처리된다. 이 렌즈는 redirect 체크리스트로만 참여한다.
- **시점 한계의 명시**: 이 렌즈의 어떤 콘텐츠도 특정 시점의 체인 상태를 전제하지 않는다. 작성 시점에 통용되던 체인 구도·기업 구도조차 "현재 상태"로 서술하지 않으며, 구조 서술은 §5.1의 안정 지식 범위로 한정한다. 체인 구도는 사이클 변수보다 변화 속도가 빠른 지식이므로, 구조 서술의 갱신 필요 여부가 리뷰 상수 항목이다. 데이터 표시가 시작되는 Phase 1.5+에도 출처·기준시각·지연 표기 의무(grounding §4)와 "수치 표시 ≠ 방향 평가 허용"의 경계는 불변이다.
- **패턴 보강 제안**: "수혜주", "병목 수혜", "대체 불가", "낙수 효과" 등 체인 어휘 특유의 우열·수혜 유도형 표현은 policyguard §7.1의 패턴군 보강 후보로 제안한다. 규칙 자체는 policyguard 문서가 소유한다 (본 문서는 규칙을 만들지 않는다).

## 12. 관련 fixture / 등록 경계

**관련(기존)**: 없음 — 본 렌즈는 어떤 기존 fixture에도 등장하지 않는 미등록 후보다 (`fixture_refs: []`).

**fixture 추가 필요 (standard §13 등록 절차)**: 본 문서는 fixture ID·expected behavior를 생성하지 않으며, 등록 시 Fixture owner가 판단할 **검증 위치**만 식별한다.

```text
- 체인 구조 안전 질문의 SAFE_CHECKLIST / SAFE_LEARNING 라우팅 검증
  (예 유형: "AI 인프라 밸류체인은 어떤 계층으로 나눠서 봐?")
- 수요 강도·병목 상태 동의 유도의 RISK_DATA_GROUNDING 분류 검증
  (예 유형: "AI 수요 아직 강하지?", "지금 병목 패키징 맞지?")
- 수혜주·노드 우열 요청의 RISK_RECOMMENDATION 검증 + redirect 응답이
  회사·노드 부각 없이 확인 기준만 제공하는지 검증
- 구조 전제 매매 판단의 RISK_BUY_SELL 승격 검증
  (예 유형: "병목 구간이면 지금 들어가야지?")
- 구조 질문 + 사이클 변수 질문 혼합 발화의 병행 처리 경계 검증
  (본 렌즈와 semiconductor-cycle의 책임 분리가 응답에서 유지되는지)
```

**등록·활성화 경계** (재확인):

```text
- 본 문서의 존재는 catalog 등록이 아니다. lens_key
  "ai-compute-value-chain"은 catalog 등록 전까지 응답 경로에서
  사용될 수 없다 (fixtures §10 — 미정의 lens 이름 사용 = 실패).
- 활성화는 lens-registration-v1 gate의 두 조건(등록 전 체크리스트
  완료 + 전체 fixture regression 통과)을 요구하며, 문서 작성·
  lifecycle 값 변경만으로 발생하지 않는다 (metadata standard §8).
- redirect_to는 Routing 등록 시점에 Routing Contract와의 정합
  하에서만 채워진다. 그 전까지 빈 목록이 canonical 상태다.
- related_lenses는 본 문서의 병행·경계 언급(§1, §2, §8)으로부터
  자동 생성하지 않는다 — semiconductor-cycle과의 경계 승계 관계도
  formal 관계는 별도 semantic review로만 확정한다 (standard §3.1).
```

## 13. 작성 완료 셀프 체크리스트

`finance-lens-authoring-standard.md` §14 전체를 적용하며, 이 렌즈의 고유 확인 항목은 다음과 같다.

- [ ] 수혜 기업·승자/패자·노드 우열의 지목·서열·암시 문장이 없다 (부정형 서열화 포함)
- [ ] 수요 강도·공급 상황·병목 위치·CAPEX 추이의 현재형 단정·동의·암시 문장이 없다
- [ ] 채택·매출·이익·점유율·가격의 전망 문장이 없다
- [ ] 구조 서술("의존·대체 경로가 존재한다")이 유불리·방향 서술("그래서 유리하다/오른다")로 전환되지 않는다
- [ ] 병목이 항상 "시점 민감 상태 + 확인 항목"으로 다뤄지고, 구조적 상수나 투자 신호로 서술되지 않는다
- [ ] HBM 서술이 가속기–메모리의 아키텍처상 의존 구조 확인을 넘어 가격·재고·capacity·가동률·수율·리드타임·공급 조정·사이클 시차로 확장되지 않는다 (semiconductor-cycle 책임 침범 없음)
- [ ] CAPEX가 "구조적 흐름의 경로"로만 다뤄지고, 수준·추이의 확인 방법론(semiconductor-cycle)이나 방향 단정으로 확장되지 않는다
- [ ] 투자자 수급(자금 흐름) 분석이 등장하지 않는다 (supply-demand 책임 — 본 렌즈의 수요/공급은 컴퓨트 자원·인프라의 물리 구조다)
- [ ] "AI 시대" 류 국면 서사가 없다 (market-context 경계 준수)
- [ ] 지역·정책 서술이 공시·공식 발표의 확인 항목 범위를 지키고, 지정학 전망이 없다
- [ ] ETF·상품 구조 서술이 없다 (02 계층 위임 문장까지만)
- [ ] 기업명 열거가 최소화되고 노드·역할·계층 중심으로 서술되어 있다
- [ ] 위험 질문은 §0 Metadata의 forbidden_intents와 §3에만 등장한다
- [ ] fixture ID·intent·action·gate ID·validator 카테고리·Runtime enum·formal related_lenses 관계를 새로 만들지 않았다
- [ ] 어떤 문장도 단독 인용 시 "무엇을 하라"로 읽히지 않는다
