## 1. 렌즈 목적

**외부에서 공표되는 미래 실적 기대치(추정치)의 "변화"에 대한 질문을 "비교 가능성의 확인 → 변화의 서술 → 표본의 확인 → 기록"으로 구조화한다.**

```text
구분 1. 비교 가능성  — 이전 스냅샷과 현재 스냅샷이 같은 지표·같은
                      회계기간·같은 산출 기준·같은 집계 방식·같은
                      출처·명시된 두 기준시각 위에서 비교되고 있는가
구분 2. 변화의 서술  — 상향/하향/불변의 방향과 변화의 크기를
                      "서술적 변화"로만 구분해 기록 (시장 신호로
                      전환하지 않는다)
구분 3. 표본의 확인  — 하나의 추정이 바뀐 것인가, 여럿이 바뀐
                      것인가, 집계 평균이 바뀐 것인가, 분포가
                      넓어지거나 좁아진 것인가, 표본 구성 자체가
                      바뀐 것인가
구분 4. 기록        — 확인한 스냅샷의 출처·기준시각·집계 범위와,
                      확인하지 못한 항목의 기록
```

- **수준(level)과 변화(revision)는 다르다.** 추정치가 높거나 낮다는 것은 그 자체로 revision이 아니다. revision은 **비교 가능한 이전 스냅샷과 현재 스냅샷 사이의 변화**다. 이 구분이 본 렌즈의 출발점이다.
- 본 렌즈는 `earnings`의 "기대" 축의 **변화** 차원을 심화한다. 변화의 확인과 변화의 방향 전망은 다르며, 후자는 어떤 완곡 표현으로도 금지다.
- 본 렌즈는 방향·폭·확산(breadth)·분산(dispersion)을 **읽는 방법**까지만 소유한다. 현재 어느 종목의 추정치가 어떻게 변했는지의 사실 제시, 변화가 강한 종목의 목록, 변화의 가격 함의는 어떤 경로에서도 산출물이 아니다.

## 2. 이 렌즈가 다루는 질문

| 안전 질문 예시 | 병행 렌즈 | 근거 |
|---|---|---|
| "추정치가 바뀌었는지는 뭘 비교해서 확인해?" | earnings | 확인 방법 요청 — 스냅샷 비교 가능성(구분 1) |
| "컨센서스 평균이 변했다는 건 애널리스트들이 다 바꿨다는 뜻이야?" | (개념: SAFE_LEARNING) | 집계 변화와 표본 효과의 개념 구분 요청 (구분 3) |
| "리비전의 폭이랑 방향은 뭐가 달라?" | (개념: SAFE_LEARNING) | 개념 질문. 이 렌즈는 방법론 관점 연결로 참여 |
| "추정치 기록을 남길 때 뭘 같이 적어야 해?" | journal-review | 기록 항목 요청 (구분 4) |

- 개념 정의("리비전이 뭐야?")는 SAFE_LEARNING 소비 대상이며, 이 렌즈는 정의 이후의 확인 관점 연결로만 참여한다. 정의가 "그래서 지금 어떤 종목의 리비전이 좋은가"로 확장되는 순간 §3의 위험 경로다.

## 3. 이 렌즈가 다루지 않는 질문

이 렌즈는 **현재 추정치·수정 현황·수정 기반 선별의 목적지가 아니다.** 아래 질문은 Input Guard가 먼저 분류하고, 거절/안내 선언 이후에만 이 렌즈의 확인 방법이 제공될 수 있다.

| 질문 | intent | 처리 |
|---|---|---|
| "요즘 이 종목 추정치 올라가고 있지?" / "컨센서스 얼마야?" | RISK_DATA_GROUNDING | 현재 수치·방향 단정 금지 — 단정 불가 안내 후 확인 방법만 |
| "추정치 상향 중인 종목 알려줘" / "리비전 좋은 섹터가 어디야?" | RISK_RECOMMENDATION | 수정 기반 종목·업종 선별 요청 — 목록·랭킹·스크린 제시 불가 |
| "추정치 올랐으니 지금 사도 되지?" | RISK_BUY_SELL | 변화를 매매 신호로 전제한 동의 요청 — 전제에 동의하지 않는다 |
| "추정치 반영하면 목표가 얼마야?" | RISK_TARGET_PRICE | 수정치의 가격 환산 요청 — 어떤 수치·범위도 제시 불가 |
| "추정치 깎였는데 비중 줄일까?" | RISK_POSITION_SIZE | 수정-비중 결합 요청 |
| "내 보유 종목 추정치 깎였는데 팔아?" | RISK_ACCOUNT_BASED_ADVICE | 도메인 근거가 붙어도 계좌 기반 행동 지시는 동일 경계 |

## 4. 판단 전 체크리스트

```text
- 내가 "추정치가 변했다"고 말할 때, 비교한 이전 스냅샷과 현재
  스냅샷의 두 기준시각을 각각 확인했는가?
- 두 스냅샷은 같은 지표, 같은 회계기간(분기/회계연도/역년/
  선행·후행), 같은 산출 기준(보고/조정/회사 정의), 같은 집계
  방식, 같은 출처, 같은 기여자 범위 위에서 비교되고 있는가?
  어긋난 항목이 있다면 무엇인가?
- 나는 추정치의 "수준"을 본 것인가, "변화"를 본 것인가?
  둘을 구분해서 적을 수 있는가?
- 집계값의 변화라면, 그 변화가 개별 추정의 갱신에서 온 것인지,
  기여자 수·포함 대상·추정 나이·이상치 처리·결측 처리 같은
  표본 구성의 변화에서 온 것인지 확인할 방법을 알고 있는가?
- 내가 본 추정들 중 오래된 추정이 섞여 있는지, 그 신선도를
  어떤 기준(관련 이벤트·회계기간·출처의 공표 구조·비교 목적)
  으로 볼지 정했는가?
- 회사 가이던스, 회사가 공시한 확정 실적, 외부 집계 추정,
  개별 애널리스트 추정, 나의 가정을 각각 구분해서 확인했는가?
- 이 지표의 수정과 다른 지표(매출/이익률/EPS/CAPEX 등)의
  수정이 서로 다른 변화라는 점을 전제로 확인 항목을 나눴는가?
```

## 5. 확인할 데이터

Phase 1에는 추정치·수정 데이터가 연결되어 있지 않다. 상세 추정 데이터는 라이선스 대상이거나, 지연되거나, 불완전하거나, 제공처별로 집계 방식이 다를 수 있으며, Runtime이 보유하지 않는다는 전제를 유지한다. 아래는 **사용자가 직접 확인할 항목과 출처 유형**이며, 이 렌즈가 현재 추정치·수정 이력·컨센서스 값·기여자 수·확산·분산·랭킹을 제시하지 않는다. 데이터가 없을 때 이 렌즈가 제공하는 것은 **검증 방법론까지**다.

| 확인 항목 | 확인 방법 (출처 유형) | 유의 |
|---|---|---|
| 추정 집계의 산출 방식 | 집계를 제공하는 곳의 산출 방식·포함 기준 설명 | 같은 이름의 "컨센서스"도 집계 방식·이상치 처리·결측 처리에 따라 값이 다르다 |
| 기여 추정의 수와 구성 | 집계 제공처가 함께 공표하는 표본 정보의 유무 확인 | 집계값 변화가 표본 구성 변화에서 올 수 있다 — 전원 갱신을 뜻하지 않는다 |
| 개별 추정 vs 집계 | 개별 추정 자료와 집계 자료의 구분 확인 | 하나의 갱신과 여럿의 갱신, 평균의 변화, 분포의 확대·축소는 각각 다른 관찰이다 |
| 추정의 생성 시점 | 각 추정·집계에 표기된 작성/갱신 시점 확인 | 추정이 만들어진 시점, 추정의 대상 기간, 집계가 공표된 시점, 내가 조회한 시점은 서로 다른 네 개의 시각이다 |
| 지표 정의의 일관성 | 보고 지표 / 조정 지표 / 회사 정의 지표의 구분 표기 확인 | 스냅샷 간 지표 정의가 바뀌면 그 차이는 revision이 아니다 |
| 회계기간 정렬 | 각 추정이 어느 분기·회계연도·역년·선행/후행 기간 대상인지 확인 | 기간이 다른 시리즈를 하나의 수정 이력처럼 잇지 않는다 |
| 회사 가이던스 | 회사가 공식 발표한 전망 자료의 유무와 원문 | 가이던스는 컨센서스가 아니고, 보장된 미래 결과도 아니다 — 주체를 구분해 기록 |
| 공시 실적 원문 | 공시된 사업보고서/분기보고서 | 확정 실적과 외부 추정을 같은 축에 놓지 않기 위한 기준 자료 |
| 데이터의 출처와 기준시각 | 어느 출처의, 언제 기준 자료인지 항상 함께 확인 | 상수 항목 |

- **현재 상태 결론의 최소 요건**: 특정 추정치·수정에 대한 현재형 서술이 성립하려면 출처, 지표 정의, 회계기간, 산출 기준, 기준시각, 비교시각, 집계 범위가 전부 갖춰져야 한다. 이 필드들 없이 현재 상태 결론을 만들지 않는다.
- 오래된 추정의 신선도에 **하나의 보편 기준치를 만들지 않는다.** 신선도는 관련 이벤트, 회계기간, 출처, 공표 구조, 비교 목적에 따라 달라지는 확인 대상이다.

## 6. 오해하기 쉬운 패턴

### 패턴 1. 수준과 변화의 혼동

```text
[패턴]      추정치가 높다/낮다는 "수준"의 인상을 추정치가
            올랐다/내렸다는 "변화"로 바꿔 읽는 해석.
[놓치는 것]  변화는 비교 가능한 두 스냅샷 사이에서만 성립한다는
            점. 이전 스냅샷의 확인 없이 수준만으로는 변화를
            말할 수 없다는 점.
[확인 질문]  나는 두 개의 스냅샷을 실제로 비교했는가, 하나의
            수준에서 변화를 추측했는가?
[기록 질문]  내가 비교한 이전/현재 스냅샷의 기준시각을 각각
            기록한다면?
```

### 패턴 2. 서로 다른 시리즈의 이어붙이기

```text
[패턴]      지표·회계기간·산출 기준·집계 방식·출처가 다른
            숫자들을 하나의 수정 이력처럼 이어서 읽는 해석.
[놓치는 것]  정렬되지 않은 비교에서 나타난 차이는 revision이
            아니라 정의 차이일 수 있다는 점.
[확인 질문]  두 숫자의 지표 정의, 대상 기간, 산출 기준, 집계
            방식, 출처, 기여자 범위가 일치하는지 항목별로
            확인했는가?
[기록 질문]  기록에 수정을 남길 때 정렬 항목 중 확인한 것과
            확인하지 못한 것을 나눠 적는다면?
```

## 8. 안전한 답변 구성 방식

이 렌즈의 콘텐츠는 공통 5단 구조 안에서 아래와 같이 소비된다. 거절/안내 선언 문구는 템플릿 책임이며, 이 렌즈 본문에 중복 작성하지 않는다.

| 5단 구조 | 이 렌즈가 채우는 것 |
|---|---|
| 1. 질문 재해석 | 질문을 §1의 구분 1~4(비교 가능성/변화 서술/표본/기록)로 재기술 |
| 2. 적용 관점 | earnings-revision (+ 병행 렌즈 명시) |
| 3. 확인 항목 | §4 체크리스트 + §5의 출처 유형·정렬 항목 안내에서 선택 |
| 4. 기록/복기 질문 | §7에서 선택 (스냅샷 전/후 나란히 기록 질문 포함) |
| 5. 고지 | "이 내용은 특정 종목의 매수·매도 권유가 아닌 체크리스트입니다." |

- **데이터 부재 경로의 규칙**: 현재 추정·수정에 대한 사실 확인 질문이 RISK_DATA_GROUNDING으로 분류된 경우, 단정 불가 안내가 선행되고 이 렌즈는 §5의 **검증 방법론 블록만** 채운다. 어떤 경로에서도 현재 추정치, 수정 이력, 컨센서스 값, 기여자 수, 확산·분산 값, 랭킹을 만들어내지 않는다. 이 렌즈가 자체적으로 실적 전망을 생성하지도 않는다.
- **밸류에이션 전환 금지**: 수정된 추정치를 목표가, 적정가, 기대수익률, 밸류에이션 결론으로 변환하지 않는다. 추정치가 지표에 반영되는 경로는 `valuation`과의 접점 언급까지만 한다.
- **사이클 판정 금지**: 실적 추정 변화만으로 사이클 국면을 추론하지 않는다. 일반 업황 해석은 `sector-cycle` 소유이며, 이 렌즈는 "추정 변화의 확인 ≠ 사이클 위치 판정"의 경계만 유지한다.
- **일정 프레임 위임**: 스냅샷 비교에 기준시각이 필수라는 요구까지가 이 렌즈의 몫이고, 실적 발표일·가이던스 발표일·보고 캘린더의 일반 확인 프레임은 `event-calendar` 소유다. 그 프레임을 여기에 재서술하지 않는다.
- 병행 라우팅이 잦은 렌즈: `earnings`(다음 발표에 대한 기대의 존재·반영 확인), `valuation`(추정의 지표 반영 접점), `sector-cycle`(분해 항목으로서의 추정 변화), `event-calendar`(일정 확인 프레임).

## 9. 렌즈별 금지 표현

**이 렌즈의 최대 위험은 "리비전 상향 = 매수 신호"의 신호화다.** 아래 표현이 제공/지시/추천/예측 맥락으로 나타나면 반려한다. (아래 목록은 금지 예시의 인용이다.)

```text
[신호화]         "추정치 상향은 매수 신호입니다" / "하향 리비전이니
                 피하세요" / "확산이 넓어졌으니 방향이 잡혔습니다"
                 (방향·폭·확산·분산의 시장 신호 전환 일체)
[현재 수치 제시]  "현재 컨센서스는 ~입니다" / "최근 한 달간 추정치가
                 ~% 상향됐습니다" / "기여 애널리스트는 ~명입니다"
                 (현재 추정치·수정 이력·기여자 수·확산·분산 값의 생성)
[랭킹·스크린]    "리비전이 가장 강한 종목/섹터는 ~입니다" /
                 "상향 종목 목록을 뽑아드리면" (수정 기반 선별물 일체 —
                 회사/섹터/산업/시장 랭킹 포함)
[모멘텀 단정]    "지금 이 종목은 리비전 모멘텀이 좋습니다"
                 (출처 있는 현재 데이터 없는 현재형 단정)
[가격 예측 등치]  "상향이 이어지면 주가도 오릅니다" / "가격이 안
                 움직였으니 이번 수정은 의미 없습니다"
[밸류에이션 전환] "수정치를 반영하면 목표가/적정가/기대수익률은 ~"
                 (수정치의 가격·가치 환산 일체)
[사이클 판정]    "추정치가 돌았으니 업황 바닥입니다"
[전략 프레이밍]   "리비전 트레이딩 전략" / "실적 이벤트 전후 매매
                 전략을 추천합니다"
[자체 전망 생성]  "제 계산으로는 다음 분기 EPS가 ~로 예상됩니다"
                 (렌즈가 만든 실적 전망)
[제공처 권위화]   "~사의 컨센서스가 표준이니 그것만 보면 됩니다"
                 (특정 상용 제공처의 보편 권위 단정)
```

- "수정을 어떻게 확인할 것인가"라는 방법 안내와 "수정이 이렇다/그래서 이렇게 된다"는 사실·방향 결론의 차이가 이 렌즈의 경계선이다. 후자는 어떤 완곡 표현·면책 결합으로도 금지다.
- 지표별 분해(매출/매출총이익률/영업이익률/영업이익/EPS/CAPEX)의 수정은 서로 다른 변화를 나타낸다는 설명까지가 허용선이며, **어느 지표가 지금 가장 중요한지의 서열화는 하지 않는다.**

## 10. Grounding·PolicyGuard 연결 포인트

- **guard 선행**: "요즘 추정치 올라가고 있지?", "컨센서스 얼마야?", "리비전 모멘텀 좋지?"처럼 현재 수정 상태의 사실·평가 확인을 요구하는 질문은 RISK_DATA_GROUNDING으로 분류된다. 이 렌즈는 분류 이후의 검증 방법론 안내만 담당하며, 렌즈가 위험 질문을 직접 판별·처리한다는 서술을 두지 않는다.
- **grounding 최소 필드**: 현재 추정·수정에 대한 어떤 현재형 서술도 출처, 지표 정의, 회계기간, 산출 기준, 기준시각, 비교시각, 집계 범위가 전부 갖춰졌을 때만 성립한다. 이 필드가 없으면 현재 상태 결론을 만들지 않으며, 값·이력·기여자 수·확산·분산·랭킹을 어떤 경우에도 창작하지 않는다. 현재 추정 수준, 수정, 기여자 수, 확산, 분산, 랭킹은 전부 시간 민감 검증 대상으로 취급한다.
- **선별 요청의 분류**: "상향 중인 종목 알려줘", "리비전 좋은 섹터"는 종목명이 없어도 RISK_RECOMMENDATION이다. 수정이라는 근거가 붙어도 선별 요청의 분류를 완화하지 않는다.
- **판단 결합형의 분류**: "올랐으니 사도 되지?"는 RISK_BUY_SELL, "반영하면 얼마까지 가?"는 RISK_TARGET_PRICE, "깎였는데 줄일까?"는 RISK_POSITION_SIZE, "내 보유분 깎였는데 팔아?"는 RISK_ACCOUNT_BASED_ADVICE다. 이 렌즈는 어떤 경로에서도 전제(수정의 방향 평가)에 동의하지 않은 채 확인 방법으로만 참여한다.
- **패턴 보강 제안**: "리비전 상향/하향", "추정치 모멘텀", "상향 종목", "컨센서스 돌았다" 등 수정 어휘와 판단 요청의 결합 표현은 기존 위험 패턴군의 **보강 후보로 owner에게 제안**만 한다. 규칙 신설·개정의 소유권은 PolicyGuard 문서에 있으며, 본 렌즈 문서가 새 PolicyGuard 규칙을 만들지 않는다.

## 11. Output Validator 체크포인트

본 절은 기존 일반 안전 검사 카테고리에 대한 매핑이며, 새 Validator 카테고리를 만들지 않는다.

| 이 문서의 요소 | validator 검사 (기존 일반 검사) | 확인 사항 |
|---|---|---|
| §4 체크리스트 | forbidden trading action | 수정-행동 결합·조건-행동 공식 문장 없음 |
| §5 확인할 데이터 | unsupported market data claim | 현재 추정치·수정 이력·기여자 수·확산·분산·랭킹 수치 제시 없음, 출처/기준시각/정렬 항목 포함 |
| §6 오해 패턴 | forbidden trading action / performance guarantee | 역신호화 없음 — 특히 패턴 5가 "가격 반응 전 상향이면 기회"로, 패턴 3이 "전원 갱신이 확인되면 신호"로 뒤집히지 않음 |
| §7 일지 질문 | unsafe journal review conclusion | 전부 질문형, 스냅샷 기록 유도가 행동 결론으로 끝나지 않음 |
| §9 금지 표현 | 기존 검사 카테고리에 대한 확장 후보 | "신호화/랭킹·스크린/밸류에이션 전환/자체 전망 생성" 표현군의 반영 필요 여부는 **owner 리뷰 제안으로만** 표기 — 본 문서 단독으로 검사 규칙이 생기지 않는다 |

## 12. 관련 fixture / 등록 경계

**관련(기존)**: 없음. 본 렌즈의 `fixture_refs`는 빈 목록이며, 존재하지 않는 fixture ID를 참조하지 않는다.

**fixture ID 비창작 원칙**: 본 문서는 신규 fixture ID를 만들지 않는다. 등록 절차에서 필요한 검증 범위는 아래처럼 **성격으로만** 기술하고, 케이스 정의와 ID 부여는 fixture 문서 소유의 별도 작업으로 남긴다.

- 안전 케이스: 수정 확인 "방법" 질문이 안전 경로로 라우팅되고 응답에 수치·랭킹이 없는지
- 위험 케이스: 현재 수정 상태 단정 유도, 수정 기반 선별, 수정-매매/목표가/비중/계좌 결합 질문이 각각 §3의 intent로 분류되는지
- 우회 케이스: "참고로만", "예시로만" 등 면책 결합형이 현재 수치·랭킹 제공으로 새지 않는지

**등록 경계** (candidate authoring ≠ 등록/활성화):

- lens_key `earnings-revision`은 catalog 미등록 상태이며, 등록 절차 완료 전에는 **미존재로 취급**된다. per-lens 문서를 먼저 쓰더라도 라우팅에 포함할 수 없다.
- 본 문서의 metadata는 `lifecycle_status: draft`, `routable: false`, `runtime_loadable: false`다. 비active 문서의 routable 포함은 activation 차단 사유이며, 응답 경로에서 이 렌즈 이름을 사용하는 것 자체가 regression 실패다.
- `activation_gate: lens-registration-v1`은 신규 렌즈 등록 전 체크리스트 완료와 routing fixture 전체 regression 통과의 결합을 뜻하는 gate identifier의 기재다. 통과 여부는 문서 metadata에 기록하지 않는다.
- redirect 편입, related_lenses의 formal 관계 확정, fixture 추가는 각각 routing/catalog/fixture 소유의 별도 결정이며, 본 문서는 어떤 것도 선점하지 않는다.

## 13. 작성 완료 셀프 체크리스트

`finance-lens-authoring-standard.md` §14 전체를 적용하며, 이 렌즈의 고유 확인 항목은 다음과 같다.

- [ ] 수준(level)과 변화(revision)의 구분이 모든 섹션에서 유지된다
- [ ] 방향·폭·확산·분산이 전부 "서술적 변화의 확인"으로만 다뤄지고, 시장 신호·가격 예측으로 전환되는 문장이 없다
- [ ] 현재 추정치, 수정 이력, 컨센서스 값, 기여자 수, 확산·분산 값, 랭킹, 스크린, 자체 실적 전망이 어디에도 없다
- [ ] 스냅샷 비교의 정렬 항목(지표/기간/산출 기준/집계 방식/출처/두 기준시각/기여자 범위)이 확인 항목으로 일관되게 존재한다
- [ ] 집계 변화가 전원 견해 변화로 서술되는 문장이 없고, 표본 효과가 확인 대상으로 유지된다
- [ ] 오래된 추정에 보편 신선도 기준치를 창작하지 않았다
- [ ] 가이던스/확정 실적/외부 집계/개별 추정/사용자 가정의 구분이 유지되고, 가이던스를 컨센서스나 보장된 결과로 취급하는 문장이 없다
- [ ] 수정치의 목표가·적정가·기대수익률·밸류에이션 결론 전환이 없다 (valuation 위임 준수)
- [ ] 수정만으로 사이클 국면을 추론하는 문장이 없다 (sector-cycle 위임 준수)
- [ ] 일반 이벤트 캘린더 프레임을 재서술하지 않았다 (event-calendar 위임 준수)
- [ ] 지표별 수정의 구분 설명이 "지금 가장 중요한 지표"의 서열화로 확장되지 않는다
- [ ] 특정 상용 데이터 제공처를 보편 권위로 단정하는 문장이 없다
- [ ] fixture ID·intent·action·gate·Validator 카테고리·Runtime enum·formal related_lenses·제공처 스키마를 새로 만들지 않았고, 패턴 보강은 owner 제안으로만 표기했다
- [ ] 위험 질문은 §0 forbidden_intents와 §3에만 등장한다
- [ ] 어떤 문장도 단독 인용 시 "무엇을 하라"로 읽히지 않는다
