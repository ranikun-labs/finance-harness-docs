## 1. 렌즈 목적

**한국 주식시장 관련 질문을 "이 데이터·이벤트가 어떤 제도 하에서, 어디서, 어떤 한계와 함께 공표되는가"의 확인 체계로 구조화한다.**

이 렌즈는 03-domain-deep-dive의 **국가·시장 구조 축(축 A)** 렌즈다. 계층 경계를 먼저 고정한다:

```text
- supply-demand        는 수급의 해석 프레임(주체/시장/기간/성격 구분,
                       오해 패턴)을 소유한다. 본 렌즈는 그 프레임에
                       추가하지 않으며, "한국에서 그 데이터가 어떤
                       제도로, 언제, 어떤 한계와 함께 공표되는가"의
                       확인처만 소유한다.
- event-calendar       는 시점성 이벤트의 일반 확인 프레임을 소유한다.
                       본 렌즈는 한국 고유 제도 캘린더(편출입 정기 변경,
                       파생 만기 규칙, 휴장)의 "확인처"만 추가한다.
- macro-rate-fx        는 환율·금리 변수의 해석 프레임을 소유한다.
                       본 렌즈의 환율 취급은 "한국 시장 참여자가 노출을
                       확인할 변수라는 사실"과 그 확인 항목까지이며,
                       환율의 방향·영향 해석에 참여하지 않는다.
- earnings             는 실적의 해석 프레임을 소유한다. 본 렌즈는
                       한국 공시 제도(정기·수시 공시, 기업행위 공시)의
                       확인처만 추가한다.
- etf-index-structure  (별도 후보)는 ETF·지수 상품의 메커니즘(추적,
                       괴리, 편출입의 상품 측 처리)을 소유할 예정이다.
                       본 렌즈는 "지수 제도와 패시브 자금이 존재한다는
                       제도적 맥락"까지만 다루고 상품 메커니즘을
                       중복 서술하지 않는다.
- market-context       는 국면·좌표 프레임을 소유한다. 본 렌즈는
                       시장 논평·국면에 참여하지 않는다.
```

분석 모델 (한국 시장 구조의 확인 구분):

```text
구분 1. 수급 공표 제도   — 투자자별 매매 공표 체계, 잠정/확정 집계의
                         구분, 현물/파생/프로그램 매매 공표의 분리
구분 2. 공시·기업행위 제도 — 정기·수시 공시 체계, 실적 공시, 배당·
                         증자·액면분할 등 기업행위의 공시와 기준일
                         체계의 확인
구분 3. 지수·패시브 제도  — 지수 산출 방법론 문서, 정기 변경(편출입)
                         일정의 확인처, 패시브·ETF 자금이 제도적으로
                         연결되는 경로의 존재 확인
구분 4. 매매·결제 제도   — 거래 세션 구조, 휴장일 확인처, 결제 주기,
                         KOSPI/KOSDAQ의 제도적 구분(상장 요건·소속
                         지수 체계가 다른 별개 시장이라는 사실)
구분 5. 공매도·대차와 노출 변수 — 공매도·대차잔고 공시의 확인처와
                         시차·범위 한계, 환율이 노출 변수로 존재한다는
                         사실의 확인
```

- 이 렌즈는 제도를 **암기된 사실로 단정하지 않는다.** 제도는 개정되는 지식이므로, 모든 확인 항목은 "규정 원문·공식 공표처에서 현행 여부를 확인"하는 문형을 기본으로 하며, "개정 여부 확인"이 상수 항목이다.
- 이 렌즈는 제도 사실로부터 시장 영향을 **연결하지 않는다.** "편출입 일정이 공표되어 있다"는 확인과 "그래서 수급이 어떻게 된다"는 단정은 다르며, 후자는 이 렌즈의 어떤 문장에도 없다.

## 3. 이 렌즈가 다루지 않는 질문

**"제도"라는 소재가 intent 분류를 완화하지 않는다.** 제도 질문의 형태를 하고 있어도 현재 수급·인과·행동 판단을 요구하면 아래 경로로 처리되며, Input Guard가 렌즈보다 먼저 분류한다.

| 질문 | intent | 처리 |
|---|---|---|
| "지금 외국인이 사고 있지?" | RISK_DATA_GROUNDING | DG-01 계열 — 단정 불가 안내 선행. 이 렌즈는 공표 제도의 확인처 블록으로만 참여 |
| "공매도 때문에 빠지는 거 맞지?" | RISK_DATA_GROUNDING | 인과 단정 금지 (DG-05와 동일 구조) — 잔고 공시의 확인 방법 안내까지만 |
| "만기일이라 오늘 흔들리는 거지?" | RISK_DATA_GROUNDING | 달력 사실(만기 여부)의 확인과 시장 영향 단정은 다르다 (grounding §3 조건부 원칙) |
| "편입 발표됐으니 사야지?" | RISK_BUY_SELL | REDIRECT_TO_CHECKLIST — 제도 이벤트를 전제로 한 매매 판단 요청 |
| "배당락 전에 사둘까?" | RISK_BUY_SELL | 동일 — 기준일 제도가 시점 선택 판단을 정당화하지 않는다 |
| "공매도 많이 쌓인 종목 알려줘" | RISK_RECOMMENDATION | REFUSE_AND_REDIRECT — 제도 데이터 기반 종목 선별도 종목 추천이다 |
| "환율 오르면 외국인 나가는 거 아니야?" | RISK_DATA_GROUNDING | 환율-수급 인과의 단정 유도 — 노출 변수의 확인 항목으로 전환 (해석은 macro-rate-fx 프레임도 하지 않는 영역) |

## 4. 판단 전 체크리스트

```text
- 내가 보려는 수급 데이터가 어느 공표 체계의 것인지 확인했는가?
  (투자자별 매매 / 프로그램 매매 / 파생 — 각각 별도로 공표된다)
- 그 데이터가 잠정 집계인지 확정 집계인지, 각각 언제 공표되는지를
  공표처 기준으로 확인했는가?
- 지수 관련 확인이라면, 해당 지수의 산출 방법론 문서와 정기 변경
  일정을 지수 산출 기관의 공표 자료에서 확인했는가?
- 공매도·대차잔고를 본다면, 그 공시의 공표 주기와 시차, 집계
  범위의 한계를 확인했는가? (모든 포지션이 실시간으로 보이는
  체계가 아니다 — 무엇이 공시되고 무엇이 공시되지 않는지 확인)
- 기업행위(배당/증자/분할 등)를 본다면, 공시 원문에서 기준일·
  일정·조건을 확인했는가? (요약 전달이 아니라 공시 원문 기준)
- 거래 세션·휴장·결제 주기가 관련된 질문이라면, 거래소가 공표하는
  현행 규정·일정에서 확인했는가?
- KOSPI/KOSDAQ 구분이 관련된다면, 두 시장의 제도적 차이(상장 요건,
  소속 지수 체계)를 "성격 평가" 없이 제도 문서 기준으로 확인했는가?
- 환율 노출이 관련된다면, "이 종목/자금 흐름에 환율 노출이
  존재하는가"의 확인 항목까지만 적었는가? (방향·영향 해석은 별개)
- 내가 전제한 제도 지식이 현행인지 — 개정 여부를 공표처에서
  확인했는가? (상수 항목: 제도는 바뀐다)
```

## 5. 확인할 데이터

Phase 1에는 데이터가 연결되어 있지 않으므로, 아래는 **사용자가 직접 확인할 항목과 출처 유형**이다. 이 렌즈는 특정 상용 서비스명을 나열하지 않으며(standard §4.2), 어떤 제도 항목의 현행 세부 내용(수치·비율·기한)도 본문에 고정하지 않는다 — 세부는 항상 규정 원문 확인 대상이다.

| 확인 항목 | 확인 방법 (출처 유형) | 유의 |
|---|---|---|
| 투자자별 매매 동향의 공표 체계 | 거래소의 투자자별 매매 공표 자료 | 잠정/확정 구분과 각 공표 시점 확인 (supply-demand §5의 잠정치 유의와 동일 계열 — 본 렌즈는 그 구분이 제도상 어디서 갈리는지의 확인처) |
| 프로그램 매매 공표 | 거래소의 프로그램 매매 공표 자료 | 차익/비차익 구분의 공표 여부 확인. 투자자별 매매와 별도 체계임을 확인 |
| 파생(선물·옵션) 주체별 동향 | 파생 시장의 공표 자료 | 현물 공표 체계와 분리 확인 (혼합 해석의 경계는 supply-demand 패턴 4) |
| 지수 산출 방법론 | 지수 산출 기관의 방법론 문서 | 편입·편출 기준, 정기 변경 주기의 "문서상 확인" — 기억이 아니라 현행 문서 기준 |
| 지수 정기 변경 일정 | 지수 산출 기관·거래소의 공표 일정 | 공표된 일정 사실의 확인까지 — 변경에 따른 수급 영향의 단정은 금지 (grounding §3 조건부 원칙) |
| 공매도 잔고·대차 공시 | 공매도 관련 공시 체계의 공표 자료 | 공표 주기·시차·집계 범위의 한계를 함께 확인. 공시된 잔고 = 전체 포지션이 아님을 확인 |
| 정기·수시 공시 | 공시 시스템의 원문 | 요약·전언이 아닌 원문 확인 (earnings §5와 동일 기준) |
| 기업행위 일정 (배당/증자/분할 등) | 공시 원문의 기준일·일정 항목 | 기준일 체계는 결제 주기와 연결되므로 함께 확인 |
| 거래 세션·휴장일 | 거래소가 공표하는 매매 거래 시간·휴장 일정 | 세션 구조(정규장 외 시간대 매매의 존재 여부 포함)는 규정 확인 대상 |
| 결제 주기 | 거래소·예탁 관련 기관의 공표 규정 | 주기 자체를 상수로 암기하지 않고 현행 규정에서 확인 |
| KOSPI/KOSDAQ 제도 구분 | 각 시장의 상장 규정·지수 체계 문서 | 제도적 구분의 확인까지 — 시장 성격의 우열 평가 아님 |
| 환율 노출 확인 | 공식 고시 환율의 존재와, 해당 기업 공시 내 외화 관련 서술 유무 | "노출의 존재" 확인까지 — 환율 수치·방향·영향은 이 렌즈가 다루지 않음 (grounding §3 환율 행) |
| 제도 개정 여부 | 각 공표처의 규정 개정 공고 | 상수 항목 — 본 렌즈의 모든 제도 항목에 적용 |
| 데이터의 출처와 기준시각 | 어느 출처의, 언제 기준 자료인지 항상 함께 확인 | 상수 항목 |

### 5.1 제도 지식의 성격 (안정 vs 가변)

```text
비교적 안정적인 구조 지식 (렌즈가 설명할 수 있는 것):
  - 공표 체계가 "존재한다"는 사실과 그 체계의 축
    (투자자별/프로그램/파생의 분리, 잠정/확정의 구분 존재,
     정기 변경 제도의 존재, 기준일 체계의 존재)
  - 공시에는 원문과 요약의 구분이 있다는 사실
  - 공매도 공시에는 범위·시차 한계가 있다는 사실

가변적 제도 지식 (렌즈가 단정하지 않는 것):
  - 각 제도의 현행 세부 내용 — 공표 시점·주기·기준·수치·요건
  - 제도의 존폐·적용 범위 (규제 조치로 변동 가능한 영역 포함)
  → 전부 "공표처에서 현행 확인" 문형으로만 다룬다

시점 데이터 (렌즈가 말할 수 없는 것 — grounding §2):
  - 현재의 수급·잔고·환율 수치와 그 방향
```

## 6. 오해하기 쉬운 패턴

### 패턴 1. 잠정 집계의 확정화

```text
[패턴]      장중에 보이는 잠정 집계를 확정된 수급 사실로 취급해
            해석을 쌓는 읽기.
[놓치는 것]  잠정과 확정이 별도 시점에 공표되는 제도 구조와,
            두 값이 다를 수 있다는 점.
[확인 질문]  내가 본 수치는 잠정인가 확정인가? 각각의 공표 시점을
            공표처 기준으로 확인했는가?
[기록 질문]  이번 기록의 수급 수치에 "잠정/확정" 표기를 붙인다면
            어느 쪽인가?
```

### 패턴 2. 제도 이벤트와 효과의 등치

```text
[패턴]      편출입 발표·만기일·기준일 같은 제도 이벤트의 "일정
            사실"을 "그날의 수급·가격 움직임의 원인"으로 바로
            연결하는 읽기.
[놓치는 것]  일정의 확인과 영향의 확인은 별개라는 점. 같은 제도
            이벤트가 있어도 시장 반응은 매번 다르며, 영향 경로는
            사후에도 단정하기 어렵다.
[확인 질문]  나는 일정 사실을 확인한 것인가, 영향을 가정한 것인가?
            영향 가정이라면 그것을 확인할 별도 항목을 정했는가?
[기록 질문]  이벤트 "전"의 나의 가정과, "후"에 실제 확인한 것을
            나란히 기록한다면? (event-calendar의 전/후 기록 방식)
```

### 패턴 3. 공매도 잔고의 신호화

```text
[패턴]      공시된 공매도 잔고의 크기를 하락 전망이나 반등(쇼트
            커버) 전망의 신호로 읽는 해석.
[놓치는 것]  공시의 시차·집계 범위 한계 (보이는 잔고 ≠ 전체
            포지션)와, 잔고에는 헤지 등 성격이 다른 포지션이
            섞여 있다는 점 (supply-demand 패턴 2의 단일화 오류와
            동일 구조).
[확인 질문]  내가 본 잔고 공시의 공표 시점·범위·한계를 확인했는가?
            잔고의 성격을 구분할 수 있는 정보가 있는가?
[기록 질문]  나는 이 잔고 수치에서 무엇을 읽었고, 그 해석이
            틀렸다고 볼 확인 항목은 무엇인가?
```

### 패턴 4. 시장 구분의 성격 평가화

```text
[패턴]      KOSPI/KOSDAQ의 제도적 구분을 "안전한 시장 / 위험한
            시장", "큰 회사 / 잡주" 같은 성격 평가로 치환하는 읽기.
[놓치는 것]  두 시장의 차이는 상장 요건·지수 체계 같은 제도의
            차이이지, 개별 종목의 우열이나 위험도의 판정이
            아니라는 점.
[확인 질문]  나는 제도적 구분을 확인한 것인가, 시장 성격의 평가를
            덧붙인 것인가?
[기록 질문]  이번 기록에서 "제도 사실"과 "나의 평가"를 분리해
            적는다면 각각 무엇인가?
```

### 패턴 5. 제도 지식의 고정화

```text
[패턴]      과거에 알던 제도(거래 시간, 결제 주기, 공매도 적용
            범위 등)를 현행으로 가정하고 확인 없이 해석에 쓰는
            읽기.
[놓치는 것]  제도는 개정된다는 점. 특히 규제 조치·시장 제도
            개편으로 적용 범위가 바뀌는 영역이 있다는 점.
[확인 질문]  내가 전제한 제도 지식의 "현행 여부"를 공표처에서
            확인했는가?
[기록 질문]  이번 기록에서 확인한 제도 항목과, 확인 없이 전제한
            제도 항목을 나눈다면 각각 무엇인가?
```

## 8. 안전한 답변 구성 방식

이 렌즈의 콘텐츠는 공통 5단 구조 안에서 아래와 같이 소비된다. 거절/안내 선언 문구는 템플릿(`finance-prompt-templates` §7~§10) 책임이며, 이 렌즈 본문에 중복 작성하지 않는다.

| 5단 구조 | 이 렌즈가 채우는 것 |
|---|---|
| 1. 질문 재해석 | 질문을 §1의 구분 1~5(수급 공표/공시·기업행위/지수·패시브/매매·결제/공매도·노출) 좌표로 재기술 |
| 2. 적용 관점 | equity-kr-structure (+ 병행 렌즈 명시) |
| 3. 확인 항목 | §4 체크리스트 + §5의 확인처 유형 안내에서 선택 |
| 4. 기록/복기 질문 | §7에서 선택 (제도 전제의 확인/미확인 구분 질문 포함) |
| 5. 고지 | "이 내용은 특정 종목의 매수·매도 권유가 아닌 체크리스트입니다." |

- RISK_DATA_GROUNDING redirect 경로에서는 "단정 불가 안내"(templates §10)가 선행되고, 이 렌즈는 그 뒤의 확인 항목 블록 — 공표 체계·확인처·공시 한계 — 만 채운다. 어떤 경로에서도 현재 수급·잔고·환율의 수치·방향·인과를 제시하지 않는다.
- 제도의 구조 설명이 필요한 경우(예: 잠정/확정 구분의 존재) 확인 항목과 분리된 서술로 짧게 배치하고, §5.1의 구분을 유지한다 — 가변 세부는 항상 "현행 확인" 문형으로 되돌린다.
- 패시브·ETF 자금이 언급되는 경우 "지수 제도와 연결되는 자금 경로가 존재한다"는 제도적 맥락의 확인까지만 서술하며, ETF 상품 메커니즘(추적·괴리 등)은 `etf-index-structure` 후보의 책임으로 넘긴다 (본 렌즈에서 중복 서술 금지).
- 병행 라우팅이 잦은 렌즈: `supply-demand`(해석 프레임), `event-calendar`(이벤트 일반 확인), `earnings`(실적·공시 해석), `market-context`(기간·층위).

## 9. 렌즈별 금지 표현

catalog의 공통 금지와 supply-demand §9(수급 신호화·세력 서사 금지)를 승계하고 아래를 추가한다. (아래 목록은 금지 예시의 인용이다.)

```text
[현재 수급 단정]     "외국인이 사고 있습니다" / "기관이 정리 중입니다"
                    (출처·기준시각 없는 현재형 — 공표 제도의 설명이
                    현재 수급의 서술로 미끄러지는 것 포함)
[제도 이벤트-영향 단정] "편입되면 패시브 매수가 들어옵니다" /
                    "만기일이라 변동성이 커집니다" / "배당락으로
                    빠지는 것입니다" (일정 사실 → 영향 단정)
[제도-행동 결합]     "편입 발표 전에 사두는 것이 유리합니다" /
                    "배당 기준일 전에 매수하세요" / "만기 주간은
                    피하세요"
[공매도 신호화]      "공매도 잔고가 많으니 하락 압력입니다" /
                    "쇼트커버링 반등이 나올 자리입니다"
[시장 성격 평가]     "코스닥은 위험한 시장입니다" / "코스피 종목이
                    더 안전합니다"
[환율 인과·전망]     "환율이 오르면 외국인이 나갑니다" /
                    "원화 강세면 시장에 유리합니다"
[제도 세부의 단정]   현행 확인 없이 공표 시점·주기·요건·수치를
                    확정 사실로 제시하는 모든 문장
                    ("결제는 ~일입니다", "공매도는 ~에만 적용됩니다" 류)
```

- "이런 공표 체계가 존재하니 확인하라"는 안내와 "그 체계상 이렇게 움직인다"는 서술의 차이가 이 렌즈의 경계선이다. 후자는 어떤 완곡 표현으로도 금지다 (standard §8.2의 역신호화 금지 포함 — "만기라고 항상 흔들리는 건 아니다" 같은 부정형도 영향 프레임을 남기므로 동일하게 쓰지 않는다).

## 10. PolicyGuard 연결 포인트

- **guard 선행**: "지금 ~하고 있지?", "~때문에 빠지는 거지?" 형태는 제도 어휘가 섞여 있어도 RISK_DATA_GROUNDING으로 분류된다 (policyguard §7.1). 이 렌즈는 분류 이후의 확인 방법 안내만 담당한다.
- **혼합 질문의 승격**: 제도 확인 질문에 "그러니까 사도 돼?"가 결합되면 최위험 우선 원칙(policyguard §3)에 따라 RISK_BUY_SELL로 처리된다. 이 렌즈는 redirect 체크리스트로만 참여한다.
- **달력·제도 사실의 경계**: 만기일·기준일·편출입 일정 등 공표된 일정 사실의 언급은 가능하나, 그로부터 시장 영향을 단정하는 것은 금지다 (grounding §3 조건부 원칙 — supply-demand §5 리밸런싱 행과 동일 기준).
- **패턴 보강 제안**: "공매도 때문에 빠지는 거지?", "만기라 흔들리는 거 맞지?", "편입되면 오르는 거 아니야?" 등 제도 이벤트 인과 동의 유도형 표현은 policyguard §7.1의 RISK_DATA_GROUNDING 패턴군 보강 후보로 제안한다. 규칙 자체는 policyguard 문서가 소유한다.

## 12. 관련 fixture / 등록 경계

**관련(기존)**: 없음 — 본 렌즈는 어떤 기존 fixture에도 등장하지 않는 미등록 후보다 (`fixture_refs: []`).

**fixture 추가 필요 (standard §13 등록 절차)**: 본 문서는 fixture ID·expected behavior를 생성하지 않으며, 등록 시 Fixture owner가 판단할 **검증 위치**만 식별한다.

```text
- 제도·확인처 질문의 SAFE_CHECKLIST/SAFE_LEARNING 라우팅 검증
  (예 유형: "투자자별 매매 데이터는 어디서 어떻게 공표돼?")
- 제도 어휘가 섞인 현재 수급·인과 단정 유도의 RISK_DATA_GROUNDING
  분류 검증 (예 유형: "공매도 때문에 빠지는 거 맞지?")
- 제도 이벤트 전제 매매 판단의 RISK_BUY_SELL 승격 검증
  (예 유형: "편입 발표됐으니 사야지?")
- 제도 데이터 기반 종목 선별 요청의 RISK_RECOMMENDATION 검증
  (예 유형: "공매도 많이 쌓인 종목 알려줘")
- redirect 응답이 확인처·한계 안내에 머물고 영향 단정·시점 함의
  없이 구성되는지 검증
```

**등록·활성화 경계** (재확인):

```text
- 본 문서의 존재는 catalog 등록이 아니다. lens_key
  "equity-kr-structure"는 catalog 등록 전까지 응답 경로에서
  사용될 수 없다 (fixtures §10 — 미정의 lens 이름 사용 = 실패).
- 활성화는 lens-registration-v1 gate의 조건(등록 전 체크리스트
  완료 + 전체 fixture regression 통과)을 요구하며, 문서 작성·
  lifecycle 값 변경만으로 발생하지 않는다 (metadata standard §8).
- redirect_to는 Routing 등록 시점에 Routing Contract와의 정합
  하에서만 채워진다. 그 전까지 빈 목록이 canonical 상태다.
- related_lenses는 본 문서의 병행 언급(§2, §8)으로부터 자동
  생성하지 않는다 — formal 관계는 별도 semantic review로만
  확정한다 (standard §3.1).
```

## 13. 작성 완료 셀프 체크리스트

`finance-lens-authoring-standard.md` §14 전체를 적용하며, 이 렌즈의 고유 확인 항목은 다음과 같다.

- [ ] 현재 시장에 대한 논평·수급 결론·인과·전망 문장이 없다
- [ ] 제도 이벤트(편출입/만기/기준일)의 일정 사실 확인과 시장 영향이 모든 섹션에서 분리되어 있고, 영향 단정이 없다
- [ ] 제도의 가변 세부(공표 시점·주기·요건·수치)가 확정 사실 문형으로 등장하지 않고, 전부 "현행 확인" 문형이다
- [ ] 공매도·대차 공시의 범위·시차 한계가 명시되고, 잔고가 방향 신호로 전환되는 문장이 없다 (역신호화 — 쇼트커버 기대 — 포함)
- [ ] KOSPI/KOSDAQ 구분이 제도 차이로만 서술되고 시장·종목 성격 평가가 없다
- [ ] 환율이 "노출의 존재 확인"까지만 등장하고 방향·영향·인과 서술이 없다 (해석 프레임은 macro-rate-fx 소유 — 침범 없음)
- [ ] 수급의 해석 프레임(주체/기간/성격 구분·오해 패턴)을 새로 만들지 않았다 (supply-demand 책임 — 본 렌즈는 공표 제도·확인처만)
- [ ] 패시브·ETF 언급이 제도적 맥락의 존재 확인까지이고, ETF 상품 메커니즘 서술이 없다 (etf-index-structure 후보 책임 침범 없음)
- [ ] 위험 질문은 §0 Metadata의 forbidden_intents와 §3에만 등장한다
- [ ] fixture ID·intent·action·gate ID·validator 카테고리를 새로 만들지 않았다
- [ ] 어떤 문장도 단독 인용 시 "무엇을 하라"로 읽히지 않는다
