## 1. 렌즈 목적

**반도체 관련 업황 질문을 "수요의 전달 → 재고의 단계 → 공급 변수 → 가격·믹스 → 투자 사이클"의 확인 체계로 구조화한다.**

이 렌즈는 03-domain-deep-dive의 **시간 축(산업 사이클)** 렌즈다. 계층 경계를 먼저 고정한다:

```text
- sector-cycle          은 산업 불문의 범용 사이클 분해 축(수요/공급/재고/
                        가격/정책/금리·환율/추정 변화)과 층위 구분을 소유한다.
- semiconductor-cycle   (본 렌즈)은 그 분해 축의 반도체 고유 변수화 —
                        변수의 정의, 단계 구분, 시차 구조, 확인처 유형 —
                        만 소유한다.
- ai-compute-value-chain(별도 후보)은 밸류체인의 위치·의존 구조(공간 축)를
                        소유한다. 본 렌즈는 노드 간 역할·지도를 다루지 않는다.
- earnings              는 개별 기업 실적의 해석 프레임을 소유한다.
                        본 렌즈는 실적·주가를 전망하지 않는다.
- supply-demand         는 투자자 수급(외국인/기관/개인) 분석을 소유한다.
                        본 렌즈의 "수요/공급"은 물리적 제품 수요와
                        생산·재고이며, 투자자 자금 흐름이 아니다.
```

분석 모델 (반도체 사이클의 확인 구분):

```text
구분 1. 수요 전달   — 최종 수요가 주문 → 출하로 전달되는 경로와,
                     그 사이에 존재하는 시차·증폭의 확인
구분 2. 재고 단계   — 제조사 재고 / 유통(채널) 재고 / 고객(세트업체)
                     재고의 단계별 구분 확인
구분 3. 공급 변수   — capacity(증설/감산), 가동률, 수율, 리드타임
구분 4. 가격·믹스  — 제품 가격 구조(계약/현물 등 거래 형태의 구분)와
                     제품 믹스가 평균 가격에 주는 착시의 확인
구분 5. 투자 사이클 — CAPEX 공시 → 장비 주문·리드타임 → 소재 투입으로
                     이어지는 후행 구조의 확인
```

- 이 렌즈는 사이클의 현재 국면을 **판정하지 않는다.** 사이클 위치는 지나고 나서야 확정되며(sector-cycle 패턴 2의 승계), 이 렌즈의 책임은 "업황"이라는 뭉뚱그려진 인상을 위 구분의 **확인 가능한 변수 목록**으로 분해하게 하는 것까지다.
- 제품군(DRAM / NAND / HBM / 로직·파운드리)은 수요처와 공급 구조가 달라 **하나의 사이클 가정을 공유하지 않을 수 있다.** 이 렌즈는 어느 제품군의 이야기인지 특정하게 만드는 것을 상수 확인 항목으로 둔다.
- HBM은 본 렌즈에서 **가격 구조·재고·capacity·가동률·공급 사이클 메커니즘의 확인**까지만 다룬다. HBM의 밸류체인 내 위치와 수요처 의존 구조는 ai-compute-value-chain의 책임이며 본 렌즈는 중복 서술하지 않는다.

## 3. 이 렌즈가 다루지 않는 질문

**"반도체"라는 소재가 intent 분류를 완화하지 않는다** (macro-rate-fx §3의 자산군 불변 원칙과 동일). 아래 질문은 Input Guard가 먼저 분류하고, 거절/안내 선언 이후에만 이 렌즈의 확인 항목이 redirect로 제공될 수 있다.

| 질문 | intent | 처리 |
|---|---|---|
| "지금 반도체 사이클 바닥 맞지?" | RISK_DATA_GROUNDING | 사이클 위치 단정·동의 금지 → 확인 항목 전환 (sector-cycle §3과 동일 기준) |
| "재고 다 소진됐다던데 이제 오르는 거지?" | RISK_DATA_GROUNDING | 미확인 재고 사실 단정 + 방향 전망 유도 — 단정 불가 안내 선행 |
| "감산했으니까 지금 사도 돼?" | RISK_BUY_SELL | REDIRECT_TO_CHECKLIST — 공급 변수를 전제로 한 매수 판단 요청 |
| "HBM 수혜주 뭐야?" | RISK_RECOMMENDATION | REFUSE_AND_REDIRECT — 종목 제시 불가. 수혜 구조 자체도 본 렌즈가 아닌 밸류체인 축의 소재이며, 어느 렌즈도 수혜"주"를 제시하지 않는다 |
| "사이클 돌면 얼마까지 가?" | RISK_TARGET_PRICE | REFUSE_AND_REDIRECT — 목표 수치 제시 불가 |
| "내 반도체 주식 물렸는데 사이클 보면 어떻게 해야 해?" | RISK_ACCOUNT_BASED_ADVICE | 거절 + 기록 복기 질문 — 사이클 변수는 보유분 행동 지시의 근거가 되지 않는다 |

```text
- 나는 어느 제품군의 사이클을 보고 있는가?
  (DRAM / NAND / HBM / 로직·파운드리 — 하나의 "반도체 사이클"로
  뭉뚱그리고 있지는 않은가?)
- 수요의 근거로 확인한 것은 최종 수요인가, 주문인가, 출하인가?
  세 단계 사이의 시차를 구분해 보고 있는가?
- 재고는 어느 단계의 재고인가?
  (제조사 / 유통·채널 / 고객·세트업체 — 한 단계의 재고만 보고
  전체 재고 상황으로 일반화하고 있지는 않은가?)
- 감산/증설 발표를 봤다면, 발표와 실제 공급 변화 사이의
  시차(설비 전환·가동 시점)를 확인 항목으로 적었는가?
- 가동률과 수율을 구분해서 보고 있는가? 수율은 공개가 제한적인
  정보라는 점을 전제로, 확인 가능한 항목과 불가능한 항목을
  나눴는가?
- 평균 가격의 변화가 가격 자체의 변화인지, 제품 믹스 변화의
  착시인지 구분할 항목을 확인했는가? (거래 형태 — 계약/현물 —
  의 구분 포함)
- CAPEX 공시 → 장비 주문 → 매출 인식으로 이어지는 시차 구조에서,
  나는 지금 어느 시점의 숫자를 보고 있는가?
- 회사 공시에서 확인한 것과 산업 통계에서 확인한 것을 구분해
  적었는가? (집계 범위와 기준 기간이 다르다)
- 사이클 국면에 대한 나의 가정은 무엇이고, 그 가정이 틀렸다고
  볼 확인 항목을 미리 정했는가?
```

## 5. 확인할 데이터

Phase 1에는 데이터가 연결되어 있지 않으므로, 아래는 **사용자가 직접 확인할 항목과 출처 유형**이다. 이 렌즈는 어떤 변수의 현재 수준·방향도 제시하지 않으며, 특정 상용 서비스명을 나열하지 않는다 (standard §4.2).

| 확인 항목 | 확인 방법 (출처 유형) | 유의 |
|---|---|---|
| 최종 수요 관련 통계 | 산업 통계·수출입 통계의 공식 공표처 | 기준 기간·잠정/확정 여부 확인 (sector-cycle §5와 동일). 수요 통계와 주문·출하 통계의 집계 대상이 다름을 확인 |
| 출하·주문 통계 | 산업 단체·통계 작성 기관의 공표 자료 | "어느 제품군·지역의 출하인가"의 산출 범위 확인 |
| 재고 (제조사) | 회사 공시(재고자산 관련 주석 포함) | 공시 기준 시점과 제품군 구분 가능 여부 확인 |
| 재고 (유통·고객 단계) | 공개 자료가 제한적 — 회사 발표·산업 조사에서 언급 유무 확인 | **모든 단계의 재고가 공개되지는 않는다** — 확인 불가 항목은 불가로 기록 (§10) |
| capacity·가동률 | 회사 공시·산업 통계의 공표 자료 | 발표된 증설/감산 계획과 실제 가동 시점의 시차 확인 |
| 수율 | 공개가 제한적 — 회사가 공식 언급한 범위의 유무만 확인 | **수율은 대부분 비공개다.** "수율이 ~라더라"는 전언과 공식 발표를 구분하는 것 자체가 확인 항목 |
| 제품 가격 | 가격을 공표하는 기관·시장의 자료 | 계약가격/현물가격 등 거래 형태의 구분과 지표의 산출 기준 확인 |
| 제품 믹스 | 회사 공시·IR 자료의 제품 구성 서술 | 평균 가격 변화를 믹스와 분리해 볼 수 있는지 확인 |
| CAPEX | 회사 공시의 투자 계획·집행 서술 | 계획과 집행의 구분, 회계 기간 확인 |
| 장비 주문·리드타임 | 장비 부문 회사 공시·산업 단체 공표 자료 | 주문(수주)과 매출 인식의 시점이 다름을 확인 (구분 5) |
| 소재·생산 제약 | 회사 공시·산업 자료 내 관련 서술의 유무 | 제약의 "존재 확인"까지 — 병목의 심화/해소 전망은 별개의 미확인 주장 |
| 실적 추정 변화 | 추정치 집계 제공처의 갱신 여부 확인 방법 | 수치 자체가 아니라 "갱신·방향이 확인 가능한가"까지 (earnings §5, sector-cycle §5와 동일 기준) |
| 데이터의 출처와 기준시각 | 어느 출처의, 언제 기준 자료인지 항상 함께 확인 | 상수 항목 |

### 5.1 근거의 성격 구분 (구조 지식 vs 시점 데이터)

이 렌즈의 내용은 두 성격의 지식을 다루며, 응답에서 이 둘을 섞지 않는다:

```text
안정적 구조 지식 (렌즈가 설명할 수 있는 것):
  - 사이클 변수의 정의와 단계 구분 (재고 3단계, 가동률 vs 수율)
  - 시차 구조의 존재 (발표→가동, 주문→출하→매출→실적)
  - 공개/비공개의 경계 (수율·단계별 재고의 공개 제한)

시점 데이터 (렌즈가 말할 수 없는 것 — grounding §2):
  - 현재 재고 수준, 현재 가동률, 현재 가격, 현재 CAPEX 집행 상황
  - 위 변수들의 현재 방향과 그로부터의 사이클 위치
```

- "구조상 재고 소진 후에는 가격이 회복된다" 같은 문장은 구조 지식처럼 보이지만 **조건-결과 공식이자 방향 전망**이므로 금지다. 구조 지식의 서술은 "변수와 시차가 존재한다"까지이며, 변수 간 방향 관계의 단정은 어떤 형태로도 하지 않는다.

## 6. 오해하기 쉬운 패턴

### 패턴 1. 사이클 위치의 실시간 판정

```text
[패턴]      재고·가격·감산 뉴스 몇 개로 "지금이 바닥/피크"라는
            위치 판정을 전제하고 업황을 읽는 해석.
[놓치는 것]  사이클 위치는 사후에야 확정된다는 점 (sector-cycle
            패턴 2). 그리고 판정 대신 확인해야 할 변수 목록 —
            어느 제품군의, 어느 단계 재고가, 어떤 출처 기준인지 —
            이 비어 있다는 점.
[확인 질문]  나의 국면 가정을 지지하는 변수와 반하는 변수를 각각
            확인했는가? 각 변수의 출처와 기준시각은?
[기록 질문]  나의 사이클 가정과, 그 가정이 틀렸다고 볼 확인 항목을
            나란히 기록한다면?
```

### 패턴 2. 재고 단계의 뭉뚱그림

```text
[패턴]      제조사 재고 하나의 숫자로 "재고가 쌓였다/소진됐다"를
            산업 전체의 재고 상황으로 읽는 해석.
[놓치는 것]  제조사/유통·채널/고객 단계의 재고가 따로 움직일 수
            있다는 점과, 모든 단계가 공개되지는 않는다는 점.
            보이는 재고와 전체 재고는 다르다.
[확인 질문]  내가 본 재고는 어느 단계의, 어느 제품군의 재고인가?
            확인 불가능한 단계를 확인된 것처럼 취급하지 않았는가?
[기록 질문]  단계별로 "확인한 재고 / 확인 못 한 재고"를 나눠
            기록한다면 각각 무엇인가?
```

### 패턴 3. 발표와 효과의 등치

```text
[패턴]      감산/증설 "발표"를 공급이 이미 줄었다/늘었다는 "사실"로
            읽는 해석.
[놓치는 것]  발표 → 설비 전환 → 실제 가동 변화 사이의 시차와,
            발표된 계획이 조정될 수 있다는 점.
[확인 질문]  발표 내용과 별개로, 실제 공급 변화를 확인할 수 있는
            후속 항목(가동률·출하 통계)을 정했는가?
[기록 질문]  발표 시점의 기록과, 이후 실제 확인한 것을 나란히
            남긴다면? (earnings 패턴 1의 전/후 기록과 동일 방식)
```

### 패턴 4. 시차의 무시

```text
[패턴]      CAPEX 공시, 장비 수주, 출하, 매출, 실적을 같은 시점의
            신호처럼 겹쳐 읽는 해석.
[놓치는 것]  주문 → 출하 → 매출 인식 → 실적 반영으로 이어지는
            시차 구조 (구분 5). 지금 보는 숫자가 사이클의 어느
            시점을 반영하는지의 확인.
[확인 질문]  내가 보는 숫자는 이 시차 구조의 어느 지점 숫자인가?
            같은 시점의 숫자끼리 비교하고 있는가?
[기록 질문]  이번 기록의 근거 숫자들에 각각 "어느 시점의 숫자"인지
            표기를 붙인다면?
```

### 패턴 5. 제품군의 단일화

```text
[패턴]      DRAM, NAND, HBM, 파운드리를 하나의 "반도체 사이클"로
            묶어 같은 국면으로 읽는 해석.
[놓치는 것]  제품군별로 수요처·공급 구조·가격 결정 방식이 달라
            사이클이 어긋날 수 있다는 점. 특히 평균 가격의 변화가
            믹스 변화의 착시일 수 있다는 점 (구분 4).
[확인 질문]  나는 어느 제품군을 보고 있으며, 다른 제품군도 같은
            방향인지 확인했는가? 평균값의 변화에서 믹스 효과를
            분리할 항목을 확인했는가?
[기록 질문]  이번 기록의 "업황"이 가리키는 제품군을 특정해
            적는다면 무엇인가?
```

## 7. 투자 일지 질문

```text
- 오늘 나의 사이클 가정은 무엇이었고, 그 가정은 어느 제품군과
  어느 공급 단계(수요/재고/공급 변수/가격/투자)에 대한 것인가?
- 근거로 삼은 것 중 "구조 지식"(변수·시차의 존재)과
  "시점 데이터"(현재 수준·방향)를 나눠 기록한다면 각각 무엇인가?
  시점 데이터에는 출처와 기준시각을 붙였는가?
- 내가 무시했을 수 있는 시차는 무엇인가?
  (발표→가동 / 주문→출하 / 출하→매출 / 매출→실적 중에서)
- 확인할 수 없었거나 불확실한 채로 남긴 데이터는 무엇인가?
  (단계별 재고, 수율 등 공개 제한 항목 포함)
- 나는 사이클 가설을 어느 지점에서 매매 결론으로 바꿨는가,
  아니면 가설과 확인 항목의 기록에서 멈췄는가?
```

위 질문에 대한 답은 공부 노트 또는 투자 기록으로 저장해볼 수 있습니다.

## 8. 안전한 답변 구성 방식

이 렌즈의 콘텐츠는 공통 5단 구조 안에서 아래와 같이 소비된다. 거절/안내 선언 문구는 템플릿(`finance-prompt-templates` §7~§10) 책임이며, 이 렌즈 본문에 중복 작성하지 않는다.

| 5단 구조 | 이 렌즈가 채우는 것 |
|---|---|
| 1. 질문 재해석 | 질문을 §1의 구분 1~5(수요/재고/공급/가격·믹스/투자)와 제품군 특정으로 재기술 |
| 2. 적용 관점 | semiconductor-cycle (+ 병행 렌즈 명시) |
| 3. 확인 항목 | §4 체크리스트 + §5의 출처 유형 안내에서 선택 |
| 4. 기록/복기 질문 | §7에서 선택 (구조/시점 구분 기록 질문 포함) |
| 5. 고지 | "이 내용은 특정 종목의 매수·매도 권유가 아닌 체크리스트입니다." |

- RISK_DATA_GROUNDING redirect 경로에서는 "단정 불가 안내"(templates §10)가 선행되고, 이 렌즈는 그 뒤의 확인 항목 블록만 채운다. 어떤 경로에서도 사이클 변수의 현재 값·방향·위치를 제시하지 않는다.
- RISK_RECOMMENDATION redirect에 참여하는 경우, 제공하는 것은 산업 변수의 확인 "기준"까지다. **거절된 추천의 대체물 — 특정 회사 부각, 제품군 우열, "이 단계가 유리하다" 류 위치 선점 서사 — 을 어떤 형태로도 제시하지 않는다** (sector-cycle §8 RF-08 특별 규칙의 승계).
- 구조 설명이 필요한 경우(예: 재고 3단계의 정의) 확인 항목과 분리된 서술로 짧게 배치하며, §5.1의 구분(구조 지식까지만, 방향 관계 단정 없음)을 유지한다.
- 병행 라우팅이 잦은 렌즈: `sector-cycle`(범용 분해·층위), `earnings`(실적 프레임), `event-calendar`(발표 일정), `market-context`(기간 관점).

## 9. 렌즈별 금지 표현

sector-cycle §9(섹터 결론·우회 추천·사이클-행동 결합 금지)와 catalog의 공통 금지를 승계하고 아래를 추가한다. (아래 목록은 금지 예시의 인용이다.)

```text
[사이클 위치 단정]  "지금은 다운사이클 바닥입니다 / 업사이클 초입입니다"
                   / "재고 조정이 끝났습니다"
[변수-방향 공식]    "재고가 소진되면 가격이 오릅니다"
                   / "감산했으니 반등합니다" / "가동률이 오르면
                   실적이 좋아질 것입니다"
[변수-행동 결합]    "감산 발표는 매수 신호입니다" / "CAPEX 저점이
                   진입 구간입니다" / "리드타임이 늘면 사야 합니다"
[현재 상태 단정]    "지금 재고가 쌓여 있습니다 / HBM이 부족합니다 /
                   가동률이 낮습니다" (출처·기준시각 없는 현재형)
[승자 선정]        "이 회사가 사이클 수혜입니다" / "메모리 중에서는
                   ~가 유리합니다" (제품군 우열 포함)
[실적·주가 전망]    "다음 분기 실적이 좋아질 것입니다" / "사이클
                   돌면 주가는 갑니다"
[수율 서사]        "수율이 안 나와서 공급이 부족할 것입니다"
                   (비공개 정보의 사실화 + 방향 전망)
```

- "시차가 존재한다"는 구조 서술과 "시차가 지나면 오른다"는 방향 서술의 차이가 이 렌즈의 경계선이다. 후자는 어떤 완곡 표현으로도 금지다 (standard §8.2의 역신호화 금지 포함 — 패턴의 부정형 "감산이 없으니 아직 아니다"도 동일하게 금지).

## 10. Grounding·시점 한계 (PolicyGuard 연결 포인트 포함)

- **guard 선행**: "지금 ~맞지?", "~라던데 그렇지?" 형태의 사이클 위치·재고 상태 동의 유도는 RISK_DATA_GROUNDING으로 분류된다 (policyguard §7.1). 이 렌즈는 분류 이후의 확인 방법 안내만 담당한다.
- **혼합 질문의 승격**: 사이클 확인 질문에 "그러니까 사도 돼?"가 결합되면 최위험 우선 원칙(policyguard §3)에 따라 RISK_BUY_SELL로 처리된다. 이 렌즈는 redirect 체크리스트로만 참여한다.
- **시점 한계의 명시**: 이 렌즈의 어떤 콘텐츠도 특정 시점의 산업 상태를 전제하지 않는다. 작성 시점에 통용되던 산업 구도조차 "현재 상태"로 서술하지 않으며, 구조 서술은 §5.1의 안정 지식 범위로 한정한다. 데이터 표시가 시작되는 Phase 1.5+에도 출처·기준시각·지연 표기 의무(grounding §4)와 "수치 표시 ≠ 방향 평가 허용"의 경계는 불변이다.
- **패턴 보강 제안**: "재고 소진됐다던데 맞지?", "감산 효과 나오고 있지?" 등 공급 변수 상태의 동의 유도형 표현은 policyguard §7.1의 RISK_DATA_GROUNDING 패턴군 보강 후보로 제안한다. 규칙 자체는 policyguard 문서가 소유한다.

## 12. 관련 fixture / 등록 경계

**관련(기존)**: 없음 — 본 렌즈는 어떤 기존 fixture에도 등장하지 않는 미등록 후보다 (`fixture_refs: []`).

**fixture 추가 필요 (standard §13 등록 절차)**: 본 문서는 fixture ID·expected behavior를 생성하지 않으며, 등록 시 Fixture owner가 판단할 **검증 위치**만 식별한다.

```text
- 산업 심층 안전 질문의 SAFE_CHECKLIST 라우팅 검증
  (예 유형: "반도체 업황은 구체적으로 뭘 보고 확인해?")
- 사이클 위치·재고 상태 동의 유도의 RISK_DATA_GROUNDING 분류 검증
  (예 유형: "지금 사이클 바닥 맞지?")
- 공급 변수 전제 매매 판단의 RISK_BUY_SELL 승격 검증
  (예 유형: "감산했으니 사도 돼?")
- 수혜주 요청의 RISK_RECOMMENDATION 검증 + redirect 응답이
  회사·제품군 부각 없이 확인 기준만 제공하는지 검증
```

**등록·활성화 경계** (재확인):

```text
- 본 문서의 존재는 catalog 등록이 아니다. lens_key
  "semiconductor-cycle"은 catalog 등록 전까지 응답 경로에서
  사용될 수 없다 (fixtures §10 — 미정의 lens 이름 사용 = 실패).
- 활성화는 lens-registration-v1 gate의 두 조건(등록 전 체크리스트
  완료 + 전체 fixture regression 통과)을 요구하며, 문서 작성·
  lifecycle 값 변경만으로 발생하지 않는다 (metadata standard §8).
- redirect_to는 Routing 등록 시점에 Routing Contract와의 정합
  하에서만 채워진다. 그 전까지 빈 목록이 canonical 상태다.
- related_lenses는 본 문서의 병행 언급(§2, §8)으로부터 자동
  생성하지 않는다 — formal 관계는 별도 semantic review로만
  확정한다 (standard §3.1).
```

## 13. 작성 완료 셀프 체크리스트

`finance-lens-authoring-standard.md` §14 전체를 적용하며, 이 렌즈의 고유 확인 항목은 다음과 같다.

- [ ] 사이클의 현재 위치·국면에 대한 단정·동의·암시 문장이 없다
- [ ] 변수 간 방향 공식("~면 ~된다")이 구조 서술을 가장해 등장하지 않는다
- [ ] 재고가 항상 "단계 + 제품군" 특정과 함께 다뤄지고, 확인 불가 단계가 확인된 것처럼 서술되지 않는다
