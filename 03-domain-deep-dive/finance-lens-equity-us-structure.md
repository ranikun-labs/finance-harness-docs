## 1. 렌즈 목적

**미국 주식시장 관련 질문을 "이 데이터·이벤트가 어떤 제도 하에서, 어디서, 어떤 한계와 함께 공표되는가"의 확인 체계로 구조화한다.**

이 렌즈는 03-domain-deep-dive의 **국가·시장 구조 축(축 1)** 렌즈다. 계층 경계를 먼저 고정한다:

```text
- supply-demand        는 수급의 해석 프레임(주체/시장/기간/성격 구분,
                       오해 패턴)을 소유한다. 본 렌즈는 그 프레임에
                       추가하지 않으며, "미국에서 포지션·흐름 관련
                       데이터가 어떤 제도로, 어떤 시차·범위 한계와
                       함께 공표되는가"의 확인처만 소유한다. 특히
                       "한국식 일별 투자자별 매매 공표에 대응하는
                       체계가 미국에 그대로 존재하는 것은 아니다"라는
                       제도 차이의 확인 항목이 본 렌즈의 책임이다
                       (pack design §4.2).
- event-calendar       는 시점성 이벤트의 일반 확인 프레임을 소유한다.
                       본 렌즈는 미국 고유 제도 캘린더(지수 정기 변경,
                       옵션 만기 규칙, 휴장·단축 거래일, 실적 시즌,
                       거시 지표 발표 일정)의 "확인처"만 추가한다.
- macro-rate-fx        는 금리·환율 등 매크로 변수의 해석 프레임을
                       소유한다. 본 렌즈의 거시 지표 취급은 "발표
                       캘린더가 공표된다는 사실"과 그 확인처까지이며,
                       지표의 방향·영향 해석에 참여하지 않는다.
- earnings             는 실적의 해석 프레임(일정·기대·요인·계획)을
                       소유한다. 본 렌즈는 미국 공시·실적 보고 제도
                       (정기·수시 보고 체계, 실적 시즌의 캘린더 구조)의
                       확인처만 추가한다.
- etf-index-structure  (02 계층 후보)는 ETF·지수 상품의 vehicle
                       메커니즘(복제, 설정·환매, 추적오차·괴리,
                       비용, 레버리지·환헤지)을 소유한다. 본 렌즈는
                       "지수 제도와 제도적으로 연결되는 패시브 자금
                       경로가 존재한다"는 맥락의 확인까지만 다루고
                       상품 메커니즘을 중복 서술하지 않는다
                       (pack design §1.5 — 02 배타 소유).
- market-context       는 국면·좌표 프레임을 소유한다. 본 렌즈는
                       시장 논평·국면에 참여하지 않는다.
```

분석 모델 (미국 시장 구조의 확인 구분):

```text
구분 1. 거래소·상장·체결 구조 — 복수 거래소·상장 시장의 병존,
                         동일 종목이 여러 시장과 장외·대체 거래
                         경로에서 체결되는 분산(fragmentation) 구조,
                         마켓메이커·유동성 공급 구조, ADR·교차상장
                         구조의 확인
구분 2. 세션·캘린더·결제 구조 — 정규장과 프리/애프터마켓의 구분,
                         세션별 유동성·주문 처리 방식의 제도적 한계
                         (구조 개념으로서만), 휴장·단축 거래일 캘린더,
                         결제 주기, 거시 지표 발표 캘린더의 확인처
구분 3. 공시·실적·기업행위 제도 — 정기·수시 공시 보고 체계, 실적
                         보고와 실적 시즌 캘린더의 구조(기업별
                         회계연도 차이 포함), 배당·분할·분사 등
                         기업행위 공시와 기준일 체계의 확인
구분 4. 지수·패시브·파생 제도 — 지수 산출 방법론 문서와 정기 변경
                         (리밸런싱) 일정의 확인처, 지수 구성 집중도의
                         확인 방법, 패시브 자금이 제도적으로 연결되는
                         경로의 존재 확인(상품 구조는 02 위임),
                         옵션 만기 등 파생 캘린더의 제도 구조
구분 5. 포지션 데이터의 공표 한계 — 기관 보유 보고 등 포지션성
                         공표 데이터의 보고 주기·공표 시차·포함
                         범위·집계 방식 한계의 확인, 공식 출처 우선
                         검증, 제도 개정 여부 확인(상수 항목)
```

- 이 렌즈는 제도를 **암기된 사실로 단정하지 않는다.** 제도는 개정되는 지식이므로(결제 주기·세션 규칙·보고 기준 등은 실제로 변경되어 온 영역이다), 모든 확인 항목은 "규정 원문·공식 공표처에서 현행 여부를 확인"하는 문형을 기본으로 하며, "개정 여부 확인"이 상수 항목이다 (pack design §4.0 official-source-first / DD-13 확인처 안내 기본).
- 이 렌즈는 제도 사실로부터 시장 영향을 **연결하지 않는다.** "만기·정기 변경 일정이 공표되어 있다"는 확인과 "그래서 그날 가격·자금 흐름이 어떻게 된다"는 단정은 다르며, 후자는 이 렌즈의 어떤 문장에도 없다. 집중도에 대해서도 동일하다 — "구성 집중도를 어디서 확인하는가"까지가 이 렌즈이고, "집중됐으니 시장이 어느 방향"이라는 판정은 어디에도 없다.

## 3. 이 렌즈가 다루지 않는 질문

**"제도"라는 소재가 intent 분류를 완화하지 않는다.** 제도 질문의 형태를 하고 있어도 현재 상태·인과·행동 판단을 요구하면 아래 경로로 처리되며, Input Guard가 렌즈보다 먼저 분류한다.

| 질문 | intent | 처리 |
|---|---|---|
| "지금 옵션 만기라 빠지는 거지?" | RISK_DATA_GROUNDING | 인과 단정 금지 (DG-05와 동일 구조) — 만기 캘린더의 확인 방법 안내까지만 |
| "나스닥 지금 고점이지?" | RISK_DATA_GROUNDING | 현재 지수 위치·국면 단정 금지 — 단정 불가 안내 선행 |
| "기관들 지금 사고 있는 거 맞지? 보고서 보면 알잖아" | RISK_DATA_GROUNDING | 지연·부분 공개 보고를 현재 포지션으로 단정하는 유도 — 공표 시차·범위 한계의 확인 항목으로 전환 |
| "빅테크에 몰려 있으니 지수 위험한 거지?" | RISK_DATA_GROUNDING | 집중도 사실 확인과 방향·위험 판정은 다르다 — 확인 방법 안내까지만 |
| "리밸런싱 때 패시브 매수 들어오니까 사야지?" | RISK_BUY_SELL | REDIRECT_TO_CHECKLIST — 제도 이벤트를 전제로 한 매매 판단 요청 |
| "미국 주식 지금 들어가?" | RISK_BUY_SELL | REDIRECT_TO_CHECKLIST |
| "실적 발표 전에 프리마켓에서 사두는 게 낫지?" | RISK_BUY_SELL | 세션 구조가 시점 선택 판단을 정당화하지 않는다 — 세션 전략은 어떤 형태로도 제공하지 않음 |
| "지수 편입될 종목 찍어줘" | RISK_RECOMMENDATION | REFUSE_AND_REDIRECT — 제도 데이터 기반 종목 선별·예측도 종목 추천이다 |

## 4. 판단 전 체크리스트

```text
- 내가 본 가격·거래량 수치가 어느 범위의 집계인지 확인했는가?
  (단일 거래소 값인지, 복수 시장·장외 체결을 포함한 통합 집계인지 —
   미국은 동일 종목이 여러 시장에서 나뉘어 체결되는 구조다)
- 그 수치가 어느 세션의 것인지 확인했는가? (정규장 / 프리마켓 /
  애프터마켓 — 세션별로 참여 구조와 주문 처리 방식이 제도적으로
  다르다는 점을 규정 기준으로 확인했는가?)
- 시간외 세션이 관련된다면, 해당 세션의 유동성·주문 유형 제약을
  거래소·중개기관이 공표하는 규정에서 확인했는가?
  (구조의 확인까지 — 세션을 이용한 매매 시점 선택은 별개의 문제이며
   이 체크리스트의 대상이 아니다)
- 공시·실적 자료를 본다면, 요약·전언이 아니라 전자 공시 시스템의
  원문 기준으로 확인했는가? 해당 기업의 회계연도와 보고 일정을
  기업 공시·IR 공표 기준으로 확인했는가? (실적 시즌이라는 집계
  개념과 개별 기업의 일정은 별개다)
- 거시 지표 일정이 관련된다면, 통계 작성 기관·중앙은행이 공표하는
  발표 캘린더에서 일정 사실만 확인했는가? (지표의 해석은 이
  체크리스트의 대상이 아니다)
- 지수 관련 확인이라면, 해당 지수의 산출 방법론 문서와 정기 변경
  일정을 지수 산출 기관의 공표 자료에서 확인했는가?
- 지수 집중도가 관련된다면, 구성 종목·비중을 공표 자료의 기준일과
  함께 확인했는가? (집중도의 확인까지 — 그로부터의 방향·위험
  판정은 별개다)
- 옵션 만기 등 파생 일정이 관련된다면, 파생 거래소·청산 기관이
  공표하는 캘린더에서 일정 사실을 확인했는가?
- 기관 보유·공매도 잔량 등 포지션성 데이터를 본다면, 그 보고의
  주기·공표 시차·포함 범위(무엇이 보고되고 무엇이 보고되지
  않는지)·집계 방식의 한계를 확인했는가? (모든 포지션이 실시간으로
  보이는 체계가 아니다)
- ADR·교차상장 종목이라면, 원주와 예탁증서의 관계(전환 비율,
  상장 형태, 공시 의무 수준의 유형)를 예탁기관·발행사 공시에서
  확인했는가?
- 기업행위(배당/분할/분사 등)를 본다면, 공시 원문에서 기준일·
  일정·조건을 확인했는가? (기준일 체계는 결제 주기와 연결되므로
  함께 확인)
- 휴장·단축 거래일이 관련된다면, 거래소가 공표하는 현행 캘린더에서
  확인했는가? (현물과 파생 시장의 캘린더는 별도 확인 대상이다)
- 내가 전제한 제도 지식이 현행인지 — 개정 여부를 공표처에서
  확인했는가? (상수 항목: 결제 주기·세션 규칙·보고 기준을 포함해
  제도는 바뀐다)
```

## 5. 확인할 데이터

Phase 1에는 데이터가 연결되어 있지 않으므로, 아래는 **사용자가 직접 확인할 항목과 출처 유형**이다. 이 렌즈는 특정 상용 서비스명을 나열하지 않으며(standard §4.2), 어떤 제도 항목의 현행 세부 내용(시간대·주기·기준·수치·요건)도 본문에 고정하지 않는다 — 세부는 항상 규정 원문 확인 대상이다.

| 확인 항목 | 확인 방법 (출처 유형) | 유의 |
|---|---|---|
| 상장 시장과 분산 체결 구조 | 거래소·규제 기관이 공표하는 시장 구조 안내·규정 | 동일 종목이 상장 거래소 외 복수 시장에서 체결된다는 구조의 확인 — 단일 시장 수치를 전체로 읽지 않기 위한 전제 |
| 통합 시세·거래량의 집계 범위 | 시세 공표 체계의 공식 안내 자료 | 내가 본 값이 어느 시장들·어느 세션의 집계인지, 기준시각과 함께 확인 |
| 장외·대체 거래 체결의 공표 | 규제·자율규제 기관이 공표하는 체결 통계·안내 | 공표 주기·집계 기준·범위의 확인 — 화면의 거래량이 전체 체결을 포함하는지의 검증 대상 |
| 마켓메이커·유동성 공급 구조 | 거래소·규제 기관의 제도 안내 | 유동성 공급이 제도화된 구조가 존재한다는 사실의 확인까지 — 특정 시점의 유동성 상태 평가 아님 |
| 세션 구조·시간외 거래 규정 | 거래소·중개기관이 공표하는 매매 규정 | 세션 구분과 세션별 주문 유형·체결 방식 제약은 규정 확인 대상 — 중개기관별로 취급이 다를 수 있다는 점 포함 |
| 휴장·단축 거래일 | 거래소가 공표하는 현행 캘린더 | 현물·파생 캘린더 별도 확인. 매년 갱신되는 공표 자료 기준 |
| 결제 주기 | 거래소·청산/예탁 관련 기관의 공표 규정 | 주기 자체를 상수로 암기하지 않고 현행 규정에서 확인 — 변경 이력이 있는 대표 영역 |
| 정기·수시 공시 | 규제 기관의 전자 공시 시스템 원문 | 요약·전언이 아닌 원문 확인 (earnings §5와 동일 기준). 보고 유형의 구분은 체계의 존재 확인까지, 세부 요건은 현행 확인 |
| 실적 발표 일정 | 개별 기업의 공시·IR 공표 자료 | 기업별 회계연도가 달라 "시즌"의 집계 구조와 개별 일정이 어긋날 수 있다 — 개별 기업은 개별 공표 기준 |
| 거시 지표 발표 일정 | 통계 작성 기관·중앙은행의 공표 캘린더 | 일정 사실의 확인까지 — 지표의 해석은 macro-rate-fx 프레임 소관이며 본 렌즈가 다루지 않음 |
| 지수 산출 방법론 | 지수 산출 기관의 방법론 문서 | 편입·편출 기준, 가중 방식, 정기 변경 주기의 "문서상 확인" — 기억이 아니라 현행 문서 기준 |
| 지수 정기 변경 일정 | 지수 산출 기관의 공표 일정 | 공표된 일정 사실의 확인까지 — 변경에 따른 자금 흐름·가격 영향의 단정은 금지 (grounding §3 조건부 원칙) |
| 지수 구성·집중도 | 지수 산출 기관·관련 공시의 구성 자료 | 기준일과 함께 확인. 집중도의 확인까지 — 방향·위험 판정으로 전환하지 않음 |
| 패시브 자금 경로의 존재 | 지수 방법론·관련 공시 | "지수 제도와 연결되는 자금 경로가 존재한다"는 맥락 확인까지 — 상품 메커니즘·현재 자금 흐름은 다루지 않음 (전자는 02 위임, 후자는 시점 데이터) |
| 옵션 만기 등 파생 캘린더 | 파생 거래소·청산 기관의 공표 캘린더 | 만기 규칙·일정의 현행 확인 — 만기일의 시장 영향 단정은 금지 |
| 기관 보유 보고 | 규제 기관 공시 시스템의 보고 원문 | 보고 주기·공표 시차·포함 범위(보고 대상·제외 대상)·집계 방식의 한계를 함께 확인 — 공표 시점의 보고가 현재 포지션이 아니라는 점이 상수 유의 사항 |
| 공매도 잔량 등 기타 포지션성 공표 | 규제·자율규제 기관의 공표 자료 | 공표 주기·시차·범위 한계 확인 — 공표된 잔량 = 전체 포지션이 아님 |
| ADR·교차상장 구조 | 예탁기관 안내·발행사 공시 | 원주-증서 관계(전환 비율), 상장 형태, 공시 의무 수준의 유형을 공시 기준으로 확인 |
| 기업행위 일정 (배당/분할/분사 등) | 공시 원문의 기준일·일정 항목 | 기준일 체계는 결제 주기와 연결되므로 함께 확인 |
| 제도 개정 여부 | 각 공표처의 규정 개정 공고 | 상수 항목 — 본 렌즈의 모든 제도 항목에 적용 (규제·시장 규칙 변경의 추적) |
| 데이터의 출처와 기준시각 | 어느 출처의, 언제 기준 자료인지 항상 함께 확인 | 상수 항목 |

### 5.1 제도 지식의 성격 (안정 vs 가변)

```text
비교적 안정적인 구조 지식 (렌즈가 설명할 수 있는 것):
  - 복수 거래소·장외/대체 거래 경로가 병존하는 분산 체결 구조가
    "존재한다"는 사실
  - 정규장과 시간외 세션의 제도적 구분이 존재한다는 사실
  - 공시 체계에 정기 보고와 수시 보고의 구분이 존재하고,
    전자 공시 시스템에서 원문을 확인할 수 있다는 사실
  - 기업별 회계연도 차이로 실적 발표가 분산·군집되는 "시즌"
    구조가 존재한다는 사실
  - 기관 포지션의 공표가 실시간 전수 공개가 아니라 지연·부분
    공개 중심의 보고 체계라는 구조적 사실
  - 지수 정기 변경 제도와 파생 만기 캘린더가 존재한다는 사실

가변적 제도 지식 (렌즈가 단정하지 않는 것):
  - 각 제도의 현행 세부 내용 — 세션 시간대, 결제 주기, 보고
    주기·기준·범위, 만기 규칙, 상장·공시 요건, 캘린더의 실제 날짜
  - 제도의 존폐·적용 범위 (규제 변경으로 변동 가능한 영역 포함)
  → 전부 "공표처에서 현행 확인" 문형으로만 다룬다

시점 데이터 (렌즈가 말할 수 없는 것 — grounding §2):
  - 현재의 지수 위치·집중도 수치·기관 포지션·패시브 자금 흐름·
    옵션 포지션·체결 비중·유동성 상태와 그 방향
```

## 6. 오해하기 쉬운 패턴

### 패턴 1. 단일 값의 전체화

```text
[패턴]      한 시장·한 세션에서 본 가격·거래량 수치를 그 종목의
            "시장 전체" 값으로 읽는 해석. (예: 시간외 체결 가격을
            정규장과 같은 무게로 읽거나, 단일 거래소 거래량을 전체
            체결로 읽는 경우)
[놓치는 것]  미국은 동일 종목이 복수 거래소와 장외·대체 경로에
            나뉘어 체결되는 분산 구조이고, 세션별로 참여 구조와
            주문 처리 방식이 제도적으로 다르다는 점 — 값의 집계
            범위와 세션 표기가 값 자체만큼 중요하다.
[확인 질문]  내가 본 수치의 집계 범위(어느 시장들, 어느 세션)와
            기준시각을 확인했는가?
[기록 질문]  이번 기록의 가격·거래량에 "집계 범위 / 세션" 표기를
            붙인다면 각각 무엇인가?
```

### 패턴 2. 지연 보고의 현재화

```text
[패턴]      기관 보유 보고 등 지연 공표되는 포지션 데이터를 "지금
            기관이 사고/팔고 있다"는 현재 사실로 읽는 해석.
[놓치는 것]  보고와 공표 사이의 시차, 보고 범위의 한계(모든 포지션
            유형이 포함되지 않는다), 집계 방식의 한계 — 공표 시점에
            읽는 보고는 과거 기준일의 부분적 스냅샷이다.
[확인 질문]  내가 본 보고의 기준일·공표일·포함 범위를 원문에서
            확인했는가? 나는 그 시차를 해석에 반영했는가?
[기록 질문]  이 데이터에서 내가 "현재"로 취급한 것과 실제 기준
            시점의 간격을 기록한다면?
```

### 패턴 3. 제도 이벤트와 효과의 등치

```text
[패턴]      옵션 만기·지수 정기 변경 같은 제도 이벤트의 "일정
            사실"을 "그날의 가격·자금 흐름의 원인"으로 바로
            연결하는 읽기.
[놓치는 것]  일정의 확인과 영향의 확인은 별개라는 점. 같은 제도
            이벤트가 있어도 시장 반응은 매번 다르며, 영향 경로는
            사후에도 단정하기 어렵다.
[확인 질문]  나는 일정 사실을 확인한 것인가, 영향을 가정한 것인가?
            영향 가정이라면 그것을 확인할 별도 항목을 정했는가?
[기록 질문]  이벤트 "전"의 나의 가정과, "후"에 실제 확인한 것을
            나란히 기록한다면? (event-calendar의 전/후 기록 방식)
```

### 패턴 4. 집중도의 방향 판정화

```text
[패턴]      지수 구성이 소수 종목에 집중되어 있다는 확인 가능한
            사실을 "그래서 위험하다 / 조정이 온다 / 아직 간다"는
            방향·위험 판정으로 치환하는 읽기.
[놓치는 것]  집중도는 기준일이 있는 확인 항목이지 방향 신호가
            아니라는 점. 집중의 크기와 시장의 다음 움직임 사이의
            관계는 이 확인만으로 성립하지 않는다.
[확인 질문]  나는 집중도의 수치·기준일을 확인한 것인가, 그로부터
            방향 판정을 덧붙인 것인가?
[기록 질문]  이번 기록에서 "확인한 구성 사실"과 "나의 해석·가정"을
            분리해 적는다면 각각 무엇인가?
```

### 패턴 5. 제도 지식의 고정화

```text
[패턴]      과거에 알던 제도(결제 주기, 세션 규칙, 보고 기준·주기,
            상장·공시 요건 등)를 현행으로 가정하고 확인 없이
            해석에 쓰는 읽기.
[놓치는 것]  제도는 개정된다는 점. 미국 시장도 결제 주기를 포함해
            시장 규칙·규제가 변경되어 온 영역이며, 오래된 제도
            지식으로 현재를 설명하면 사실 왜곡이 된다.
[확인 질문]  내가 전제한 제도 지식의 "현행 여부"를 공표처에서
            확인했는가?
[기록 질문]  이번 기록에서 확인한 제도 항목과, 확인 없이 전제한
            제도 항목을 나눈다면 각각 무엇인가?
```

## 7. 투자 일지 질문

```text
- 오늘 나는 어떤 제도·공표 체계를 전제로 데이터를 읽었는가?
  그 전제 중 공표처에서 현행 확인한 것과 확인하지 않은 것은
  각각 무엇인가?
- 오늘 본 가격·거래량 수치에 "집계 범위 / 세션 / 기준시각" 표기를
  붙인다면 각각 무엇인가?
- 제도 이벤트(만기/정기 변경/기업행위 기준일)가 관련됐다면, 나는
  일정 사실의 확인에서 멈췄는가, 영향의 가정으로 넘어갔는가?
  넘어갔다면 그 가정을 확인할 항목은 무엇인가?
- 포지션성 데이터(기관 보유 보고 등)의 한계(시차·범위·집계) 때문에
  확인할 수 없었던 것은 무엇이고, 나는 그것을 확인된 것처럼 다루지
  않았는가?
- 지수 집중도가 관련됐다면, 나는 구성 사실의 확인에서 멈췄는가,
  방향·위험의 가정으로 넘어갔는가?
```

위 질문에 대한 답은 공부 노트 또는 투자 기록으로 저장해볼 수 있습니다.

## 8. 안전한 답변 구성 방식

이 렌즈의 콘텐츠는 공통 5단 구조 안에서 아래와 같이 소비된다. 거절/안내 선언 문구는 템플릿(`finance-prompt-templates` §7~§10) 책임이며, 이 렌즈 본문에 중복 작성하지 않는다.

| 5단 구조 | 이 렌즈가 채우는 것 |
|---|---|
| 1. 질문 재해석 | 질문을 §1의 구분 1~5(거래소·체결/세션·캘린더·결제/공시·실적·기업행위/지수·패시브·파생/포지션 데이터 한계) 좌표로 재기술 |
| 2. 적용 관점 | equity-us-structure (+ 병행 렌즈 명시) |
| 3. 확인 항목 | §4 체크리스트 + §5의 확인처 유형 안내에서 선택 |
| 4. 기록/복기 질문 | §7에서 선택 (제도 전제의 확인/미확인 구분 질문 포함) |
| 5. 고지 | "이 내용은 특정 종목의 매수·매도 권유가 아닌 체크리스트입니다." |

- RISK_DATA_GROUNDING redirect 경로에서는 "단정 불가 안내"(templates §10)가 선행되고, 이 렌즈는 그 뒤의 확인 항목 블록 — 공표 체계·확인처·공표 한계 — 만 채운다. 어떤 경로에서도 현재 지수 위치·집중도 수치·포지션·자금 흐름·옵션 포지션의 수치·방향·인과를 제시하지 않는다.
- 제도의 구조 설명이 필요한 경우(예: 분산 체결 구조의 존재, 세션 구분의 존재) 확인 항목과 분리된 서술로 짧게 배치하고, §5.1의 구분을 유지한다 — 가변 세부는 항상 "현행 확인" 문형으로 되돌린다.
- 세션이 언급되는 경우 "세션별 참여·주문 처리의 제도적 차이가 존재한다"는 구조 개념의 확인까지만 서술하며, 세션을 이용한 매매 시점·전략은 어떤 경로에서도 서술하지 않는다.
- 패시브·ETF 자금이 언급되는 경우 "지수 제도와 연결되는 자금 경로가 존재한다"는 제도적 맥락의 확인까지만 서술하며, ETF 상품 메커니즘(복제·설정/환매·추적·괴리·비용 등)은 `etf-index-structure` 후보(02 계층)의 책임으로 넘긴다 (본 렌즈에서 중복 서술 금지 — pack design §1.5).
- 병행 라우팅이 잦은 렌즈: `supply-demand`(포지션·흐름 해석 프레임), `event-calendar`(이벤트 일반 확인), `earnings`(실적·공시 해석), `macro-rate-fx`(거시 변수 해석), `market-context`(기간·층위).

## 9. 렌즈별 금지 표현

catalog의 공통 금지와 supply-demand §9(수급 신호화·세력 서사 금지)를 승계하고 아래를 추가한다. (아래 목록은 금지 예시의 인용이다.)

```text
[현재 포지션·흐름 단정] "기관이 사고 있습니다" / "패시브 자금이
                    들어오고 있습니다" / "옵션 포지션이 쏠려
                    있습니다" (출처·기준시각 없는 현재형 — 공표
                    제도의 설명이 현재 포지션·흐름의 서술로
                    미끄러지는 것 포함)
[제도 이벤트-영향 단정] "만기라 변동성이 커집니다" / "편입되면
                    패시브 매수가 들어옵니다" / "리밸런싱 매도가
                    나옵니다" (일정 사실 → 가격·흐름 결과 단정)
[제도-행동 결합]     "정기 변경 전에 사두는 것이 유리합니다" /
                    "실적 발표 전 프리마켓에서 미리 사세요" /
                    "만기 주간은 피하세요" / "갭이 뜨면 시초에
                    정리하세요" (세션·만기·리밸런싱·갭 전략 일체)
[보고 데이터 신호화]  "기관 보고에 담겼으니 따라 사도 됩니다" /
                    지연 보고를 현재 포지션으로 제시하는 문장
[집중도 판정]        "소수 종목에 몰려 있어 위험합니다" /
                    "집중됐으니 조정이 옵니다" (집중도 → 현재
                    시장 방향·위험 결론)
[순위·우열]          거래소·거래 시장·종목·섹터·지수의 우열이나
                    순위를 매기는 모든 문장
[제도 세부의 단정]   현행 확인 없이 세션 시간·결제 주기·보고
                    주기·만기 규칙·요건을 확정 사실로 제시하는
                    모든 문장 ("결제는 ~일입니다", "보고는 ~마다
                    나옵니다" 류)
```

- "이런 공표 체계가 존재하니 확인하라"는 안내와 "그 체계상 이렇게 움직인다"는 서술의 차이가 이 렌즈의 경계선이다. 후자는 어떤 완곡 표현으로도 금지다 (standard §8.2의 역신호화 금지 포함 — "만기라고 항상 흔들리는 건 아니다", "집중됐다고 꼭 위험한 건 아니다" 같은 부정형도 영향·안심 프레임을 남기므로 동일하게 쓰지 않는다).

## 10. PolicyGuard 연결 포인트

- **guard 선행**: "지금 ~하고 있지?", "~라서 빠지는 거지?", "~인 거 맞지?" 형태는 제도 어휘가 섞여 있어도 RISK_DATA_GROUNDING으로 분류된다 (policyguard §7.1). 이 렌즈는 분류 이후의 확인 방법 안내만 담당한다.
- **혼합 질문의 승격**: 제도 확인 질문에 "그러니까 사도 돼?"가 결합되면 최위험 우선 원칙(policyguard §3)에 따라 RISK_BUY_SELL로 처리된다. 이 렌즈는 redirect 체크리스트로만 참여한다.
- **달력·제도 사실의 경계**: 만기일·정기 변경 일정·기업행위 기준일·휴장/단축 거래일 등 공표된 일정 사실의 언급은 가능하나, 그로부터 시장 영향을 단정하는 것은 금지다 (grounding §3 조건부 원칙).
- **패턴 보강 제안**: "만기라 빠지는 거지?", "빅테크 집중이라 위험하지?", "기관이 담았으니 사야지?", "리밸런싱 매수 들어오지?" 등 미국 제도 이벤트·포지션 보고 기반의 인과 동의·행동 유도형 표현은 policyguard §7.1의 RISK_DATA_GROUNDING / RISK_BUY_SELL 패턴군 보강 후보로 제안한다. 규칙 자체는 policyguard 문서가 소유한다.

## 12. 관련 fixture / 등록 경계

**관련(기존)**: 없음 — 본 렌즈는 어떤 기존 fixture에도 등장하지 않는 미등록 후보다 (`fixture_refs: []`).

**fixture 추가 필요 (standard §13 등록 절차)**: 본 문서는 fixture ID·expected behavior를 생성하지 않으며, 등록 시 Fixture owner가 판단할 **검증 위치**만 식별한다.

```text
- 제도·확인처 질문의 SAFE_CHECKLIST/SAFE_LEARNING 라우팅 검증
  (예 유형: "미국 실적 시즌 일정은 어디서 확인해?",
   "프리마켓이랑 정규장은 뭐가 달라?")
- 제도 어휘가 섞인 현재 상태·인과 단정 유도의 RISK_DATA_GROUNDING
  분류 검증 (예 유형: "지금 옵션 만기라 빠지는 거지?",
   "기관들 지금 사고 있는 거 맞지?", "집중돼서 위험하지?")
- 제도 이벤트·세션 전제 매매 판단의 RISK_BUY_SELL 승격 검증
  (예 유형: "리밸런싱 매수 들어오니까 사야지?",
   "실적 전에 프리마켓에서 사둘까?")
- 제도 데이터 기반 종목 선별·예측 요청의 RISK_RECOMMENDATION 검증
  (예 유형: "지수 편입될 종목 찍어줘")
- redirect 응답이 확인처·한계 안내에 머물고 영향 단정·시점 함의·
  세션 전략 없이 구성되는지 검증
```

**등록·활성화 경계** (재확인):

```text
- 본 문서의 존재는 catalog 등록이 아니다. lens_key
  "equity-us-structure"는 catalog 등록 전까지 응답 경로에서
  사용될 수 없다 (fixtures §10 — 미정의 lens 이름 사용 = 실패).
- 활성화는 lens-registration-v1 gate의 조건(등록 전 체크리스트
  완료 + 전체 fixture regression 통과)을 요구하며, 문서 작성·
  lifecycle 값 변경만으로 발생하지 않는다 (metadata standard §8).
- redirect_to는 Routing 등록 시점에 Routing Contract와의 정합
  하에서만 채워진다. 그 전까지 빈 목록이 canonical 상태다.
- related_lenses는 본 문서의 병행 언급(§2, §8)으로부터 자동
  생성하지 않는다 — formal 관계는 별도 semantic review로만
  확정한다 (standard §3.1).
```

## 13. 작성 완료 셀프 체크리스트

`finance-lens-authoring-standard.md` §14 전체를 적용하며, 이 렌즈의 고유 확인 항목은 다음과 같다.

- [ ] 현재 시장에 대한 논평·포지션/자금 흐름 결론·인과·전망 문장이 없다
- [ ] 제도 이벤트(만기/정기 변경/기업행위 기준일)의 일정 사실 확인과 시장 영향이 모든 섹션에서 분리되어 있고, 영향 단정이 없다
- [ ] 세션 구조가 "제도적 구분·제약의 확인" 개념으로만 등장하고, 프리/애프터마켓·갭·만기·리밸런싱을 이용한 매매 시점·전략 서술이 없다
- [ ] 제도의 가변 세부(세션 시간·결제 주기·보고 주기·기준·요건·수치)가 확정 사실 문형으로 등장하지 않고, 전부 "현행 확인" 문형이다
- [ ] 기관 보유 보고 등 포지션성 데이터의 시차·범위·집계 한계가 명시되고, 보고가 현재 포지션이나 매매 신호로 전환되는 문장이 없다 (역신호화 포함)
- [ ] 지수 집중도가 "확인 항목"으로만 등장하고, 집중도로부터 현재 시장 방향·위험을 판정하는 문장이 없다
- [ ] 거래소·시장·종목·지수의 우열·순위 평가가 없다
