## 1. 렌즈 목적

**시점성 이벤트에 대한 질문을 "무엇이, 언제, 확정인지, 나와 어떤 경로로 관련된다고 생각하는지"를 확인하는 관점으로 구조화한다.**

```text
구분 1. 이벤트 식별  — 어떤 이벤트인가 (통화정책 / 지표 발표 / 만기 /
                      리밸런싱 / 지수 편출입 / 실적 / 배당락)
구분 2. 일정 확정성  — 공표된 확정 일정인가, 추정인가
구분 3. 시간 좌표    — 어느 시간대 기준의 언제인가 (해외 이벤트 주의)
구분 4. 관련 경로    — 이 이벤트가 내 관심 자산과 관련된다고 "내가"
                      생각하는 경로는 무엇인가 (기록 대상)
```

- 이 렌즈는 이벤트의 시장 영향을 **전망하지 않는다.** 일정이라는 달력 사실을 확인하게 하고, 영향 경로에 대한 사용자의 가설을 기록으로 전환하는 것까지가 책임이다.

## 2. 이 렌즈가 다루는 질문

| 안전 질문 예시 | 병행 렌즈 | 근거 |
|---|---|---|
| "월말 리밸런싱이 뭐야?" | supply-demand | SF-02 — 개념 질문 + 시점성 이벤트 (SAFE_LEARNING 연결) |
| "실적 발표 전에 뭘 봐야 해?" | earnings | SF-03 — 실적 관점 + 일정 확인 |
| "옵션만기 때는 뭘 확인하면서 보는 거야?" | supply-demand | 확인 방법 요청 |
| "이벤트 일정은 어디서 확인해?" | (단독 가능) | 확인처 안내 요청 |

---

## 3. 이 렌즈가 다루지 않는 질문

아래 질문은 이 렌즈가 답하지 않는다. Input Guard가 먼저 분류하고, 거절/안내 선언 이후에만 이 렌즈의 확인 항목이 redirect로 제공된다.

| 질문 | intent | 처리 |
|---|---|---|
| "옵션만기 전에 정리해두는 게 낫지?" | RISK_BUY_SELL | REDIRECT_TO_CHECKLIST — 거절 선언 선행 |
| "FOMC 전에 사둘까, 결과 보고 살까?" | RISK_BUY_SELL | 동일 — **시점 선택도 매매 판단이다** |
| "지금 리밸런싱 매도 나오고 있는 거지?" | RISK_DATA_GROUNDING | 단정 불가 안내 + 확인 방법 (supply-demand 병행) |
| "이번 CPI 잘 나올까?" | RISK_DATA_GROUNDING | 결과 전망 단정 금지 + 일정/확인 항목 안내 |
| "이번 주 FOMC 언제야?" | RISK_DATA_GROUNDING | Phase 1에는 일정 데이터 미연결 — 미확인 날짜를 사실로 제시하지 않고 공식 확인처 안내 (grounding §3) |

## 4. 판단 전 체크리스트

```text
- 이번 주/이번 달에 예정된 이벤트 중 내가 확인한 것은 무엇인가?
  어느 공식 출처에서 확인했는가?
- 그 일정은 공표된 확정 사실인가, 언론·커뮤니티발 추정인가?
- 해외 이벤트라면 어느 시간대 기준의 일정인지 확인했는가?
- 이 이벤트가 내 관심 자산과 관련된다고 생각하는 경로를
  한 문장으로 적을 수 있는가? 적지 못한다면 무엇을 더
  확인해야 하는가?
- 이벤트의 "발표일"과 그에 따른 "실행일"(예: 지수 편출입의
  리밸런싱 기준일)이 서로 다른 날짜인지 확인했는가?
- 이벤트 전후로 내가 확인할 데이터 항목을 미리 정해뒀는가?
- 과거 같은 유형의 이벤트 때 나는 무엇을 확인하고
  기록했는가? (기록 열람)
```

## 5. 확인할 데이터

Phase 1에는 일정 데이터가 연결되어 있지 않으므로, 아래는 **사용자가 직접 확인할 항목과 출처 유형**이다. 이 렌즈의 확인 대상은 대부분 달력 사실이며, **달력 사실의 확인과 그로부터의 시장 영향 단정은 분리한다** (grounding §3).

| 확인 항목 | 확인 방법 (출처 유형) | 유의 |
|---|---|---|
| 통화정책 일정 (FOMC/금통위) | 각 중앙은행이 공표하는 연간 회의 일정 | 결과 발표 시각과 시간대를 함께 확인 |
| 경제지표 발표 일정 (CPI 등) | 해당 통계 작성·발표 기관의 공식 일정 | 발표 주기와 기준 시점(몇 월분 지표인지) 확인 |
| 옵션/선물 만기일 | 거래소가 공표하는 파생상품 만기 일정 | 국내/해외 만기가 겹치는 주간인지 확인 |
| 월말/분기말 여부 | 달력 | 달력 사실 확인까지만 — "그래서 매도가 나온다"는 별개의 미확인 주장 |
| 지수 편출입 일정 | 지수 산출기관의 공식 발표 | 발표일·리뷰 기준일·리밸런싱 실행일이 서로 다른 날짜임을 확인 |
| 실적 발표 일정 | 공시/기업 IR 공식 일정 | 확정 공시 전 일정은 추정일 수 있다 — 확정 여부 표기 확인 |
| 배당 기준일/배당락일 | 공시·거래소 안내 | 기준일과 배당락일의 관계는 개념(SAFE_LEARNING)으로 확인 |
| 데이터의 출처와 기준시각 | 어느 출처의, 언제 기준 정보인지 항상 함께 확인 | 상수 항목 — 지난해 일정으로 올해를 추정하지 않는다 |

## 6. 오해하기 쉬운 패턴

### 패턴 1. 일정 사실과 방향 단정의 혼동

```text
[패턴]      "이벤트가 있다"는 달력 사실에서 곧바로 "그래서 시장이
            이렇게 움직인다"는 방향 결론으로 건너뛰는 해석.
[놓치는 것]  일정의 확인과 영향의 판단이 별개의 단계라는 점.
            일정은 확인 가능한 사실이지만, 방향은 미확인 주장이다.
[확인 질문]  나는 지금 "일정"을 확인한 것인가, "영향"을 가정한
            것인가? 둘을 구분해서 적을 수 있는가?
[기록 질문]  이 이벤트에 대해 사실로 확인한 것과 내가 가정한 것을
            나눠서 기록한다면 각각 무엇인가?
```

### 패턴 2. 사후 소급 귀속

```text
[패턴]      이벤트 이후의 가격 움직임을 전부 그 이벤트의 결과로
            돌리는 해석.
[놓치는 것]  같은 기간에 있었던 다른 요인들과, 이벤트 이전에 이미
            나타난 움직임의 존재 여부.
[확인 질문]  이벤트 전후 구간을 나눠서 확인했는가? 같은 기간의
            다른 이벤트/요인 목록을 확인했는가?
[기록 질문]  나는 이 움직임의 원인으로 이 이벤트 하나만 기록했는가,
            확인한 다른 요인도 함께 기록했는가?
```

### 패턴 3. "불확실성 해소" 공식

```text
[패턴]      "이벤트만 지나가면 불확실성이 해소된다"는 통과 공식으로
            이벤트를 읽는 해석.
[놓치는 것]  "이벤트가 지나갔다"는 사실과 "이벤트 결과의 내용"이
            별개라는 점. 그 공식을 자기 기록으로 확인해본 적이
            있는지 여부.
[확인 질문]  나는 이 공식을 어디서 받아들였는가? 내 기록에서 이
            공식이 실제로 어땠는지 확인해본 적이 있는가?
[기록 질문]  이번 이벤트 전에 내가 가정한 경로를 기록해두고,
            이벤트 후 실제로 확인한 것과 나란히 남긴다면?
```

### 패턴 4. 만기일 변동성의 일반화

```text
[패턴]      만기일마다 큰 변동이 온다는 일반화로 만기 주간을
            읽는 해석.
[놓치는 것]  그 인상이 몇 번의 경험이나 전언에서 왔는지에 대한
            확인. 만기일에 확인할 구체 항목(프로그램 매매 동향 등)의
            부재.
[확인 질문]  만기일에 내가 확인하기로 정한 데이터 항목은 무엇인가?
            (막연한 경계심 대신 확인 목록이 있는가?)
[기록 질문]  이번 만기 주간에 실제로 확인한 것은 무엇이었는가?
```

### 패턴 5. 발표일과 실행일의 혼동

```text
[패턴]      지수 편출입의 "발표"와 리밸런싱 "실행"을 같은 날의
            한 이벤트로 뭉뚱그리는 해석.
[놓치는 것]  발표일, 리뷰 기준일, 실행일이 서로 다른 날짜라는 점과
            각 날짜에 확인할 항목이 다르다는 점.
[확인 질문]  이 이벤트의 발표일과 실행일을 공식 출처에서 각각
            확인했는가?
[기록 질문]  나는 어느 날짜를 기준으로 이 이벤트를 기록하고
            있는가?
```

## 7. 투자 일지 질문

```text
- 이번 주/이번 달 이벤트 중 내가 확인한 일정과 그 출처는
  무엇인가? (확정/추정 구분과 함께)
- 이 이벤트가 내 관심 자산과 관련된다고 생각한 경로를
  한 문장으로 기록한다면?
- 이벤트 전에 정한 확인 항목과, 이벤트 후 실제로 확인한 것은
  각각 무엇인가? (전/후를 나란히 기록)
- 이벤트를 앞둔 지금의 감정을 한 단어로 기록한다면?
  (예: 불안, 기대, 무관심)
```

위 질문에 대한 답은 공부 노트 또는 투자 기록으로 저장해볼 수 있습니다.

## 8. 안전한 답변 구성 방식

이 렌즈의 콘텐츠는 공통 5단 구조 안에서 아래와 같이 소비된다. 거절/안내 선언 문구는 템플릿(`finance-prompt-templates` §7~§10) 책임이며, 이 렌즈 본문에 중복 작성하지 않는다.

| 5단 구조 | 이 렌즈가 채우는 것 |
|---|---|
| 1. 질문 재해석 | 질문을 §1의 구분 1~4(식별/확정성/시간 좌표/관련 경로)로 재기술 |
| 2. 적용 관점 | event-calendar (+ 병행 렌즈 명시) |
| 3. 확인 항목 | §4 체크리스트 + §5의 출처 유형 안내에서 선택 |
| 4. 기록/복기 질문 | §7에서 선택 (특히 "전/후 나란히 기록" 질문) |
| 5. 고지 | "이 내용은 특정 종목의 매수·매도 권유가 아닌 체크리스트입니다." |

- 개념 질문(SF-02 등)에서는 SAFE_LEARNING 템플릿(templates §5)의 "체크리스트로 바꾸면" 블록을 이 렌즈가 채운다. 개념 설명은 일반론까지만 쓰고, 시점 판단으로 확장하지 않는다.
- 일정 사실 확인 질문이 RISK_DATA_GROUNDING으로 분류된 경우, "단정 불가 안내"(templates §10)가 선행되고 이 렌즈는 공식 확인처 안내 블록만 채운다. 미확인 날짜를 사실로 제시하지 않는다.
- 병행 라우팅이 잦은 렌즈: `supply-demand`(리밸런싱/만기 수급), `earnings`(실적 일정), `emotion-check`(이벤트 전 불안 신호).

## 9. 렌즈별 금지 표현

catalog §3.4의 금지 표현을 승계하고 아래를 추가한다. **이 렌즈의 어떤 문장도 이벤트를 매매 타이밍 도구로 변환할 수 없다.** (아래 목록은 금지 예시의 인용이다.)

```text
[시점-행동 공식]   "이벤트 전에는 피하는 것이 좋습니다"
                  / "이벤트 전에 사두세요 / 팔아두세요"
                  / "결과 보고 들어가는 것이 안전합니다"
[통과 공식]       "불확실성 해소 후 상승이 일반적입니다"
                  / "이벤트만 지나가면 오릅니다"
[결과 전망]       "이번 CPI는 잘 나올 것입니다"
                  / "동결이 유력합니다" / "서프라이즈가 예상됩니다"
[영향 단정]       "리밸런싱 매도가 나오고 있습니다"
                  / "만기 때문에 흔들리는 것입니다"
[만기 일반화]      "만기일에는 변동성이 커지므로 조심해야 합니다"
[일정 단정]       (미확인 날짜를 확정 사실처럼 제시하는 모든 문장)
[전략 프레이밍]    "이벤트 매매 전략" / "이벤트 드리븐 접근을
                  추천합니다"
```

- "일정을 확인하라"는 안내와 "일정에 맞춰 행동하라"는 서술의 차이가 이 렌즈의 경계선이다. 후자는 어떤 완곡 표현으로도 금지다 (standard §8.2).

## 10. PolicyGuard 연결 포인트

- **guard 선행**: "만기 전에 정리할까?"처럼 이벤트가 매매 판단 요청의 배경으로 쓰인 질문은 RISK_BUY_SELL로 분류된다. "언제 살까/팔까"의 **시점 선택 질문도 매매 판단 요청**이며, 이 렌즈는 거절 선언 이후의 확인 항목으로만 참여한다.
- **일정 사실 질문의 처리**: "이번 주 FOMC 언제야?"류는 달력 사실 확인 요구이나, Phase 1의 서비스는 일정 데이터를 보유하지 않으므로 미확인 날짜 제시 없이 공식 확인처 안내로 처리한다 (grounding §3의 "실적 발표 일정 ⚠️ 조건부"와 동일 기준). 데이터 연결(Phase 1.5+) 이후에도 출처·기준시각 표기가 전제되며, 그때에도 영향 단정은 금지된다.
- **패턴 보강 제안**: "~전에 들어갈까/나올까", "결과 보고 살까" 등 이벤트-시점 결합형 판단 요청 표현은 policyguard §7.1의 RISK_BUY_SELL 패턴군 보강 후보로 제안한다. 규칙 자체는 policyguard 문서가 소유한다.

## 13. 작성 완료 셀프 체크리스트

`finance-lens-authoring-standard.md` §14 전체를 적용하며, 이 렌즈의 고유 확인 항목은 다음과 같다.

- [ ] "일정 확인(달력 사실)"과 "방향 영향(미확인 주장)"이 모든 섹션에서 분리되어 있다
- [ ] 이벤트를 매매 타이밍 도구로 쓰는 문장이 없다 ("전에 피해라 / 후가 기회다 / 불확실성 해소 후 상승" 및 완곡 변형 포함)
- [ ] 미확인 날짜·결과 전망을 사실로 제시하는 문장이 없다
- [ ] 발표일/기준일/실행일 구분이 확인 항목으로만 서술되고, 특정 날짜의 행동 함의로 이어지지 않는다
- [ ] 오해 패턴 5개가 모두 4부 구조이며, 어느 패턴의 부정도 행동 함의로 읽히지 않는다
- [ ] 위험 질문은 §0 forbidden intent와 §3에만 등장하고, 렌즈가 직접 답하는 서술이 없다
- [ ] 어떤 문장도 단독 인용 시 "무엇을 하라"로 읽히지 않는다
