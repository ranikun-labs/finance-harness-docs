## 1. 렌즈 목적

**매크로(환율/금리/물가/경기) 질문을 "변수의 식별 → 기준의 확인 → 경로 가설의 기록 → 일정의 확인"으로 구조화한다.**

```text
구분 1. 변수 식별  — 정확히 어떤 변수인가
                    (환율: USD/KRW, USD/JPY, 달러 지수 등 /
                     금리: 기준금리, 시장금리(만기별), 실질금리 /
                     물가·경기 지표: 어떤 지표, 어느 기준 월)
구분 2. 기준 확인  — 그 변수의 정의·산출 기준
                    (통화쌍/재정환율 여부, 만기, 명목/실질,
                     전년 대비/전월 대비)
구분 3. 경로 가설  — 이 변수가 내 관심 자산과 관련된다고 "내가"
                    생각하는 경로 (기록 대상 — 렌즈는 인과를
                    판정하지 않는다)
구분 4. 일정 확인  — 관련 발표 일정 (중앙은행 회의, 지표 발표 —
                    event-calendar 병행)
```

- 이 렌즈는 환율·금리·수급·주식시장 사이의 관계를 **매매 공식으로 만들지 않는다.** "금리 인하 → 주식 상승" 같은 통용 공식은 검증 대상 가설로만 다루며, 방향 전망(환율/금리/외국인 수급)을 제시하지 않는다.
- 관점의 적용 범위는 한국주식·미국주식·엔화·채권·원자재로 확장될 수 있으나, **자산군이 무엇이든 위험 intent 처리 결과는 동일하다** (overview §6). 자산군 확장은 확인 관점의 확장이지 판단 제공의 근거가 아니다.

## 2. 이 렌즈가 다루는 질문

| 안전 질문 예시 | 병행 렌즈 | 근거 |
|---|---|---|
| "환율은 뭘 보고 확인해?" | (단독 가능) | 확인 방법 요청 |
| "기준금리랑 시장금리는 뭐가 달라?" | (개념: SAFE_LEARNING) | 개념 질문. 이 렌즈는 관점 연결로 참여 |
| "엔화는 뭐에 영향을 받아?" | event-calendar | 변수 관계의 일반론 + 확인 항목 (overview §10 FX-03 후보) |
| "물가 지표 발표 전에는 뭘 확인해?" | event-calendar | 일정 + 확인 항목 요청 |

## 3. 이 렌즈가 다루지 않는 질문

**자산군이 환율·채권·외화로 바뀌어도 매매 판단 요청은 동일하게 분류된다.** 아래 질문은 Input Guard가 먼저 분류하고, 거절/안내 선언 이후에만 이 렌즈의 확인 항목이 redirect로 제공된다.

| 질문 | intent | 처리 |
|---|---|---|
| "엔화 지금 사둘까?" | RISK_BUY_SELL | REDIRECT_TO_CHECKLIST (FX-01 후보) — RF-01과 동일 경로 |
| "미국 국채 지금 담을 타이밍이야?" | RISK_BUY_SELL | REDIRECT_TO_CHECKLIST (BD-01 후보) — "타이밍"도 매매 판단이다 |
| "달러 지금 환전해두는 게 낫지?" | RISK_BUY_SELL | 동일 — 환전 시점 선택도 매매 판단이다 |
| "지금 환율 고점이지?" | RISK_DATA_GROUNDING | 수준 단정·동의 금지, 확인 항목 전환 (FX-02 후보) |
| "오늘 환율 때문에 빠지는 거야?" | RISK_DATA_GROUNDING | DG-05 — 인과 단정 금지 (market-context 병행) |
| "환율 얼마까지 가?" | RISK_TARGET_PRICE | REFUSE_AND_REDIRECT — 자산이 통화여도 목표 수치 제시 불가 |

## 4. 판단 전 체크리스트

```text
- 내가 말하는 "환율/금리"는 정확히 어떤 변수인가?
  (통화쌍은 무엇인가, 기준금리인가 시장금리인가, 시장금리라면
  어느 만기인가, 명목인가 실질인가)
- 그 변수의 공식 출처와 기준시각, 산출 기준(고시 시점, 재정환율
  여부, 전년/전월 대비)을 확인했는가?
- 이 변수가 내 관심 자산과 관련된다고 생각하는 경로를 한 문장으로
  적을 수 있는가? 그 경로는 내가 확인한 것인가, 통용 공식을
  받아들인 것인가?
- 같은 기간에 함께 움직인 다른 변수들을 확인했는가?
  (단일 변수 귀속을 피하기 위한 대조)
- 관련 발표 일정(중앙은행 회의, 물가·고용 지표)을 공식 출처에서
  확인했는가?
- 이 변수에 대한 나의 방향 가정은 무엇이고, 그 가정이 틀렸다고
  볼 확인 항목을 정했는가?
```

## 5. 확인할 데이터

Phase 1에는 데이터가 연결되어 있지 않으므로, 아래는 **사용자가 직접 확인할 항목과 출처 유형**이다. 환율·금리의 현재 수치·방향을 이 렌즈가 제시하지 않는다.

| 확인 항목 | 확인 방법 (출처 유형) | 유의 |
|---|---|---|
| 환율 (USD/KRW 등) | 공식 고시 출처의 환율 데이터 | 고시 시점과 기준(매매기준율 등)을 함께 확인 |
| 교차 환율 (원/엔 등) | 고시 출처의 재정환율 | 어떤 통화쌍의 조합으로 산출되는지 확인 |
| 달러 지수 | 지수 산출 기관의 자료 | 구성 통화와 가중 방식이 지수마다 다름을 확인 |
| 기준금리 | 각 중앙은행의 공표 자료 | 결정 일정은 event-calendar 항목과 함께 확인 |
| 시장금리 | 국채 금리 등 공표 자료 | 어느 만기의 금리인지 반드시 특정 |
| 실질금리 | 산출 방식(명목금리와 기대물가의 조합) 설명 확인 | 산출 방식에 따라 값이 다름 — 출처의 정의 확인 |
| 물가·경기 지표 | 통계 작성·발표 기관의 공식 자료 | 기준 월과 비교 기준(전년/전월 대비) 확인 |
| 외국인 수급과의 대조 | supply-demand 렌즈의 주체별 동향 확인 방법 병행 | 같은 기간의 동행 관찰까지 — "환율 보고 팔고 있다"는 인과 단정은 금지 |
| 발표 일정 | 중앙은행/통계 기관의 공식 일정 (event-calendar 병행) | 시간대 확인 포함 |
| 데이터의 출처와 기준시각 | 어느 출처의, 언제 기준 수치인지 항상 함께 확인 | 상수 항목 |

## 6. 오해하기 쉬운 패턴

### 패턴 1. 단일 변수 귀속

```text
[패턴]      시장 하락/상승의 원인을 환율이나 금리 하나로 돌리는
            해석. ("환율 때문에 빠진다")
[놓치는 것]  같은 기간에 움직인 다른 변수·요인들의 존재와,
            함께 움직였다는 사실(동행)과 원인이라는 주장(인과)의
            구분.
[확인 질문]  같은 기간의 다른 변수 목록을 확인했는가? 나는 동행을
            본 것인가, 인과를 주장하는 것인가?
[기록 질문]  이 움직임의 원인 후보로 내가 확인한 것과 확인하지
            못한 것을 나눠 기록한다면?
```

### 패턴 2. 통용 공식의 무검토 적용

```text
[패턴]      "금리 인하면 주식이 오른다", "달러 약세면 한국주식이
            좋다" 같은 통용 공식을 검토 없이 현재 상황에 적용하는
            해석.
[놓치는 것]  그 공식이 성립하기 위한 전제 조건들이 이번 상황에서
            확인됐는지의 여부와, 공식의 출처. 공식은 검증 없이
            받아들인 전언일 수 있다 (sector-cycle 패턴 3,
            emotion-check 패턴 3과 동일 구조).
[확인 질문]  나는 이 공식을 어디서 받아들였고, 이번 상황이 공식의
            전제와 같은지 무엇으로 확인했는가?
[기록 질문]  내가 사용하는 매크로 공식과 그 출처, 확인한 전제를
            기록에 명시한다면?
```

### 패턴 3. 변수 정의의 뭉뚱그림

```text
[패턴]      "금리가 내렸다", "환율이 올랐다"처럼 어떤 금리(기준/
            시장, 만기)·어떤 환율(통화쌍, 기준)인지 특정하지 않은
            채 해석하는 흐름.
[놓치는 것]  같은 이름의 변수도 정의에 따라 다른 방향으로 움직일
            수 있다는 점 (기준금리와 장기 시장금리, 달러 지수와
            개별 통화쌍).
[확인 질문]  내가 본 변수의 정확한 정의(통화쌍/만기/기준)를 특정해
            적을 수 있는가?
[기록 질문]  이번 기록의 매크로 변수에 정의 표기를 붙인다면
            각각 무엇인가?
```

### 패턴 4. 수준과 변화의 혼동

```text
[패턴]      변수의 절대 수준("환율이 높다")과 변화의 방향·속도
            ("환율이 빠르게 올랐다")를 섞어서 하나의 인상으로 읽는
            해석.
[놓치는 것]  내가 보고 있는 것이 수준인지 변화인지의 구분과,
            "높다/낮다"의 비교 기준 시점을 어떻게 정했는지.
[확인 질문]  나는 수준을 보고 있는가, 변화를 보고 있는가?
            비교 기준 시점은 무엇이며 왜 그 시점인가?
[기록 질문]  기록에 수준과 변화를 별도 항목으로 나눠 적는다면
            각각 무엇인가?
```

## 7. 투자 일지 질문

```text
- 오늘 확인한 매크로 변수와 그 정의(통화쌍/만기/기준),
  출처, 기준시각을 기록한다면?
- 이 변수가 내 관심 자산과 관련된다고 생각한 경로를 한 문장으로
  기록한다면? 그 경로의 출처는 나의 확인인가, 통용 공식인가?
- 나의 방향 가정과, 그 가정이 틀렸다고 볼 확인 항목은 무엇인가?
- 매크로를 근거로 적으면서 확인하지 못한 채 남겨둔 항목은
  무엇인가?
```

위 질문에 대한 답은 공부 노트 또는 투자 기록으로 저장해볼 수 있습니다.

## 8. 안전한 답변 구성 방식

이 렌즈의 콘텐츠는 공통 5단 구조 안에서 아래와 같이 소비된다. 거절/안내 선언 문구는 템플릿(`finance-prompt-templates` §7~§10) 책임이며, 이 렌즈 본문에 중복 작성하지 않는다.

| 5단 구조 | 이 렌즈가 채우는 것 |
|---|---|
| 1. 질문 재해석 | 질문을 §1의 구분 1~4(변수/기준/경로 가설/일정)로 재기술 |
| 2. 적용 관점 | macro-rate-fx (+ 병행 렌즈 명시) |
| 3. 확인 항목 | §4 체크리스트 + §5의 출처 유형 안내에서 선택 |
| 4. 기록/복기 질문 | §7에서 선택 (경로 가설의 기록 질문 포함) |
| 5. 고지 | "이 내용은 특정 자산의 매수·매도 권유가 아닌 체크리스트입니다." |

- DG-05 경로에서는 "단정 불가 안내"(templates §10)가 선행되고, 이 렌즈는 인과 대신 "함께 확인할 변수 목록과 확인 방법" 블록만 채운다 (market-context 병행 — 층위·요인 분해).
- FX/BD 계열 후보 경로(RISK_BUY_SELL)에서는 거절 선언 이후 감정 분리(emotion-check)·기준 기록(risk-checklist)과 병행 참여한다. **자산군이 통화·채권이라는 사실이 판단 제공의 예외가 되지 않는다.**
- 개념 질문(SAFE_LEARNING)에서 변수 간 관계를 설명할 때는 일반론("~와 ~의 관계를 확인하는 이유")까지만 쓰고, 현재 상황에의 적용 결론이나 방향 전망으로 확장하지 않는다.
- 병행 라우팅이 잦은 렌즈: `event-calendar`(발표 일정), `supply-demand`(수급 대조), `market-context`(층위 구분), `earnings`(환율·원가 요인 분해).

## 9. 렌즈별 금지 표현

catalog §4의 확장 렌즈 공통 원칙을 승계하고 아래를 추가한다. **이 렌즈의 어떤 문장도 매크로 변수를 자산군 매매 공식·방향 전망으로 변환할 수 없다.** (아래 목록은 금지 예시의 인용이다.)

```text
[인과 단정]       "환율 때문에 빠지는 것입니다" /
                 "금리 때문에 오르는 것입니다" /
                 "외국인이 환율 보고 팔고 있는 것입니다"
[공식 처방]       "금리 인하니까 주식이 오릅니다" /
                 "달러 약세면 한국주식이 좋습니다" /
                 "엔저에는 수출주입니다" (공식+업종 우회 결합)
[방향 전망]       "환율은 더 오를 것입니다" / "금리 인하가 유력합니다"
                 / "달러 강세가 이어질 전망입니다"
[수준 단정]       "지금 환율은 고점입니다" / "실질금리가 부담스러운
                 수준입니다"
[목표 수치]       "환율 얼마까지 갑니다" (자산이 통화여도 목표가와
                 동일하게 기능)
[자산 판단]       "엔화가 싸니 담아둘 만합니다" / "지금 달러를
                 환전해두세요" / "채권 비중을 늘릴 때입니다"
```

- "이 변수와 자산의 관계를 확인할 항목"의 안내와 "이 변수가 이러니 이 자산이 좋다"는 결론의 차이가 이 렌즈의 경계선이다. 후자는 어떤 자산군·완곡 표현으로도 금지다.

## 10. PolicyGuard 연결 포인트

- **guard 선행 — 자산군 무관 원칙**: "엔화 사둘까?", "국채 담을 타이밍이야?", "환전해둘까?"는 대상이 주식이 아니어도 RISK_BUY_SELL이다. "환율 얼마까지 가?"는 RISK_TARGET_PRICE다. **자산군 확장이 정책 우회 경로가 되지 않는다**는 overview §6의 원칙이 이 렌즈에서 가장 자주 시험되며, 이 렌즈는 분류 이후의 확인 항목으로만 참여한다.
- **인과 단정 유도**: "~때문에 빠지는 거야?", "환율 보고 파는 거지?"는 RISK_DATA_GROUNDING이다 (DG-05, policyguard §7.1의 사실 단정 유도 패턴).
- **공식 동의 유도**: "금리 내리면 오르는 거 맞지?"처럼 통용 공식에 대한 동의를 구하는 질문은, 일반론 개념 설명(SAFE_LEARNING)이 가능한 경우에도 **현재 상황 적용·방향 전망으로 답하지 않는다.** 애매하면 위험 쪽 보수 분류(policyguard §7.2).
- **패턴 보강 제안**: "환전 타이밍", "담아둘까", "갈아탈까"(통화·채권·원자재 맥락) 등 자산군 확장형 매매 판단 표현은 policyguard §7.1의 RISK_BUY_SELL 패턴군 보강 후보로 제안한다.

## 13. 작성 완료 셀프 체크리스트

`finance-lens-authoring-standard.md` §14 전체를 적용하며, 이 렌즈의 고유 확인 항목은 다음과 같다.

- [ ] 환율/금리/수급/시장 관계가 어디에서도 매매 공식·인과 단정으로 서술되지 않는다 ("~니까 오른다/빠진다" 부재)
- [ ] 환율·금리의 방향 전망, 수준 단정, 목표 수치가 없다
- [ ] 자산군(엔화/달러/채권/원자재)에 대한 매수·매도·환전·비중 판단이 없고, "자산군 무관 동일 분류" 원칙이 §0/§3/§10에 일관되게 서술된다
- [ ] 통용 공식이 처방이 아니라 출처·전제 확인 질문으로만 다뤄진다 (패턴 2가 "전제 확인 시 사용 가능"으로 뒤집히지 않음)
- [ ] 변수 정의(통화쌍/만기/명목·실질/비교 기준)의 특정이 확인 항목으로 일관되게 요구된다
- [ ] 위험 질문은 §0 forbidden intent와 §3에만 등장한다
- [ ] 어떤 문장도 단독 인용 시 "무엇을 하라"로 읽히지 않는다
