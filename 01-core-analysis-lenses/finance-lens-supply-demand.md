## 1. 렌즈 목적

**수급 관련 질문을 "누가, 어떤 시장에서, 어떤 기간에 걸쳐, 어떤 성격으로" 사고팔았는지를 구분해 확인하는 관점으로 구조화한다.**

```text
구분 1. 주체     — 외국인 / 기관(연기금·투신 등 세부) / 개인 / 프로그램
구분 2. 시장     — 현물 / 선물·옵션 등 파생
구분 3. 기간     — 하루 흐름 / 누적 흐름
구분 4. 성격     — 패시브(지수 추종·리밸런싱 등 기계적) / 액티브(재량)
```

- 이 렌즈는 수급이 좋은지 나쁜지 **평가하지 않는다.** 위 네 구분을 확인하지 않은 채 수급을 해석하고 있지 않은지 점검하게 하는 것까지가 책임이다.

## 2. 이 렌즈가 다루는 질문

| 안전 질문 예시 | 병행 렌즈 | 근거 |
|---|---|---|
| "외국인 수급은 어떻게 봐야 해?" | (단독 가능) | SF-04 — 확인 방법 요청 |
| "하이닉스 요즘 어때?" | market-context, earnings | SF-01 — 기본 3관점 분해의 수급 축 |
| "프로그램 매매는 뭘 확인하면서 보는 거야?" | event-calendar | 확인 방법 요청 (만기 등 시점 요인 병행) |
| "수급과 가격이 엇갈릴 때는 뭘 확인해야 해?" | market-context | 관점 요청 |

## 4. 판단 전 체크리스트

```text
- 어느 주체의 수급을 보고 있는가? "기관" 안의 세부 주체
  (연기금/투신 등)까지 구분해 확인했는가?
- 하루짜리 흐름인가, 누적 흐름인가? 누적이라면 어떤 기간의
  누적인지 스스로 정했는가?
- 현물 수급인가, 선물·옵션 등 파생 수급인가?
  둘을 섞어서 하나의 방향으로 읽고 있지는 않은가?
- 월말/분기말/만기 등 기계적 수급이 발생할 수 있는 구간인지
  확인했는가? (event-calendar 병행)
- 지금 보는 수급이 패시브(지수 추종) 성격인지 액티브(재량)
  성격인지 구분할 수 있는 정보가 있는가?
- 수급과 가격이 같은 방향인가, 엇갈리는가?
  엇갈린다면 추가로 확인할 항목을 정했는가?
- 수급 데이터의 출처, 기준시각, 잠정치/확정치 여부를 확인했는가?
```

## 5. 확인할 데이터

Phase 1에는 데이터가 연결되어 있지 않으므로, 아래는 **사용자가 직접 확인할 항목과 방법**이다.

| 확인 항목 | 확인 방법 | 유의 |
|---|---|---|
| 주체별 매매 동향 | 거래소가 공표하는 투자자별 매매 데이터를 하루/누적으로 나눠 확인 | 장중 집계는 잠정치일 수 있다 — 잠정치/확정치 구분을 확인 |
| 누적 흐름 | 스스로 정한 기간(예: 관찰 시작일 이후)의 순매수 누적을 확인 | 기간을 사후에 바꾸면 원하는 그림이 만들어진다 (§6 패턴 5) |
| 파생 수급 | 선물/옵션의 주체별 동향을 현물과 분리해 확인 | 파생 매매에는 헤지·차익거래 수요가 섞여 있다 |
| 프로그램 매매 | 거래소가 공표하는 프로그램 매매 동향 확인 | 차익/비차익 구분이 있는지 확인 |
| 리밸런싱 구간 여부 | 달력상 월말/분기말/만기 해당 여부 확인 | 달력 사실 확인까지만 — 그로부터 매도/매수가 "나오고 있다"는 단정은 금지 |
| 데이터의 출처와 기준시각 | 어느 출처의, 언제 기준 데이터인지 항상 함께 확인 | 상수 항목 |

## 6. 오해하기 쉬운 패턴

### 패턴 1. 하루 순매수의 추세화

```text
[패턴]      특정 주체의 하루 순매수/순매도를 추세의 시작이나
            전환으로 해석.
[놓치는 것]  누적 흐름과, 그 누적을 볼 기간을 어떻게 정했는지.
[확인 질문]  같은 주체의 누적 흐름을, 미리 정한 기간 기준으로
            확인했는가?
[기록 질문]  나는 며칠치의 수급을 보고 이 인상을 받았는가?
```

### 패턴 2. 주체의 단일화

```text
[패턴]      "외국인" 또는 "기관"을 하나의 의도를 가진 단일
            주체처럼 해석.
[놓치는 것]  같은 분류 안에 지수 추종 자금, 재량 운용 자금,
            차익거래 자금 등 성격이 다른 흐름이 섞여 있다는 점.
[확인 질문]  이 수급이 패시브 성격인지 액티브 성격인지 구분할
            근거를 확인했는가?
[기록 질문]  나는 이 수급의 주체를 어떤 성격으로 가정하고
            읽었는가?
```

### 패턴 3. 수급과 방향의 등치

```text
[패턴]      특정 주체가 사면 오르고 팔면 내린다는 등치로 수급을
            읽는 해석.
[놓치는 것]  모든 체결에는 반대편이 있다는 점, 그리고 수급이
            가격의 원인이 아니라 결과로 나타나는 경우도 있다는 점.
[확인 질문]  수급과 가격이 엇갈린 구간도 같은 기준으로 확인했는가?
[기록 질문]  나는 수급을 원인으로 읽었는가, 결과로 읽었는가?
            그 근거는?
```

### 패턴 4. 파생과 현물의 혼동

```text
[패턴]      선물 매도 등 파생 포지션을 곧바로 현물 방향 전망으로
            해석.
[놓치는 것]  파생 매매에 섞여 있는 헤지 수요와 차익거래 수요.
[확인 질문]  현물과 파생의 주체별 동향을 분리해서 확인했는가?
[기록 질문]  나는 파생 수급에서 어떤 의도를 읽어냈고, 다른
            설명 가능성을 확인했는가?
```

### 패턴 5. 기간 소급 선택

```text
[패턴]      수급 누적 기간을 결론이 그럴듯해지는 방향으로
            사후에 골라 읽는 해석.
[놓치는 것]  관찰 기간을 데이터 확인 "전에" 정했는지 여부.
[확인 질문]  누적 기간을 미리 정하고 확인했는가, 보고 나서
            정했는가?
[기록 질문]  다음 기록에는 관찰 기간을 먼저 적고 데이터를
            확인해보면 어떤가?
```

## 7. 투자 일지 질문

```text
- 오늘 확인한 수급은 어느 주체, 어느 시장(현물/파생),
  어느 기간의 것인가?
- 수급 데이터의 출처와 기준시각, 잠정치/확정치 여부를
  함께 기록했는가?
- 나는 이 수급에서 무엇을 읽어냈고, 그 해석이 틀렸다고
  볼 수 있는 확인 항목은 무엇인가?
- 수급을 확인하기 전과 후의 감정을 각각 한 단어로
  기록한다면?
```

위 질문에 대한 답은 공부 노트 또는 투자 기록으로 저장해볼 수 있습니다.

## 8. 안전한 답변 구성 방식

| 5단 구조 | 이 렌즈가 채우는 것 |
|---|---|
| 1. 질문 재해석 | 질문을 §1의 구분 1~4(주체/시장/기간/성격) 좌표로 재기술 |
| 2. 적용 관점 | supply-demand (+ 병행 렌즈 명시) |
| 3. 확인 항목 | §4 체크리스트에서 선택 |
| 4. 기록/복기 질문 | §7에서 선택 |
| 5. 고지 | "이 내용은 특정 종목의 매수·매도 권유가 아닌 체크리스트입니다." |

- RISK_DATA_GROUNDING redirect 경로에서는 "단정 불가 안내"(templates §10)가 선행되고, 이 렌즈는 그 뒤의 "확인할 데이터 항목" 블록만 채운다. 단정 불가 안내 문구를 이 렌즈 본문에 중복 작성하지 않는다.
- 병행 라우팅이 잦은 렌즈: `market-context`, `event-calendar`.

## 9. 렌즈별 금지 표현

catalog §3.2의 금지 표현을 승계하고 아래를 추가한다. **이 렌즈의 어떤 문장도 수급을 매매 신호로 변환할 수 없다.** (아래 목록은 금지 예시의 인용이다.)

```text
[수급 사실 단정]   "외국인이 사고 있습니다" / "기관이 던지고 있습니다"
                  (출처·기준시각 없는 현재형)
[수급 평가]       "수급이 좋습니다 / 나쁩니다" / "수급이 받쳐줍니다"
                  / "매물이 소화됐습니다"
[수급-행동 연결]   "수급이 좋으니 사도 됩니다" / "기관이 파니 파세요"
                  / "외국인을 따라가는 것이 유리합니다"
[수급 신호화]      "외국인 순매수 전환은 매수 신호입니다"
                  / "누적 순매수가 이어지면 진입을 고려할 수 있습니다"
[세력 서사]       "세력이 모으고 있습니다" / "큰손이 들어왔습니다"
[파생 방향 단정]   "선물 매도가 쌓였으니 하락에 베팅하는 것입니다"
```

- "누적 흐름을 확인하라"는 안내와 "누적이면 신호다"는 서술의 차이가 이 렌즈의 경계선이다. 후자는 어떤 완곡 표현으로도 금지다 (standard §8.2).

## 10. PolicyGuard 연결 포인트

- **guard 선행**: "지금 ~하고 있지?" 형태의 수급 사실 확인 요구는 RISK_DATA_GROUNDING으로 분류된다 (policyguard §7.1). 이 렌즈는 분류 이후의 확인 방법 안내만 담당한다.
- **혼합 질문의 승격**: 수급 확인 질문에 "그러니까 사도 돼?"가 결합되면 최위험 우선 원칙에 따라 RISK_BUY_SELL로 처리된다. 이 렌즈는 redirect 체크리스트로만 참여한다.
- **패턴 보강 제안**: "세력", "큰손", "매집" 등 수급 서사 어휘가 판단 요청과 결합되는 표현은 policyguard §7.1 위험 신호 패턴군 보강 후보로 제안한다.

## 13. 작성 완료 셀프 체크리스트

`finance-lens-authoring-standard.md` §14 전체를 적용하며, 이 렌즈의 고유 확인 항목은 다음과 같다.
