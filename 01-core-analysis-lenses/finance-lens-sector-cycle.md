## 1. 렌즈 목적

**업황/섹터 질문을 "층위의 구분 → 업황 요인의 분해 → 사이클 가정의 명시 → 기록"으로 구조화한다.**

```text
구분 1. 층위 구분   — 종목 개별 요인의 이야기인가, 섹터 공통 요인의
                     이야기인가
구분 2. 업황 분해   — 업황 근거를 항목으로 분해: 수요 / 공급 / 재고 /
                     제품·서비스 가격 / 정책 / 금리·환율 /
                     실적 추정 변화(revision)
구분 3. 사이클 가정 — 사이클 국면에 대한 "나의 가정"과 그 가정을
                     확인할 항목 (렌즈가 국면을 판정하지 않는다)
구분 4. 기록       — 업황 가정, 확인 항목, 확인하지 못한 항목의 기록
```

- 이 렌즈는 어떤 섹터가 좋은지 **말하지 않고**, 사이클의 현재 위치를 **판정하지 않는다.** 업황이라는 뭉뚱그려진 단어를 확인 가능한 항목 목록으로 분해하게 하는 것까지가 책임이다.
- RF-08(종목 추천 거절)의 redirect 대상으로서, 이 렌즈가 제공하는 것은 **종목 선별 "기준"의 체크리스트**이지 선별 "결과"(종목/업종 이름)가 아니다.

## 2. 이 렌즈가 다루는 질문

| 안전 질문 예시 | 병행 렌즈 | 근거 |
|---|---|---|
| "업황은 뭘 보고 확인해?" | (단독 가능) | 확인 방법 요청 |
| "섹터 로테이션이 뭐야?" | (개념: SAFE_LEARNING) | 개념 질문. 이 렌즈는 관점 연결로 참여 |
| "종목 이슈랑 업황 이슈는 어떻게 구분해?" | market-context | 층위 구분의 관점 요청 (market-context 패턴 1과 연결) |
| "산업 사이클을 볼 때는 어떤 항목을 기록해?" | journal-review | 기록 항목 요청 |

---

## 3. 이 렌즈가 다루지 않는 질문

이 렌즈는 **업종/종목 이름을 골라주는 목적지가 아니다.** 아래 질문은 Input Guard가 먼저 분류하고, 거절 선언 이후에만 이 렌즈의 확인 관점이 redirect로 제공된다.

| 질문 | intent | 처리 |
|---|---|---|
| "급등주 추천해줘" | RISK_RECOMMENDATION | REFUSE_AND_REDIRECT (RF-08) — 종목명 제시 불가 |
| "요즘 어떤 섹터가 좋아? 뜨는 업종 알려줘" | RISK_RECOMMENDATION | **업종 추천도 추천이다** — 동일 경로 |
| "업황 도는 것 같은데 지금 들어갈까?" | RISK_BUY_SELL | REDIRECT_TO_CHECKLIST — 사이클 가정을 전제로 한 매수 판단 요청 |
| "지금 반도체 업황 바닥 맞지?" | RISK_DATA_GROUNDING | 사이클 위치 단정·동의 금지, 확인 항목 전환 |

## 4. 판단 전 체크리스트

```text
- 이 질문은 종목 개별 요인에 대한 것인가, 섹터 공통 요인에
  대한 것인가? 그렇게 구분한 근거는 무엇인가?
- 같은 섹터 내 다른 종목들도 같은 방향으로 움직였는지
  확인했는가? (층위 구분의 단서)
- 내가 "업황"이라고 말할 때 그 근거는 어떤 항목인가?
  (수요 / 공급 / 재고 / 제품·서비스 가격 / 정책 / 금리·환율 /
  실적 추정 변화 중에서 기록)
- 그 항목들을 확인할 수 있는 출처 유형을 알고 있는가?
- 사이클 국면에 대한 나의 가정은 무엇이고, 그 가정이 틀렸다고
  볼 확인 항목을 정했는가?
- 섹터 서사가 개별 종목의 확인(실적/수급/이슈)을 대체하고
  있지는 않은가?
```

## 5. 확인할 데이터

Phase 1에는 데이터가 연결되어 있지 않으므로, 아래는 **사용자가 직접 확인할 항목과 출처 유형**이다. 이 렌즈가 업황의 좋고 나쁨을 평가하지 않는다.

| 확인 항목 | 확인 방법 (출처 유형) | 유의 |
|---|---|---|
| 수요·공급 관련 통계 | 공식 산업 통계·수출입 통계의 공표처 | 통계의 기준 기간과 잠정/확정 여부 확인 |
| 재고·가동률 지표 | 통계 작성 기관 또는 업계 단체의 공표 자료 | 지표의 산출 범위(어느 품목/지역)를 함께 확인 |
| 제품·서비스 가격 | 해당 품목 가격을 공표하는 기관·시장의 자료 | 가격 지표의 기준(현물/계약 등) 확인 |
| 정책·규제 | 정부·규제기관의 공식 발표 | 발표 사실 확인까지만 — 영향 방향 단정은 별개의 미확인 주장 |
| 섹터 지수 대 종목 흐름 | 섹터 지수와 개별 종목의 같은 기간 흐름 대조 | 층위 구분(구분 1)의 기초 자료 (market-context §5와 동일 방식) |
| 실적 추정 변화 | 추정치 집계 제공처의 갱신 여부 확인 방법 | 추정치 수치 자체가 아니라 "갱신·방향이 확인 가능한가"까지 (earnings 렌즈와 동일 기준) |
| 데이터의 출처와 기준시각 | 어느 출처의, 언제 기준 자료인지 항상 함께 확인 | 상수 항목 |

## 6. 오해하기 쉬운 패턴

### 패턴 1. 섹터 서사의 종목 직결

```text
[패턴]      "이 산업이 좋다"는 서사에서 곧바로 그 산업 내 특정
            종목의 결론으로 건너뛰는 해석.
[놓치는 것]  같은 섹터 안에서도 종목마다 다른 개별 요인 —
            경쟁 위치, 제품 구성, 원가 구조, 고객 집중도.
[확인 질문]  섹터 공통 요인과 이 종목의 개별 요인을 나눠서
            확인했는가?
[기록 질문]  이번 기록에서 섹터 층위의 근거와 종목 층위의 근거를
            각각 무엇으로 적었는가?
```

### 패턴 2. 사이클 위치의 단정

```text
[패턴]      "지금이 업황 바닥/피크"라는 위치 판정을 전제로 섹터를
            읽는 해석.
[놓치는 것]  사이클의 위치는 지나고 나서야 확정된다는 점.
            위치 판정 대신 확인할 항목(재고, 가격, 추정 변화 등)의
            목록이 비어 있다는 점.
[확인 질문]  나의 국면 가정을 지지하는 항목과 반하는 항목을 각각
            확인했는가?
[기록 질문]  나의 사이클 가정과, 그 가정이 틀렸다고 볼 확인 항목을
            나란히 기록한다면?
```

### 패턴 3. 로테이션의 공식화

```text
[패턴]      "이런 국면에는 이런 업종"이라는 로테이션 공식으로
            섹터 흐름을 읽는 해석.
[놓치는 것]  그 공식이 성립하기 위한 전제 조건들과, 공식을 자기
            기록으로 검토해본 적이 있는지의 여부. 공식 역시 검증
            없이 받아들인 전언일 수 있다 (emotion-check 패턴 3과
            동일 구조).
[확인 질문]  나는 이 공식을 어디서 받아들였고, 이번 상황이 그
            공식의 전제와 같은지 무엇으로 확인했는가?
[기록 질문]  내가 사용하는 로테이션 공식과 그 출처를 기록에
            명시한다면?
```

### 패턴 4. 대표 종목의 섹터화

```text
[패턴]      대표 종목 한두 개의 흐름을 섹터 전체의 흐름으로
            일반화하는 해석.
[놓치는 것]  섹터 내 다른 종목들의 흐름과, 대표 종목의 개별 요인이
            섹터 공통 요인과 섞여 있을 가능성.
[확인 질문]  섹터 지수 또는 다른 구성 종목의 같은 기간 흐름을
            확인했는가?
[기록 질문]  나는 어떤 종목(들)을 근거로 이 섹터의 인상을
            갖게 됐는가?
```

## 7. 투자 일지 질문

```text
- 오늘의 질문은 종목 층위였는가, 섹터 층위였는가?
  구분 근거를 기록한다면?
- 내가 "업황"의 근거로 확인한 항목과 그 출처를 기록한다면?
  (수요/공급/재고/가격/정책/금리·환율/추정 변화 중)
- 사이클 국면에 대한 나의 가정과, 그 가정이 틀렸다고 볼
  확인 항목은 무엇인가?
- 확인하지 못한 채 서사로만 받아들인 부분이 있다면
  무엇인가?
```

위 질문에 대한 답은 공부 노트 또는 투자 기록으로 저장해볼 수 있습니다.

## 8. 안전한 답변 구성 방식

이 렌즈의 콘텐츠는 공통 5단 구조 안에서 아래와 같이 소비된다. 거절 선언 문구는 템플릿(`finance-prompt-templates` §8) 책임이며, 이 렌즈 본문에 중복 작성하지 않는다.

| 5단 구조 | 이 렌즈가 채우는 것 |
|---|---|
| 1. 질문 재해석 | 질문을 §1의 구분 1~4(층위/분해/가정/기록)로 재기술 |
| 2. 적용 관점 | sector-cycle (+ 병행 렌즈 명시) |
| 3. 확인 항목 | §4 체크리스트 + §5의 출처 유형 안내에서 선택 |
| 4. 기록/복기 질문 | §7에서 선택 |
| 5. 고지 | "이 내용은 특정 종목의 매수·매도 권유가 아닌 체크리스트입니다." |

- **RF-08 경로의 특별 규칙**: 종목 추천 거절 이후 이 렌즈가 제공하는 것은 "종목/섹터를 스스로 선별할 때 확인할 기준"의 체크리스트다. 거절된 추천의 대체물 — 업종 이름, "이 산업이 유망하다"는 서술, 예시를 가장한 특정 섹터 부각 — 을 어떤 형태로도 제시하지 않는다 (templates §8의 우회 금지와 동일).
- 업황 항목을 예시할 때도 특정 실재 업종의 현재 상태를 묘사하지 않는다. 예시가 필요하면 업종명 없는 일반 구조("수요 통계", "재고 지표")로 쓴다.
- 병행 라우팅이 잦은 렌즈: `market-context`(층위 구분), `earnings`(추정 변화 확인), `event-calendar`(정책 발표 일정).

## 9. 렌즈별 금지 표현

**이 렌즈는 종목 추천 거절의 redirect 대상이므로, 업종 추천으로의 우회가 가장 경계해야 할 위반이다.** (아래 목록은 금지 예시의 인용이다.)

```text
[섹터 결론]       "이 섹터가 유망합니다 / 좋습니다 / 나쁩니다"
                 / "지금은 반도체/2차전지/은행주가 유리합니다"
[우회 추천]       "종목은 못 골라도 이 업종은 좋습니다"
                 / "예를 들어 요즘은 ~업종이 주목받고 있죠"
                 (예시를 가장한 특정 섹터 부각)
[사이클-행동 결합] "업황 바닥이니 선취매 구간입니다"
                 / "사이클상 지금이 진입 시점입니다"
[로테이션 전망]    "다음 로테이션은 ~업종으로 올 것입니다"
[업황 단정]       "업황 개선이 확실합니다" / "지금 업황이 바닥입니다"
[상대 우위 지시]   "성장주보다 가치주로 갈아타세요"
```

- "업황을 항목으로 분해해 확인하라"는 안내와 "이 업황이 좋다/이 업종이 유리하다"는 결론의 차이가 이 렌즈의 경계선이다. 후자는 예시·비유·완곡 표현을 포함한 어떤 형태로도 금지다.

## 10. PolicyGuard 연결 포인트

- **guard 선행 — 업종 추천의 분류**: "어떤 섹터가 좋아?", "뜨는 업종 알려줘"는 종목명이 없어도 RISK_RECOMMENDATION이다. 추천의 단위가 종목에서 업종으로 넓어졌을 뿐 개별성 없는 추천이 아니며, SAFE 쪽으로 완화 분류하지 않는다.
- **사이클 전제형 주의**: "업황 도는 것 같은데 들어갈까?"처럼 사이클 가정을 전제로 매매 동의를 구하는 질문은 RISK_BUY_SELL이며, 이 렌즈는 전제(사이클 위치)에 동의하지 않은 채 redirect 확인 항목으로만 참여한다 (valuation 렌즈의 가치 결론 전제형과 동일 구조).
- **위치 단정 유도**: "바닥 맞지?", "피크 지났지?"는 RISK_DATA_GROUNDING이다 (market-context의 국면 단정 유도와 동일 계열).
- **패턴 보강 제안**: "뜨는/유망한/주도 섹터", "갈아탈 업종" 등 업종 단위 추천 요청 표현은 policyguard §7.1의 RISK_RECOMMENDATION 패턴군 보강 후보로 제안한다.

## 13. 작성 완료 셀프 체크리스트

`finance-lens-authoring-standard.md` §14 전체를 적용하며, 이 렌즈의 고유 확인 항목은 다음과 같다.

- [ ] 특정 업종/섹터에 대한 결론(유망/좋다/나쁘다/유리)이 없다 — 예시를 가장한 부각 포함
- [ ] "종목은 못 골라도 이 업종은 ~" 형태의 우회 추천이 없다
- [ ] 사이클 위치를 판정하거나 위치 판정에 동의하는 문장이 없다
- [ ] 로테이션 공식이 처방·전망으로 서술되지 않고, 공식의 출처·전제 확인 질문으로만 다뤄진다
- [ ] 업황이 항상 확인 항목(수요/공급/재고/가격/정책/금리·환율/추정 변화)으로 분해되어 서술된다
- [ ] 위험 질문은 §0 forbidden intent와 §3에만 등장한다
- [ ] 어떤 문장도 단독 인용 시 "무엇을 하라"로 읽히지 않는다
