## 1. 렌즈 목적

**실적 관련 질문을 "일정의 확인 → 기대의 확인 → 요인의 분해 → 나의 계획 기록"으로 구조화한다.**

```text
구분 1. 일정      — 다음 실적 발표 일정 (확정/추정, 공시 출처)
구분 2. 기대      — 시장 기대(컨센서스)의 존재·출처와, 그 기대가
                    가격에 반영됐다고 볼 근거의 확인
구분 3. 요인 분해  — 실적 기대의 근거를 산업 업황 / 회사 개별 /
                    일회성 / 환율·원가 요인으로 분해
구분 4. 계획 기록  — 결과가 기대와 다를 경우의 나의 계획 (기록용 —
                    계획의 내용은 사용자의 몫이다)
```

- 이 렌즈는 실적 결과를 **전망하지 않고**, 기대 반영 여부를 **판정하지 않는다.** "기대가 반영됐다고 볼 근거가 있는가"는 결론이 아니라 확인 질문으로만 존재한다.

## 2. 이 렌즈가 다루는 질문

| 안전 질문 예시 | 병행 렌즈 | 근거 |
|---|---|---|
| "실적 발표 전에 뭘 봐야 해?" | event-calendar | SF-03 — 실적 관점 + 일정 확인 |
| "하이닉스 요즘 어때?" | market-context, supply-demand | SF-01 — 기본 3관점 분해의 실적 축 |
| "컨센서스가 뭐야?" | (개념: SAFE_LEARNING) | 개념 질문. 이 렌즈는 관점 연결로 참여 |
| "가이던스는 어디서 확인해?" | (단독 가능) | 확인처 안내 요청 |

## 4. 판단 전 체크리스트

```text
- 다음 실적 발표 일정을 공시/IR 출처에서 확인했는가?
  그 일정은 확정 공시인가, 추정인가?
- 시장 기대(컨센서스)가 존재하는지, 존재한다면 어느 출처의
  언제 기준 집계인지 확인했는가?
- 그 기대가 이미 가격에 반영됐다고 볼 근거가 있는가?
  나는 그것을 어떤 자료로 확인할 것인가?
- 실적 기대의 근거를 요인별로 나눠 적었는가?
  (산업 업황 / 회사 개별 / 일회성 / 환율·원가)
- 직전 실적에 일회성 요인이 포함되어 있었는지 공시 원문에서
  확인했는가?
- 실적이 기대와 다르게 나올 경우의 나의 계획을 기록해뒀는가?
  (기록용)
```

## 5. 확인할 데이터

Phase 1에는 데이터가 연결되어 있지 않으므로, 아래는 **사용자가 직접 확인할 항목과 출처 유형**이다. 컨센서스·실적 수치를 이 렌즈가 제시하지 않는다.

| 확인 항목 | 확인 방법 (출처 유형) | 유의 |
|---|---|---|
| 실적 발표 일정 | 공시/기업 IR 공식 일정 | 확정 공시 전 일정은 추정일 수 있다 — 확정 여부 표기 확인 (event-calendar §5와 동일) |
| 과거 실적 원문 | 공시된 사업보고서/분기보고서 | 요약 기사보다 원문의 주석(일회성 항목)까지 확인 |
| 컨센서스 | 추정치 집계 제공처의 존재 여부·기준시각 확인 | 컨센서스는 추정의 집계이지 확정 사실이 아니다 — 출처·갱신 시점 확인 |
| 가이던스 | 회사가 공식 발표한 전망 자료의 유무 | 회사 발표(가이던스)와 시장 추정(컨센서스)을 구분해 확인 |
| 환율·원가 관련 언급 | 공시·IR 자료 내 관련 서술의 유무 | 요인 분해(구분 3)의 재료 — 영향의 방향 단정은 별개의 미확인 주장 |
| 데이터의 출처와 기준시각 | 어느 출처의, 언제 기준 정보인지 항상 함께 확인 | 상수 항목 |

## 6. 오해하기 쉬운 패턴

### 패턴 1. 결과와 반응의 등치

```text
[패턴]      "실적이 좋으면 오르고 나쁘면 빠진다"는 등치로 실적
            발표를 읽는 해석.
[놓치는 것]  발표 전에 시장이 이미 어떤 기대를 갖고 있었는지의
            확인. 결과 단독이 아니라 결과와 기대의 관계가 별도의
            확인 대상이라는 점.
[확인 질문]  나는 발표 전의 시장 기대를 어떤 자료로 확인했는가?
[기록 질문]  발표 전에 내가 확인한 기대와, 발표 후 실제 결과·반응을
            나란히 기록한다면? (event-calendar의 전/후 기록과 동일
            방식)
```

### 패턴 2. 컨센서스의 사실화

```text
[패턴]      컨센서스를 회사의 발표나 확정된 사실처럼 취급하는 해석.
[놓치는 것]  컨센서스는 추정치들의 집계이며, 출처·표본·갱신 시점에
            따라 값이 다르다는 점.
[확인 질문]  내가 본 컨센서스의 출처와 기준시각, 갱신 여부를
            확인했는가?
[기록 질문]  나는 어느 출처의 컨센서스를 기준으로 이 기록을
            남기는가?
```

### 패턴 3. 일회성 요인의 추세화

```text
[패턴]      일회성 이익/비용이 포함된 분기 실적을 실력의 추세로
            해석.
[놓치는 것]  공시 원문에 표기된 일회성 항목의 유무와 규모 구분.
[확인 질문]  이 실적에서 반복 가능한 부분과 일회성 부분을 공시
            원문에서 구분해봤는가?
[기록 질문]  내가 실적을 근거로 기록할 때, 일회성 여부를 확인한
            항목과 확인하지 못한 항목은 각각 무엇인가?
```

### 패턴 4. 가이던스와 컨센서스의 혼동

```text
[패턴]      회사의 공식 전망(가이던스)과 시장의 추정 집계
            (컨센서스)를 같은 것으로 뭉뚱그리는 해석.
[놓치는 것]  두 숫자의 주체가 다르다는 점. 회사 발표와 시장 추정은
            각각 별도로 확인할 대상이다.
[확인 질문]  내가 본 전망치는 회사가 발표한 것인가, 시장이 추정한
            것인가?
[기록 질문]  이번 기록에 두 값의 출처를 구분해 남긴다면 각각
            무엇인가?
```

## 7. 투자 일지 질문

```text
- 다음 실적 발표 일정과 그 확정/추정 여부, 출처를 기록한다면?
- 나의 실적 기대의 근거를 요인별(업황/개별/일회성/환율·원가)로
  나눠 기록한다면 각각 무엇인가?
- 기대가 가격에 반영됐는지에 대한 나의 가정과, 그 가정을
  확인할 자료는 무엇인가?
- 실적이 기대와 다를 경우의 나의 계획을 지금 기록한다면?
  (기록용 — 발표 후 실제 확인한 것과 나란히 남긴다)
```

위 질문에 대한 답은 공부 노트 또는 투자 기록으로 저장해볼 수 있습니다.

## 8. 안전한 답변 구성 방식

이 렌즈의 콘텐츠는 공통 5단 구조 안에서 아래와 같이 소비된다. 거절/안내 선언 문구는 템플릿(`finance-prompt-templates` §7~§10) 책임이며, 이 렌즈 본문에 중복 작성하지 않는다.

| 5단 구조 | 이 렌즈가 채우는 것 |
|---|---|
| 1. 질문 재해석 | 질문을 §1의 구분 1~4(일정/기대/요인/계획)로 재기술 |
| 2. 적용 관점 | earnings (+ 병행 렌즈 명시) |
| 3. 확인 항목 | §4 체크리스트 + §5의 출처 유형 안내에서 선택 |
| 4. 기록/복기 질문 | §7에서 선택 (전/후 나란히 기록 질문 포함) |
| 5. 고지 | "이 내용은 특정 종목의 매수·매도 권유가 아닌 체크리스트입니다." |

- DG-04 redirect 경로에서는 "단정 불가 안내"(templates §10)가 선행되고, 이 렌즈는 컨센서스의 출처·기준시각·갱신 여부 등 **확인 방법 블록만** 채운다. 어떤 경로에서도 컨센서스 수치·방향을 제시하지 않는다.
- 병행 라우팅이 잦은 렌즈: `event-calendar`(발표 일정), `valuation`(추정치의 지표 반영), `market-context`(기간 관점).

## 9. 렌즈별 금지 표현

catalog §3.3의 금지 표현을 승계하고 아래를 추가한다. (아래 목록은 금지 예시의 인용이다.)

```text
[결과 전망]       "실적이 좋을 것입니다" / "컨센서스 상회가 확실합니다"
                 / "어닝 서프라이즈가 예상됩니다"
[시점-행동 결합]   "실적 발표 전이 매수 적기입니다"
                 / "발표 보고 들어가는 것이 안전합니다"
[반영 판정]       "기대가 이미 다 반영됐습니다 / 아직 반영 전입니다"
                 (반영 여부의 결론 제시 — 확인 질문으로만 가능)
[수치 제시]       "이번 분기 컨센서스는 ~ 수준입니다" / "목표가 ~원"
[요인 단정]       "환율 덕에 실적이 좋아질 것입니다" (요인 분해 항목을
                 방향 전망으로 전환)
```

- "기대 반영 여부를 확인할 자료가 있는가"라는 질문과 "반영됐다/안 됐다"는 판정의 차이가 이 렌즈의 경계선이다. 후자는 어떤 완곡 표현으로도 금지다.

## 10. PolicyGuard 연결 포인트

- **guard 선행**: "컨센서스 어때?", "잘 나올까?" 등 현재형/미래형 결과 확인 요구는 RISK_DATA_GROUNDING으로 분류된다 (policyguard §7.1). 이 렌즈는 분류 이후의 확인 방법 안내만 담당한다.
- **시점 결합 주의**: "발표 전에 살까 / 보고 살까"는 event-calendar 렌즈와 동일하게 RISK_BUY_SELL이다. 실적이라는 소재가 분류를 완화하지 않는다.
- **목표가 결합**: "실적 반영하면 얼마까지 가?"는 RISK_TARGET_PRICE이며 redirect 대상은 valuation이다. 이 렌즈는 요인 분해 항목의 병행 참여까지만 한다.
- **패턴 보강 제안**: "서프라이즈 확실하지?", "이번엔 어닝 쇼크지?" 등 결과 단정 동의 유도형 표현은 policyguard §7.1의 RISK_DATA_GROUNDING 패턴군 보강 후보로 제안한다.

## 13. 작성 완료 셀프 체크리스트

`finance-lens-authoring-standard.md` §14 전체를 적용하며, 이 렌즈의 고유 확인 항목은 다음과 같다.

- [ ] 실적 결과·컨센서스·서프라이즈에 대한 전망/단정 문장이 없다
- [ ] "일정의 확인"과 "결과의 전망"이 모든 섹션에서 분리되어 있다
- [ ] 기대 반영 여부가 결론이 아니라 확인 질문으로만 존재한다
- [ ] 요인 분해(업황/개별/일회성/환율·원가)가 방향 전망으로 전환되는 문장이 없다
- [ ] 컨센서스·실적·목표가 수치가 어디에도 없다
- [ ] 위험 질문은 §0 forbidden intent와 §3에만 등장한다
- [ ] 어떤 문장도 단독 인용 시 "무엇을 하라"로 읽히지 않는다
