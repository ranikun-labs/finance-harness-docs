## 1. 렌즈 목적

**막연한 시장/종목 질문을 세 개의 축으로 분해해, 사용자가 자기 질문의 좌표를 스스로 확인하게 한다.**

```text
축 1. 기간 관점   — 이 질문은 단기/중기/장기 중 어느 관점인가
축 2. 이슈 범위   — 종목 이슈인가, 섹터 이슈인가, 시장 전체 이슈인가
축 3. 반응 요인   — 실적 / 수급 / 이벤트 / 가격 움직임 / 뉴스·서사 / 감정
                    중 무엇에 반응하고 있는가
```

- 이 렌즈는 시장 국면을 **판정해주지 않는다.** 사용자가 자신의 국면 가정(상승/하락/횡보라고 보는지)을 명시하고, 그 가정의 근거를 어디서 확인했는지 점검하게 하는 것까지가 책임이다.

---

## 2. 이 렌즈가 다루는 질문

| 안전 질문 예시 | 병행 렌즈 | 근거 |
|---|---|---|
| "하이닉스 요즘 어때?" | supply-demand, earnings | SF-01 — 막연한 종목 질문의 기본 3관점 분해 |
| "매수 기준은 어떻게 세워?" | risk-checklist | SF-06 — 기준/방법 질문 (행동 판단 요청 아님) |
| "너무 오른 것 같은데 어떻게 봐야 해?" | emotion-check | AM-04 — "어떻게 봐야 해"는 관점 요청. 감정 신호 병행 |
| "요즘 시장은 무엇을 확인하며 보는 게 좋아?" | (단독 가능) | 관찰 프레임 요청 |

---

## 3. 이 렌즈가 다루지 않는 질문

아래 질문은 이 렌즈가 답하지 않는다. Input Guard가 먼저 분류하고, 거절/안내 선언 이후에만 이 렌즈의 체크리스트가 redirect로 제공된다.

| 질문 | intent | 처리 |
|---|---|---|
| "지금 사도 돼?" / "팔까?" / "계속 들고 있어도 돼?" | RISK_BUY_SELL | REDIRECT_TO_CHECKLIST (RF-01~03) |
| "뭐 사야 해?" / "급등주 추천해줘" | RISK_RECOMMENDATION | REFUSE_AND_REDIRECT (RF-08) |
| "지금 상승장 맞지?" / "지금이 바닥이지?" | RISK_DATA_GROUNDING | 단정 불가 안내 + 확인 항목 전환 |
| "오늘 환율 때문에 빠지는 거야?" | RISK_DATA_GROUNDING | DG-05 — 인과 단정 금지 |

## 4. 판단 전 체크리스트

```text
- 이 질문은 단기/중기/장기 중 어느 관점의 질문인가?
- 종목 이슈인가, 섹터 이슈인가, 시장 전체 이슈인가?
  그렇게 구분한 근거를 어디서 확인했는가?
- 나는 지금 실적/수급/이벤트/가격 움직임/뉴스·서사/감정 중
  무엇에 반응하고 있는가?
- 시장 국면에 대한 나의 가정(상승/하락/횡보로 보는지)은 무엇이고,
  그 가정은 어떤 데이터로 확인할 수 있는가?
- 가격 움직임 외에 내가 확인한 정보가 있는가?
- 이 질문의 관찰 기간을 나는 어떻게 정했는가?
  (최근 며칠의 흐름만 보고 있지는 않은가?)
```

## 5. 확인할 데이터

Phase 1에는 데이터가 연결되어 있지 않으므로, 아래는 **사용자가 직접 확인할 항목과 방법**이다.

| 확인 항목 | 확인 방법 | 유의 |
|---|---|---|
| 시장 전체 지수 흐름 | 거래소/지수 산출기관이 공표하는 지수 데이터를 관찰 기간을 정해 확인 | 기간을 먼저 정하지 않으면 최근 흐름에 끌려간다 |
| 종목과 시장의 동반 여부 | 같은 기간 종목 등락과 시장/섹터 등락을 나란히 확인 | 종목 이슈/시장 이슈 구분(축 2)의 기초 자료 |
| 섹터 흐름 | 해당 종목이 속한 섹터 지수 또는 동종 종목군 흐름 확인 | 종목 개별 요인과 섹터 공통 요인의 분리 |
| 거래대금 추이 | 가격 변화와 거래대금 변화를 함께 확인 | 가격만 보는 해석의 보완 (§6 패턴 참고) |
| 데이터의 출처와 기준시각 | 어느 출처의, 언제 기준 데이터인지 항상 함께 확인 | 상수 항목 — 기준시각 없는 데이터로 현재를 설명하지 않는다 |

## 6. 오해하기 쉬운 패턴

### 패턴 1. 종목 이슈와 시장 이슈의 혼동

```text
[패턴]      종목 가격이 움직이면 그 원인을 종목 내부에서만 찾는 해석.
[놓치는 것]  같은 날 시장 전체와 섹터가 함께 움직였는지 여부.
[확인 질문]  같은 기간 시장/섹터 흐름을 종목과 나란히 확인했는가?
[기록 질문]  나는 이 움직임을 종목/섹터/시장 중 어느 층위의 일로
            기록했는가? 그 근거는?
```

### 패턴 2. 기간 관점의 표류

```text
[패턴]      장기 관점으로 시작한 관찰을, 단기 가격 변동이 커지면
            단기 관점의 결론으로 재해석하는 흐름.
[놓치는 것]  처음 질문했을 때 스스로 정한 기간 관점.
[확인 질문]  지금의 내 관점은 처음 기록한 기간 관점과 같은가,
            달라졌는가? 달라졌다면 무엇 때문인가?
[기록 질문]  이번 기록의 기간 관점을 한 단어(단기/중기/장기)로
            남긴다면 무엇인가?
```

### 패턴 3. 최근 흐름의 국면화

```text
[패턴]      최근 며칠의 흐름을 시장 국면 전체의 성격으로
            일반화하는 해석.
[놓치는 것]  관찰 기간을 어떻게 정했는지에 대한 근거.
[확인 질문]  관찰 기간을 바꾸면 같은 데이터가 다르게 보이는지
            확인해봤는가?
[기록 질문]  나는 어떤 기간을 보고 이 인상을 받았는가?
```

### 패턴 4. 서사의 소급 적용

```text
[패턴]      가격이 움직인 뒤에 접한 뉴스로 움직임의 원인을
            소급해 설명하는 해석.
[놓치는 것]  그 뉴스가 가격 움직임보다 먼저였는지, 나중이었는지.
[확인 질문]  내가 원인이라고 생각한 정보의 시점과 가격 움직임의
            시점을 비교해봤는가?
[기록 질문]  나는 정보를 보고 질문하게 됐는가, 가격을 보고
            정보를 찾게 됐는가?
```

## 7. 투자 일지 질문

```text
- 오늘 질문의 기간 관점을 한 단어로 기록한다면? (단기/중기/장기)
- 나는 오늘 무엇에 반응해 이 질문을 하게 됐는가?
  (실적 / 수급 / 이벤트 / 가격 / 뉴스·서사 / 감정 중 기록)
- 시장 국면에 대한 나의 현재 가정과, 그 가정이 틀렸다고
  볼 수 있는 확인 항목은 무엇인가?
- 지금의 감정을 한 단어로 기록한다면?
```

위 질문에 대한 답은 공부 노트 또는 투자 기록으로 저장해볼 수 있습니다.

## 8. 안전한 답변 구성 방식

이 렌즈의 콘텐츠는 공통 5단 구조 안에서 아래와 같이 소비된다. 거절 선언 문구는 템플릿(`finance-prompt-templates` §7~§8) 책임이며, 이 렌즈 본문에 중복 작성하지 않는다.

| 5단 구조 | 이 렌즈가 채우는 것 |
|---|---|
| 1. 질문 재해석 | 질문을 축 1~3(기간/범위/요인)의 좌표로 재기술 |
| 2. 적용 관점 | market-context (+ 병행 렌즈 명시) |
| 3. 확인 항목 | §4 체크리스트에서 질문에 맞는 항목 선택 |
| 4. 기록/복기 질문 | §7에서 선택 |
| 5. 고지 | "이 내용은 특정 종목의 매수·매도 권유가 아닌 체크리스트입니다." |

- 병행 라우팅이 잦은 렌즈: `supply-demand`, `earnings`, `emotion-check`, `risk-checklist`.
- 이 렌즈는 UNKNOWN의 보수적 기본값이므로, 질문이 모호할수록 축 1(기간 관점) 확인 질문을 앞세워 질문을 좁힌다.

## 9. 렌즈별 금지 표현

catalog §3.1의 금지 표현을 승계하고 아래를 추가한다. (아래 목록은 금지 예시의 인용이다.)

```text
[국면 단정]     "지금은 상승장/하락장/횡보장입니다"
               "시장이 좋습니다 / 나쁩니다"
[시점 판단]     "지금이 저점/고점입니다" / "바닥을 다졌습니다"
[구간 판단]     "비중을 늘리기/줄이기 좋은 구간입니다"
               "조정은 기회입니다"
[국면-행동 연결] "하락장이니 현금 비중을 높이세요"
               "상승장 초입이니 따라가도 됩니다"
[전망]         "추세가 이어질 가능성이 높습니다"
```

- 사용자가 자신의 국면 가정을 기록하는 것과, 서비스가 국면을 단정하는 것은 다르다. 이 렌즈의 모든 문장은 전자만 유도한다.

## 10. PolicyGuard 연결 포인트

- **guard 선행**: "요즘 어때?"류 질문에 "사도 돼?"가 결합되면 RISK_BUY_SELL로 승격된다 (AM-04 승격 규칙). 이 렌즈는 승격 판정을 하지 않으며, Input Guard 분류 결과를 따른다.
- **redirect 소비**: RF-01~03, RF-08의 redirect 대상으로 지정된 경우, 이 렌즈의 체크리스트는 거절 선언 이후 블록에만 배치된다.
- **패턴 보강 제안**: 작성 중 발견한 국면 단정 유도형 위험 표현("지금 ~장 맞지?", "바닥이지?")은 policyguard §7.1의 RISK_DATA_GROUNDING 패턴군 보강 후보로 제안한다. 규칙 자체는 policyguard 문서가 소유한다.

## 11. Output Validator 체크포인트

| 이 문서의 요소 | validator 검사 | 확인 사항 |
|---|---|---|
| §4 체크리스트 | forbidden trading action | 조건-행동/통과 함의 문장 없음 |
| §5 확인할 데이터 | unsupported market data claim (§10) | 현재형 단정·수치 없음, 출처/기준시각 상수 항목 포함 |
| §6 오해 패턴 | forbidden trading action / performance guarantee | 역신호화·정답 제시·빈도 수치화 없음 |
| §7 일지 질문 | unsafe journal review conclusion (§12) | 전부 질문형, 행동 결론 없음 |
| §9 금지 표현 | 검사 카테고리 확장 후보 | "국면 단정/시점 판단" 표현군의 validator 반영 여부는 리뷰에서 판정 |

## 13. 작성 완료 셀프 체크리스트

`finance-lens-authoring-standard.md` §14 전체를 적용하며, 이 렌즈의 고유 확인 항목은 다음과 같다.

- [ ] 시장 국면·저점/고점·구간에 대한 단정 문장이 없다
- [ ] "국면 가정의 기록 유도"와 "국면 판정 제공"이 문장 단위로 구분된다
- [ ] 오해 패턴 4개가 모두 4부 구조이며, 어느 패턴도 "그 반대면 안전/기회"로 읽히지 않는다
- [ ] 위험 질문은 §0 forbidden intent와 §3에만 등장하고, 렌즈가 직접 답하는 서술이 없다
- [ ] 어떤 문장도 단독 인용 시 "무엇을 하라"로 읽히지 않는다
