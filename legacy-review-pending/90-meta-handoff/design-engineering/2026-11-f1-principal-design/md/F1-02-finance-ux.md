# F1-02 Finance UX: 기존 화면 검수와 기기별 구조안

- 대상: `finance-harness-fe@fda50a6`(dev, PR #52 병합 뒤). `pnpm build` 후 `e2e/support/financeE2eServer.mjs`(fixture API)로 띄워 캡처했다. 실데이터 없음.
- 실제 앱 캡처는 `app-captures/finance/`, 시안은 `mockups/finance/`. 둘을 섞지 않는다.

## 결론

1. **셸은 계약대로 동작한다. 한 곳만 빼고.** 1280×1366에서 상단 내비가 남는다(F1-01 F-1). 필수 수정.
2. **화면 안은 아직 Foundation의 핵심 규칙 세 가지가 반대로 돼 있다.** 결과 화면은 "학습 노트로 남기기"가 진한 버튼이고, 저널 상세는 "AI와 복기하기"가 전폭 진한 버튼이며, 사용자가 쓴 판단 이유가 화면에서 가장 작다. 이 셋이 필수 수정의 중심이다.
3. **기기별로 달라져야 하는 것은 세 가지뿐이다.** 내비 위치(계약), 기록으로 이어가는 행동의 자리(폰·태블릿은 고정 하단, 1280 이상은 보조 열), 목록·상세와 원본·복기의 나란히 보기(계약). 나머지는 같은 한 열을 읽기 폭 안에서 유지한다.
4. **AI 대화(후속 질문)는 지금 만들 수 없다(D).** 계약이 없다. 결정에 쓸 시안 ③과 지켜야 할 규칙을 §5에 적었다.

추천: 필수 수정 M1~M7을 화면 PR에 넣고, 선택 개선은 Pilot 승인 뒤에 한다.

## 4. 기기별 구조안 [시안: 새로 만든 HTML 렌더]

| 화면 | 폰 390 | 태블릿 세로 768 | 태블릿 가로 1024×768 | 데스크톱 1440 |
|---|---|---|---|---|
| ① 검토 시작 | 하단 탭. 입력 카드 → 예시 질문 → 최근 기록 → 고지. Strong 전폭 | 상단 내비 한 줄. 읽기 폭 660 가운데 | 레일 224. 구성 같음 | 같음. 폭을 늘리지 않는다 |
| ① 검토 결과 | 뒤로 가기만. 고정 하단 Strong 1개 | 상단 내비 유지. 고정 하단은 문장 + 버튼(내용 폭) | 레일. 고정 하단 유지 | 본문 760 + 보조 열 300("기록으로 이어가기", sticky). 고정 하단 없음. **결정 전 시안(D-10)** |
| ② 저널 목록 | 하단 탭. 카드 1장 안 행 | 상단 내비. 한 열 | 목록 + 상세 | 목록 + 상세 |
| ② 저널 상세 | 뒤로 가기. 머리 → 판단 이유 → 복기 → 맥락 → 기록 정보 | 한 열 660 | 오른쪽 열. 뒤로 가기 숨김 | 오른쪽 열 최대 720 |
| ② 복기 | 원본 → 입력 → 저장(흐름 안) | 한 열 | 원본 · 복기 1:1 | 1:1 |
| ③ 후속 질문(D-8) | 작성 바 고정 하단 | 같음 | 레일 | 본문 760 + 보조 열(D-10) |

입력 방식의 차이:
- 폰: 엄지 영역에 Strong 하나. 키보드가 올라오는 화면(검토 시작, 복기)은 저장 버튼을 고정하지 않는다.
- 태블릿: 터치와 키보드가 섞인다. 고정 하단 버튼은 전폭이 아니라 내용 폭이고, 옆에 "무엇이 남는지" 한 문장을 둔다.
- 데스크톱: 목록은 ↑↓, 제출은 Ctrl/⌘+Enter(현행 유지). 버튼은 내용 폭 왼쪽 정렬.

화면 유형과 Key(`docs/02` §10.5): ①시작 = 입력(Key: 질문 입력, Strong "검토 시작"). ①결과 = 결과(Key: 질문, 함께 남길 사실 고르기. Strong "판단 기록 남기기"). ②목록 = 목록(Key 없음, Strong 0). ②상세 = 기록 상세(Key: 판단 이유, Strong 0). ②복기 = 입력(Key: 복기 본문, Strong "복기 저장").

## 5. AI 대화 UX (시안 ③, 전체가 D)

**사실**: 후속 질문의 경로, UX 계약, Review API가 없다. 정책 Matrix(`finance-product-policy.md` §8)에 "반복·후속 분석"이 Plan별 기능으로만 적혀 있다. `design-route-map.md:56`의 "추가 질문하기"는 예전 시안 라벨이다.

**권고(만든다면 지킬 규칙)**

| 관심사 | 규칙 | 시안에서 |
|---|---|---|
| 신뢰 | 답을 말풍선이 아니라 결과 화면과 같은 구조로: 확인할 자료(출처·기준일) / 해석(상태 라벨) / 모르는 것 | 턴 1 |
| 출처 | 사실마다 출처와 기준일. 출처 없는 문장은 해석으로 표시 | 턴 1 |
| 불확실성 | "아직 모르는 것"을 답마다 둔다. 답 아래에 생성 시각과 출처 수 | 턴 1 |
| 정책 경계 | 사고파는 질문은 답하지 않는다고 말하고 확인 항목으로 돌린다. 상태 라벨은 중립색 | 턴 2 |
| 사용자 통제 | 진행 중 멈추기, 다시 정리하기, 답 지우기. 끝나지 않은 답은 기록에 쓸 수 없다 | 턴 3(`?state=streaming`) |
| 저장 | 묻고 답한 내용은 자동으로 남지 않는다. 판단 기록에는 처음 검토의 맥락과 고른 사실만 | 머리 문장, 보조 열 |
| 행동 강도 | 이 화면에 온 이유는 묻기다. Strong은 "질문 보내기" 하나. 기록으로 이어가기는 Text(폰)·Subtle(보조 열) | — |

**Owner가 정할 것**: 기능 제공 여부, 경로, Guest 허용 범위, 사용량 표시(수치는 `finance-launch-experiment-values.md` 소유), 대화 보존 기간, "AI와 복기하기"와의 관계. **추천**: 지금은 만들지 않고 결과 화면의 "다시 검토하기"만 유지한다. 얻는 것은 범위와 정책 위험 축소, 버리는 것은 이어 묻는 흐름이다.
