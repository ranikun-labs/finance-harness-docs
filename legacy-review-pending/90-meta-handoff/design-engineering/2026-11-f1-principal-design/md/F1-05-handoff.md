# F1-05 구현 인계

- 구현은 각 제품의 Writer가 한다. 이 문서는 순서·범위·AC·검증 폭만 정한다. 제품 코드·Git·Jira는 바꾸지 않았다.
- 모든 PR은 한 목적, 단독 revert 가능, 데이터 변경 없음.

## 결론

1. **이미 병합된 PR 위에서 이어 간다.** Finance #53(저널 상세)·#54(복기), Carelog #38(셸)은 F1 검수 뒤에 병합됐고 방향이 같다. Carelog #39(고객 목록·상세)는 열려 있고 먼저 진행한다. F1의 화면 PR은 최신 dev를 다시 캡처해 남은 차이만 다룬다(§1).
2. **Finance는 F-1(1280 세로 내비)을 가장 먼저, 따로 고친다.** 한 줄짜리 CSS 수정이고 다른 화면 PR의 기준 폭을 바로잡는다.
3. **그다음은 화면마다 작은 PR이다.** Finance 6개, Carelog 7개. 병렬로 갈 수 있는 묶음을 §2에 표시했다.
4. **Owner 결정이 막는 PR은 2개다.** Carelog 하단 내비(PR-C6, F1-G4)와 Finance 결과 화면의 맥락·사실 고르기와 보조 열(PR-F6, F1-G8·F1-G7). 문구(F1-G6)와 24시간제 표기(F1-G9)는 해당 PR에서 그 부분만 빼고 진행할 수 있다.

## 3. PR별 AC와 검증 폭

공통 AC(모든 화면 PR에 복사):

1. Strong 0~1개(모달 제외). 있으면 세 질문 근거를 PR 본문에 한 줄.
2. 카드 테두리·그림자 0, 카드 안 카드 0(`inset` 제외).
3. 배지는 상태에만. 날짜·유형·개수는 글자.
4. 12px 미만 글자 0. 조작 영역 44 이상(WCAG 2.5.8의 24는 하한으로 따로 기록).
5. 날짜·시각은 `docs/04` §3. ISO 문자열과 시간대 이름이 화면에 나오지 않는다.
6. Light·Dark 대비: 글자 4.5:1, UI 3:1.
7. 경계값·내비 위치·2-pane 조건·경로·`data-*` 훅·i18n 키 의미 변경 0.
8. 캡처는 fixture 데이터만. Before/After를 PR 본문에.

## 4. 시안을 쓰는 법

- `mockups/<product>/<screen>/index.html`은 **참고 구현이 아니라 구성 견본**이다. 클래스 이름은 Foundation 미리보기(`ds.css`)의 것이고 FE 컴포넌트 이름과 다르다.
- 화면마다 `README.md`에 기기별 차이, Key, Strong 근거, 새 요소(C)·Owner 결정(D)을 적었다.
- `.anno`("검수 메모")는 제품 UI가 아니다. 구현하지 않는다.
- 시안의 날짜·이름·문장은 예시다. 문구는 각 제품 i18n 원문을 따른다. 시안에서 현행과 다른 문구를 쓴 곳은 화면 README의 "Owner 결정이 필요하거나 현행과 다른 곳"에 적었다. 표시가 없는 문장도 예시로만 본다.
