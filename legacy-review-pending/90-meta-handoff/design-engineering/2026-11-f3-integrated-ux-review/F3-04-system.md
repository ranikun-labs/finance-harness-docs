# F3-04 공통 디자인 자산 — Design System v1.1 후보, 공통 React UI 후보, F1 패턴 판정

- 이 문서의 항목은 모두 **제안**이다. Foundation 정본과 제품 계약을 바꾸지 않았다.
- 판단 기준: 실제 두 제품 화면에서 같은 문제가 재현됐는가. 한 제품에서만 본 것은 공통으로 올리지 않는다.

## 결론

1. **Foundation v1.0.0의 토큰과 표현 규칙은 실제 제품에서 제대로 작동했다.** 자동 측정 1,089회(Carelog 532, Finance 557)에서 넘침 0, 12px 미만 0, 글자 대비 미달은 Finance 내비 한 곳뿐이다.
2. **Foundation에 빠져 있는 것은 "값"이 아니라 "동작 계약"이다.** 두 제품에서 똑같이 재현된 결함 여섯 가지(포커스 표시, 목록·상세 포커스, 이탈 보호, 화면 이동 시 스크롤, 저장 알림, 파괴적 확인)는 모두 v1.0.0 명세에 문장이 없거나 약한 곳이다. v1.1은 여기에 집중한다.
3. 새 토큰은 필요 없다. 새 컴포넌트는 Dialog(이탈·파괴적 확인) 하나면 된다.

추천 순서: X-01 → X-03 → X-04 → X-02 → X-05. 나머지는 화면 PR에서 함께.

- **올리지 않을 것**: 일정 행, 주간 띠, 검토 결과 블록, 복기 폼. 한 제품에서만 쓴다.

## 3. 재사용할 가치가 있는 패턴 (신규 기능·유지보수 때)

실제 화면에서 잘 작동해, 새 화면을 만들 때 그대로 따를 만한 것들이다.

| 패턴 | 어디서 봤나 | 왜 좋은가 |
|---|---|---|
| 업무 처리 Key Block | Carelog 일정 상세(정리 필요) | 상태 레일 + 상태 라벨 + 시각(가장 큰 글자) + 이유 한 줄. 진한 버튼은 끝낼 일이 있을 때만 |
| 인라인 확인 패널 | Carelog 기록 완료 | 화면을 떠나지 않고 값(실제 시각)을 확인한다. 패널이 열리면 원래 버튼이 연해져 진한 버튼이 하나로 유지된다 |
| 처리 뒤 목록 복귀와 행 강조 | Carelog 기록 완료·일정 추가 | 무엇이 바뀌었는지 위치로 알려 준다 |
| 게스트 인증 복귀 | Finance 결과 → 기록 CTA | 취소하면 누른 버튼으로, 성공하면 원래 가려던 화면의 제목으로 포커스가 간다 |
| 검증 요약 + 첫 오류 포커스 | Finance 작성 화면 | 무엇이 빠졌는지 한 번에 보이고 키보드 사용자가 바로 고칠 수 있다 |
| 단계 목록 로딩 | Finance 검토 로딩 | 기다리는 동안 무엇을 하는지 말한다 |
| 결과 화면 보조 열 | Finance 1280 이상 | 긴 본문을 끝까지 내리지 않아도 다음 행동이 보인다. 낮은 높이에서도 닿는다 |
| 설정의 선택 행 | Carelog 계정 | 선택 = 연한 면 + 체크. 진한 버튼을 쓰지 않는다 |
