## 단계 1 발견 초안 — Carelog (직접 조작, fixture, `9c3a028`)

제품별 총평 초안: **CONDITIONAL**. 화면 위계와 밀도는 제품 수준이다. 일정·기록 흐름의 데이터 가시성과 되돌릴 수 없는 행동에 필수 수정이 있다.

가장 큰 문제 3개
1. 고객 상세가 예정 시각이 지난 예정 일정(정리 필요)을 보여 주지 않고 "다음 일정 없음"이라고 말한다. 기본 시각(현재)으로 일정을 추가하면 저장은 되는데 고객 상세에는 안 보이고 저장 알림도 없다.
2. "취소 처리"가 확인 없이 즉시 적용되고 되돌릴 수 없다. "수정" 바로 옆 8px 거리에 있다.
3. 일정 화면에 들어오면 "+ 일정"과 "정리 필요한 일정 N개" 안내가 화면 밖에 있다(오늘로 자동 스크롤). 맨 위로 올라가면 선택 날짜가 과거로 바뀌어 새 일정의 기본 예정 시각이 과거가 된다.

그 밖의 확인 사항
- 이탈 보호 없음: 입력 중 하단 내비를 누르면 입력이 사라진다.
- 앱 화면 표면이 Foundation과 반대(바탕 흰색, 카드 회색). 공개·인증 화면은 Foundation대로.
- 2단에서 `h1`이 2개. 선택·완료 때 목록이 가운데 ↔ 왼쪽으로 움직인다.
- "첫 고객 추가" 제목(고객이 있어도), Assistant 제목 영어, 기록 완료 패널 버튼 "확인", 일정 추가 폼 제목 중복.

## 단계 1 발견 초안 — Finance (직접 조작, fixture, `2ae32e3`)

제품별 총평 초안: **CONDITIONAL**. 검토 시작 → 결과 → 기록으로 이어가기 → Guest 로그인 복귀까지의 흐름과 셸·Dark 완성도는 제품 수준이다. 기록 작성·복기 단계에서 입력을 지키는 일과 화면 진입 위치에 필수 수정이 있다.

가장 큰 문제 3개
1. 화면을 옮겨도 본문 스크롤 위치가 초기화되지 않는다. 결과를 끝까지 읽고 "판단 기록 남기기"를 누르면 작성 화면이 맨 아래로 열린다(폰 `main` scrollTop 1157, 제목 y=-1133).
2. 작성 화면에서 첫 입력란이 약 1,150px 아래에 있다. 검토 맥락 블록(약 700px)이 폼보다 먼저 온다. UX 계약의 표시 순서(대상 → 행동 → 이유 → 감정 → 기록 시점 → 맥락)와 다르다.
3. 작성·복기 중 브라우저 뒤로 가기는 확인 없이 이동하고 입력이 사라진다(화면 안 "돌아가기" 버튼에는 확인이 있다).

그 밖의 확인 사항
- 수정·삭제·복원 컨트롤(`JournalLifecycleControls`, `JournalEditor`)은 스타일이 없는 상태다. 비운영 참조 인증 플래그 뒤에 있어 기본 빌드에는 나오지 않는다. 플래그를 열기 전 필수.
- "검토 맥락 함께 남기기"는 저장 요청에 포함되지 않는다(하위 에이전트 보고, 직접 확인 예정). 화면 문구는 남긴다고 말한다.
- 폰의 상세·작성·복기 화면에는 머리가 없어 화면 모드 버튼이 없다(알려진 항목 3).
- 기본 production 빌드(플래그 꺼짐)에서는 `/auth`에 로그인 수단이 없어 기록 작성·복기 저장으로 갈 수 없다. 제품 출시 범위(백엔드 연동)이며 UX 판정 범위 밖으로 기록한다.
- 회전(390×844 ↔ 844×390): 입력값과 포커스 보존. Guest 인증 취소 → 결과 복귀와 포커스 복귀, 로그인 → 작성 화면 복귀와 제목 포커스 확인.
- mock 한계: 저장 직후 재조회 화면은 mock 응답 형식 문제로 오류 화면이 됐다. 저장 → 재조회는 NOT_RUN으로 둔다.
